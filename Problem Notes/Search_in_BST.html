Search in a Binary Search Tree

Use the Binary Search Tree (BST) property to find a target value without visiting every node. The iterative solution follows only the subtree that can contain the target.

Key pattern: Equal means found. Smaller means go left. Greater means go right. Reaching null means not found.

1. Problem Understanding

You are given the root of a BST, A, and a target value, B. Return 1 if a node with value B exists; otherwise, return 0.

The BST property is:

  • All values in the left subtree are smaller than the current node.
  • All values in the right subtree are greater than the current node.

Example 1 — Target found

      15
     /  \
   12    20
         /
        16

For B = 16, start at 15. Since 16 > 15, move right to 20. Since 16 < 20, move left to 16, where the target is found.

Output: 1

Example 2 — Target not found

When searching for 9 in the BST rooted at 8, move right to 21, then left to null.

Output: 0

2. Brute-Force Approach

Intuition

Traverse the entire tree using DFS and compare every node's value with B. Recursion can visit both the left and right subtrees without using the BST property.

Brute-Force Java Code

public class Solution {
    public int solve(TreeNode A, int B) {
        // An empty subtree cannot contain the target.
        if (A == null) {
            return 0;
        }

        // Return success as soon as the current node matches.
        if (A.val == B) {
            return 1;
        }

        // Search both subtrees without relying on the BST ordering.
        if (solve(A.left, B) == 1 || solve(A.right, B) == 1) {
            return 1;
        }

        // The target was not found in either subtree.
        return 0;
    }
}

Complexity Analysis

  • Time: \(O(N)\), where \(N\) is the number of nodes, because every node may be visited.
  • Auxiliary space: \(O(H)\) for the recursive call stack, where \(H\) is the tree height. In the worst case, this is \(O(N)\).

Limitation: This approach ignores the BST property and may search unnecessary nodes.

3. Optimized Approach — BST Search

Intuition

At each node, use its value to choose which subtree could contain the target:

  • If B == A.val, return 1.
  • If B < A.val, move to the left child.
  • If B > A.val, move to the right child.
  • If the current node becomes null, return 0.

This iterative solution avoids recursive stack usage and is suitable for a tree containing up to \(10^5\) nodes.

Optimized Java Code

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */
public class Solution {
    public int solve(TreeNode A, int B) {
        // Begin at the root and follow one branch at a time.
        TreeNode current = A;

        while (current != null) {
            // The target has been found.
            if (current.val == B) {
                return 1;
            }

            // A smaller target can only be in the left subtree.
            else if (B < current.val) {
                current = current.left;
            }

            // A greater target can only be in the right subtree.
            else {
                current = current.right;
            }
        }

        // The search reached an empty child without finding the target.
        return 0;
    }
}

5. Complexity Analysis

Let \(N\) be the number of nodes and \(H\) be the height of the BST.

Approach Time complexity Auxiliary space
Brute-force DFS\(O(N)\)\(O(H)\)
Optimized BST search\(O(H)\)\(O(1)\)
  • Balanced BST: \(O(\log N)\) time.
  • Skewed BST: \(O(N)\) time in the worst case.
  • Optimized auxiliary space: \(O(1)\), because the iterative solution uses only a pointer and no additional data structure.

8. Interview Preparation Notes

Key pattern: Use the BST property to eliminate one subtree at every comparison.

Common Mistakes

  • Searching both subtrees unnecessarily.
  • Moving left when the target is greater than the current value.
  • Forgetting to return 0 after reaching null.
  • Assuming every BST search is \(O(\log N)\); that is guaranteed only for a balanced tree.

Likely Interviewer Follow-Ups

Q1. Why is BST search faster than normal binary-tree search?

The BST property tells us which subtree can contain the target, so we can skip the other subtree.

Q2. What is the worst-case time complexity?

\(O(N)\), when the BST is skewed.

Q3. Can this be solved recursively?

Yes. Recursion follows the same comparisons, but it uses \(O(H)\) stack space.

Q4. What if the tree is balanced?

Its height is \(O(\log N)\), so the search takes \(O(\log N)\) time.

9. Final Recommendation

Use the iterative optimized solution in an interview. It is simple, takes constant auxiliary space, and uses the BST property effectively.

Equal → found. Smaller → left. Greater → right. Null → not found.
