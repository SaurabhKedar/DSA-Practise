Binary Tree From Inorder And Postorder

Reconstruct a binary tree from its inorder and postorder traversals. Postorder identifies the root, while inorder shows how to divide the left and right subtrees.

Pattern to remember: Read postorder backward and build Root → Right → Left, using the root's inorder position to split each subtree.

1. Problem Understanding

You are given two traversals of the same binary tree:

  • Inorder: Left → Root → Right
  • Postorder: Left → Right → Root

Reconstruct the original binary tree and return its root.

Example 1

Inorder:   [2, 1, 3]
Postorder: [2, 3, 1]

The last postorder value, 1, is the root. In inorder, values before it belong to the left subtree, and values after it belong to the right subtree.

Reconstructed tree

    1
   / \
  2   3

2. Brute-Force Approach

The simplest approach searches for each root in the inorder array every time a subtree is built.

Algorithm

  1. Take the last element of the current postorder range as the root.
  2. Search for that value in the inorder range.
  3. Count the elements to the left and right of the root in inorder.
  4. Recursively construct the left and right subtrees using their corresponding postorder ranges.
  5. Return the root.

Java solution — Brute Force

public class Solution {
    public TreeNode buildTree(ArrayList<Integer> A, ArrayList<Integer> B) {
        return build(A, B, 0, A.size() - 1, 0, B.size() - 1);
    }

    private TreeNode build(ArrayList<Integer> inorder,
                           ArrayList<Integer> postorder,
                           int inStart, int inEnd,
                           int postStart, int postEnd) {

        // An empty range represents an empty subtree.
        if (inStart > inEnd || postStart > postEnd) {
            return null;
        }

        // The last value in this postorder range is the subtree root.
        int rootValue = postorder.get(postEnd);
        TreeNode root = new TreeNode(rootValue);

        // Search the current inorder range for the root's position.
        int rootIndex = inStart;
        while (inorder.get(rootIndex) != rootValue) {
            rootIndex++;
        }

        // The number of inorder values before the root is the left-subtree size.
        int leftSize = rootIndex - inStart;

        // Build the left subtree from the matching traversal ranges.
        root.left = build(inorder, postorder,
                inStart, rootIndex - 1,
                postStart, postStart + leftSize - 1);

        // Build the right subtree from the remaining values before the root.
        root.right = build(inorder, postorder,
                rootIndex + 1, inEnd,
                postStart + leftSize, postEnd - 1);

        return root;
    }
}

Brute-force dry run

For A = [2, 1, 3] and B = [2, 3, 1]:

  1. The last postorder value is 1. Create root 1.
  2. Find 1 in inorder at index 1. The left subtree contains [2], and the right subtree contains [3].
  3. The left subtree's root is 2.
  4. The right subtree's root is 3.
  5. Both nodes have no children, so return the completed tree.
  • Time: \(O(N^2)\) in the worst case, because each root is searched for linearly.
  • Auxiliary space: \(O(N)\) for recursion in the worst case, excluding the output tree.

The repeated inorder search is the bottleneck. A HashMap can eliminate that search cost.

3. Optimized Approach — HashMap + Recursion

Intuition

  • The last unused element in postorder is the root of the current subtree.
  • The root's index in inorder tells us how many nodes belong to its left and right subtrees.

Store every inorder value's index in a HashMap. Then finding a root's position takes \(O(1)\) average time. Because postorder is Left → Right → Root, process it backward by building the root, then the right subtree, then the left subtree.

Step-by-step algorithm

  1. Store every inorder value and its index in a HashMap.
  2. Initialize a pointer at the last element of postorder.
  3. Take the current postorder element as the root and move the pointer backward.
  4. Find the root's inorder index using the HashMap.
  5. Recursively construct the right subtree first, then the left subtree.
  6. Return the root.

Optimized Java solution

This solution preserves the required buildTree(ArrayList<Integer> A, ArrayList<Integer> B) signature.

import java.util.ArrayList;
import java.util.HashMap;
import java.util.Map;

public class Solution {

    private Map<Integer, Integer> inorderIndex;
    private int postIndex;

    public TreeNode buildTree(ArrayList<Integer> A,
                              ArrayList<Integer> B) {

        // Map each value to its position so subtree roots are found quickly.
        inorderIndex = new HashMap<>();
        for (int i = 0; i < A.size(); i++) {
            inorderIndex.put(A.get(i), i);
        }

        // Begin at the last postorder value, which is the root.
        postIndex = B.size() - 1;

        return build(B, 0, A.size() - 1);
    }

    private TreeNode build(ArrayList<Integer> postorder,
                           int inStart, int inEnd) {

        // No inorder values in this range means this subtree is empty.
        if (inStart > inEnd) {
            return null;
        }

        // Consume the current root from the end of postorder.
        int rootValue = postorder.get(postIndex);
        postIndex--;
        TreeNode root = new TreeNode(rootValue);

        // The map gives the split between the left and right subtrees.
        int rootIndex = inorderIndex.get(rootValue);

        // Read backward through postorder: build the right side before the left.
        root.right = build(postorder, rootIndex + 1, inEnd);
        root.left = build(postorder, inStart, rootIndex - 1);

        return root;
    }
}

Why build the right subtree first?

Consider postorder [6, 3, 2, 1]. Reading backward gives 1, then 2, then 3, then 6. After creating root 1, the next value, 2, belongs to its right subtree. That subtree must be built before consuming 6, which belongs to the left subtree. Building the left side first would consume values in the wrong order.

5. Complexity Analysis

Let \(N\) be the number of nodes.

Approach Time complexity Auxiliary space
Brute force\(O(N^2)\) worst case\(O(N)\)
HashMap + recursion\(O(N)\) average\(O(N)\)

Optimized time: Creating the HashMap takes \(O(N)\). Each node is processed once, and its inorder position is retrieved in \(O(1)\) average time. Therefore, total time is \(O(N)\) on average.

Optimized space: The HashMap stores \(N\) entries, and recursion can use up to \(O(N)\) stack space for a skewed tree. The returned tree itself uses another \(O(N)\) space, which is output space rather than auxiliary space.

Constraint warning: The problem permits up to \(10^5\) nodes. A highly skewed tree can cause Java's recursive solution to throw StackOverflowError. This is the standard interview solution, but an iterative construction is safer when worst-case stack depth must be guaranteed.

6. Edge Cases

  • Single node: Inorder [5], postorder [5]. Return a node containing 5.
  • Completely left-skewed tree: Inorder [3, 2, 1], postorder [3, 2, 1]. The tree is built correctly, though recursion depth is \(O(N)\).
  • Completely right-skewed tree: Inorder [1, 2, 3], postorder [3, 2, 1]. The result is a right-skewed tree.
  • Root at either end of inorder: The left or right subtree may be empty. The base condition inStart > inEnd handles this.
  • Duplicate values: The problem guarantees distinct values, so each value has a unique HashMap index.

8. Interview Preparation Notes

Key pattern to remember

Tree construction using traversal arrays + HashMap + recursion.

Remember these three rules:

  1. Postorder: The last unprocessed element gives the root.
  2. Inorder: The root's index separates the left and right subtrees.
  3. Reverse postorder: Build the right subtree before the left subtree.

Common mistakes

  • Building the left subtree first when reading postorder backward.
  • Forgetting to decrement postIndex after selecting the root.
  • Using the entire inorder array in every recursive call instead of restricting the range.
  • Forgetting the base case for an empty subtree.
  • Assuming recursion is always safe for a tree with \(10^5\) nodes.

Likely interview follow-up questions

Q1. Why do we need inorder traversal?

Inorder identifies which nodes belong to the left subtree and which belong to the right subtree.

Q2. Can we construct a unique binary tree using only postorder?

No. Postorder alone does not uniquely determine an arbitrary binary tree. The inorder traversal provides the additional information needed.

Q3. Why use a HashMap?

It lets us find the root's position in inorder in \(O(1)\) average time instead of searching linearly.

Q4. Can we build the tree iteratively?

Yes. An iterative stack-based solution avoids deep recursive calls and is useful when the tree can contain \(10^5\) nodes.

9. Final Recommendation

For interviews, learn the HashMap + recursion solution first because its logic is straightforward and its average time complexity is optimal.

  • Time: \(O(N)\) average.
  • Auxiliary space: \(O(N)\).
  • Core intuition: Postorder identifies the root; inorder identifies the subtree boundaries; reading postorder backward requires constructing the right subtree first.
Most important detail: Root → Right → Left when processing postorder in reverse.
