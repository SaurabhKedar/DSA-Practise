Inorder Traversal of a Binary Tree

Inorder traversal visits the left subtree, then the current node, then the right subtree. The iterative version uses an explicit stack and is recommended when a tree may be highly skewed.

Pattern to remember: Left → Root → Right

1. Problem Understanding

Given the root node A of a binary tree, return an ArrayList<Integer> containing the node values in inorder traversal.

For every node:

  1. Traverse its left subtree.
  2. Visit the current node and add its value to the result.
  3. Traverse its right subtree.

Example tree

1
 \
  2
 /
3

Node 2 is the right child of node 1, and node 3 is the left child of node 2. The inorder result is [1, 3, 2].

Tree shape matters: If node 2 were instead the left child of node 1, with node 3 as the left child of node 2, the result would be [3, 2, 1]. The same node values can produce a different traversal when their parent-child relationships change.

The tree can contain up to \(10^5\) nodes, so the target running time is \(O(N)\).

2. Recursive Approach

There is no need for an inefficient \(O(N^2)\) solution here. The simplest correct approach is recursive traversal, which visits every node exactly once.

Algorithm

  1. If the current node is null, return.
  2. Recursively traverse the left child.
  3. Add the current node's value to the result list.
  4. Recursively traverse the right child.

Java solution — Recursive

import java.util.ArrayList;

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {
    public ArrayList<Integer> inorderTraversal(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();

        // Start traversal from the root.
        inorder(A, result);

        return result;
    }

    private void inorder(TreeNode node, ArrayList<Integer> result) {
        // Base case: there is no node to process.
        if (node == null) {
            return;
        }

        // Visit the left subtree first.
        inorder(node.left, result);

        // Then visit the current node.
        result.add(node.val);

        // Finally visit the right subtree.
        inorder(node.right, result);
    }
}

Recursive dry run

Use the example tree shown above.

Step Action Result
1Start at node 1; its left child is empty, so visit 1.[1]
2Move to node 1's right child, node 2; traverse its left child, node 3.[1]
3Node 3 has no left child; visit node 3.[1, 3]
4Return to node 2 and visit it.[1, 3, 2]
5Node 2 has no right child, so traversal is complete.[1, 3, 2]

3. Optimized Approach — Iterative Inorder Traversal

Although recursion is simple, a highly skewed tree with up to \(10^5\) nodes can cause a Java StackOverflowError due to deep recursive calls. An iterative solution uses an explicit stack to manage traversal state.

Intuition

We must visit the left subtree before the current node, but we cannot visit the current node until there is no unvisited left child. Push nodes onto a stack while moving left. When there are no more left children, pop the most recent node, record its value, and then explore its right subtree.

Algorithm

  1. Create an empty result list and stack.
  2. Start with current = A.
  3. While current is not null or the stack is not empty:
    • Push current and move to its left child while possible.
    • Pop a node and add its value to the result.
    • Move to that node's right child.
  4. Return the result.

Java solution — Iterative (recommended)

import java.util.ArrayList;
import java.util.Stack;

public class Solution {
    public ArrayList<Integer> inorderTraversal(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();
        Stack<TreeNode> stack = new Stack<>();

        TreeNode current = A;

        // Continue while there are nodes to visit.
        while (current != null || !stack.isEmpty()) {

            // Keep going left, saving nodes for later.
            while (current != null) {
                stack.push(current);
                current = current.left;
            }

            // The left subtree is processed, so visit this node.
            current = stack.pop();
            result.add(current.val);

            // Continue with the node's right subtree.
            current = current.right;
        }

        return result;
    }
}

5. Complexity Analysis

Let \(N\) be the number of nodes and \(H\) the height of the tree.

Approach Time complexity Auxiliary space
Recursive\(O(N)\)\(O(H)\) call stack
Iterative with stack\(O(N)\)\(O(H)\) explicit stack
  • Time: Each node is visited and processed exactly once, so the total time is \(O(N)\).
  • Auxiliary space: The stack stores nodes along the current path, up to the tree height \(H\). In a balanced tree, \(H=O(\log N)\); in a skewed tree, \(H=O(N)\).
  • Output space: The result list contains all \(N\) node values and requires \(O(N)\) space, regardless of approach.

8. Interview Preparation Notes

Pattern to remember: DFS (Depth-First Search), specifically inorder traversal.

The three standard traversal orders

Traversal Order
PreorderRoot → Left → Right
InorderLeft → Root → Right
PostorderLeft → Right → Root

Common mistakes

  • Adding the root before traversing left — that becomes preorder.
  • Forgetting the null base case in recursion.
  • In the iterative approach, stopping when current == null without checking whether the stack still contains nodes.
  • Assuming inorder traversal always produces sorted values. This is true for a binary search tree, not for every binary tree.

Likely interviewer follow-ups

Q1. Why is inorder traversal useful for a BST?

Because it visits BST values in non-decreasing order.

Q2. Why use an explicit stack instead of recursion?

It avoids relying on Java's limited call stack and is safer for highly skewed trees.

Q3. Can inorder traversal be performed without a stack or recursion?

Yes. Morris traversal achieves \(O(N)\) time and \(O(1)\) auxiliary space by temporarily modifying and restoring tree links.

9. Final Recommendation

For interviews, learn both approaches:

  • Recursive: Best for understanding the traversal order and writing the simplest solution.
  • Iterative: Recommended for the constraint of up to \(10^5\) nodes, since it avoids recursion-depth failures.
Final recommended complexity: \(O(N)\) time, \(O(H)\) auxiliary space, plus \(O(N)\) space for the returned list.

Remember: Inorder = Left → Root → Right.
