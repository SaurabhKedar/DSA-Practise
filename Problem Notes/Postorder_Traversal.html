Postorder Traversal of a Binary Tree

Given the root of a binary tree, return its node values in postorder: traverse the left subtree, then the right subtree, and visit the current node last. The iterative two-stack solution avoids depending on Java's recursion depth.

Pattern to remember: Left → Right → Root (LRN)

1. Problem Understanding

We are given the root node A of a binary tree. Return an ArrayList<Integer> containing the values of its nodes in postorder traversal.

  1. Left subtree: visit the left child first.
  2. Right subtree: visit the right child next.
  3. Node (root): visit the current node last.

In short: Left → Right → Node (LRN).

The example explanations in the question say “Preorder,” but the shown outputs are for postorder traversal.

2. Basic Approach — Recursive Traversal

Recursion follows the definition directly, so there is no need to store and rearrange a complete traversal. For every node, traverse its left subtree, traverse its right subtree, and then add the node's value.

Algorithm

  1. If the current node is null, stop.
  2. Recursively traverse the left subtree.
  3. Recursively traverse the right subtree.
  4. Add the current node's value to the result list.

Java code — Recursive solution

import java.util.ArrayList;

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {
    public ArrayList<Integer> postorderTraversal(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();

        // Start traversal from the root.
        postorder(A, result);

        return result;
    }

    private void postorder(TreeNode node, ArrayList<Integer> result) {
        // Base case: there is no node to visit.
        if (node == null) {
            return;
        }

        // Visit the left subtree first.
        postorder(node.left, result);

        // Visit the right subtree next.
        postorder(node.right, result);

        // Add the current node only after both subtrees.
        result.add(node.val);
    }
}

Recursive dry run

For Example 2, the traversal builds the result as follows:

3Visit node 2.[6, 3, 2]

Final answer: [6, 3, 2, 1].

Complexity

  • Time: \(O(N)\), because every node is visited exactly once.
  • Auxiliary space: \(O(H)\) for the recursion call stack, where \(H\) is the tree height; in the worst case, \(O(N)\).
  • Output space: \(O(N)\) for the result list.
Recursion-depth limitation: With up to \(10^5\) nodes, a highly skewed tree can cause a Java StackOverflowError. An iterative solution avoids relying on the call stack.

3. Recommended Approach — Iterative Traversal Using Two Stacks

Use one stack to process nodes and another to collect them in reverse postorder. Popping the second stack restores the required order.

Required postorder: Left → Right → Root

Order collected first: Root → Right → Left

Popping the second stack: Left → Right → Root

Algorithm

  1. If the root is null, return an empty list.
  2. Push the root into the first stack.
  3. Pop a node from the first stack and push it into the second stack.
  4. Push its left child, if present, and then its right child into the first stack.
  5. Repeat until the first stack is empty.
  6. Pop every node from the second stack and append its value to the result.

Java code — Iterative two-stack solution

import java.util.ArrayList;
import java.util.Stack;

public class Solution {
    public ArrayList<Integer> postorderTraversal(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();

        // An empty tree has an empty postorder traversal.
        if (A == null) {
            return result;
        }

        Stack<TreeNode> first = new Stack<>();
        Stack<TreeNode> second = new Stack<>();

        // Begin processing at the root.
        first.push(A);

        while (!first.isEmpty()) {
            // Store the node so the second stack can reverse the order.
            TreeNode node = first.pop();
            second.push(node);

            // Push left first and right second; the right child is popped first.
            if (node.left != null) {
                first.push(node.left);
            }

            if (node.right != null) {
                first.push(node.right);
            }
        }

        // Popping the second stack produces Left, Right, Root order.
        while (!second.isEmpty()) {
            result.add(second.pop().val);
        }

        return result;
    }
}

The first stack is last-in, first-out. Because the right child is pushed last, it is popped first. This builds Root → Right → Left in the second stack; popping that stack reverses the order to the required Left → Right → Root.

5. Complexity Analysis and Comparison

Let \(N\) be the number of nodes and \(H\) be the height of the tree.

Approach Time Auxiliary space Main concern
Recursive\(O(N)\)\(O(H)\)Deep recursion may overflow.
Iterative, two stacks\(O(N)\)\(O(N)\)Requires two stacks.
Iterative, one stack\(O(N)\)\(O(H)\)Slightly more complex logic.

Both recursive and iterative two-stack solutions visit every node a constant number of times, so both take \(O(N)\) time. The iterative two-stack method can use \(O(N)\) auxiliary space in the worst case. The result list also requires \(O(N)\) output space, separate from auxiliary space.

8. Interview Preparation Notes

Key concept to remember

All three binary-tree depth-first traversals visit every node once. The difference is when we process the root node.

Traversal Order Memory trick
PreorderRoot → Left → RightRoot first.
InorderLeft → Root → RightRoot in the middle.
PostorderLeft → Right → RootRoot last.

Common mistakes

  1. Adding the node too early: In recursive postorder, result.add(node.val) must come after both recursive calls.
  2. Confusing preorder with postorder: Remember LRN for postorder.
  3. Pushing children in the wrong order: In the two-stack solution, push left first and right second to build the reversed traversal.
  4. Ignoring recursion depth: For a tree with up to \(10^5\) nodes, prefer an iterative solution when stack overflow is a concern.

Likely interview follow-up questions

Why is postorder traversal called Left-Right-Root?

Because we completely process both child subtrees before processing the parent node.

Where is postorder traversal useful?

Deleting a tree, evaluating expression trees, and processing child dependencies before their parent.

Can we solve this using one stack?

Yes. Track the previously visited node to determine whether the right subtree has already been processed. This saves the second stack but requires more careful logic.

What is the difference between DFS and BFS?

Depth-first search explores a branch deeply before moving to another branch. Breadth-first search explores nodes level by level.

9. Final Recommendation

For interview preparation, understand the recursive approach first because its logic is simple. Then learn the iterative two-stack approach to handle very deep trees safely.

  • Recommended implementation: iterative two-stack solution.
  • Time complexity: \(O(N)\).
  • Auxiliary space: \(O(N)\) in the worst case.
  • Output space: \(O(N)\).
Remember: Postorder means children first, parent last — Left → Right → Root (LRN).
