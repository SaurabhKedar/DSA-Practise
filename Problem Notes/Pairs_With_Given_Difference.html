Algorithm Notes

Pairs with Given Difference — Java Solution

The key concept in this problem is HashSet / HashMap and Two Pointers. Since \(N \le 10^4\), we can solve it efficiently in \(O(N \log N)\) time using sorting and two pointers, or expected \(O(N)\) time using a HashSet.

Recommended pattern: Use a frequency map for expected linear-time counting, or sort + two pointers when you want a pointer-based solution.

1. Problem Understanding

You are given:

  • An integer array A.
  • An integer B, representing the required absolute difference.

You must count the number of distinct value pairs whose absolute difference is equal to B.

Mathematically,

\[ |x-y| = B \]

Important: We count unique value pairs, not every possible combination of array indices.

Example 1

Input: A = [1, 5, 3, 4, 2], B = 3

The valid pairs are:

  • (1, 4) because \(|1-4| = 3\)
  • (2, 5) because \(|2-5| = 3\)

Output: 2

Example 2

Input: A = [8, 12, 16, 4, 0, 20], B = 4

Valid pairs: (0,4), (4,8), (8,12), (12,16), (16,20).

Output: 5

Example 3: Difference is zero

Input: A = [1, 1, 1, 2, 2], B = 0

When B = 0, both values in a pair must be equal. The distinct pairs are (1,1) and (2,2).

Output: 2

Notice that even though 1 appears three times, (1,1) is counted only once.

2. Brute Force Approach

Intuition

Check every pair of elements. If their absolute difference equals B, count the pair only if it has not already been counted.

Because duplicate values can occur, we need a way to avoid counting the same value pair repeatedly. One simple method is to store each pair in a set.

Java code

import java.util.*;

public class Solution {
    public int solve(int[] A, int B) {
        // Store each unique pair only once, in a normalized order.
        Set<String> pairs = new HashSet<>();

        // Try every pair of indices.
        for (int i = 0; i < A.length; i++) {
            for (int j = i + 1; j < A.length; j++) {
                // Check if the absolute difference matches B.
                if (Math.abs(A[i] - A[j]) == B) {
                    int x = Math.min(A[i], A[j]);
                    int y = Math.max(A[i], A[j]);

                    // Add the pair in sorted order to avoid duplicates.
                    pairs.add(x + "," + y);
                }
            }
        }

        // Number of distinct valid pairs.
        return pairs.size();
    }
}

Dry run

For A = [1, 5, 3, 4, 2], B = 3:

  • Compare 1 and 4: difference is 3; store (1,4).
  • Compare 5 and 2: difference is 3; store (2,5).
  • All other pairs have a different difference.

The set contains two unique pairs, so the answer is 2.

Complexity

  • Time: \(O(N^2)\) expected, because we examine every pair.
  • Space: \(O(N^2)\) in the worst case for storing the distinct pairs.

Limitation: We perform many unnecessary comparisons when the array is large.

3. Optimized Approach — HashMap

Intuition

Instead of comparing every pair, store each number's frequency in a HashMap.

For a number x, we need to find another number y such that:

\[ |x-y| = B \]

When B > 0, we can count the pair by checking whether x + B exists in the map. Every distinct pair is counted once because we iterate over distinct keys.

When B == 0, we count numbers that appear at least twice, because (x, x) is valid only when the same value occurs more than once.

Step-by-step algorithm

  1. Create a HashMap to store each number and its frequency.
  2. Count the frequency of every element in A.
  3. If B == 0, count the distinct numbers whose frequency is at least 2.
  4. Otherwise, for each distinct number x, check whether x + B exists in the map.
  5. Return the total count.

Java solution

import java.util.*;

public class Solution {
    public int solve(int[] A, int B) {
        // Count how many times each value appears.
        Map<Integer, Integer> frequency = new HashMap<>();

        for (int num : A) {
            frequency.put(
                num, frequency.getOrDefault(num, 0) + 1
            );
        }

        int count = 0;

        // Special case: when the difference is zero,
        // each value can pair only with itself, and only if it appears at least twice.
        if (B == 0) {
            for (int freq : frequency.values()) {
                if (freq >= 2) {
                    count++;
                }
            }

            return count;
        }

        // For B > 0, every valid pair has the form (x, x + B).
        // Check only distinct numbers so each valid pair is counted once.
        for (int num : frequency.keySet()) {
            if (frequency.containsKey(num + B)) {
                count++;
            }
        }

        return count;
    }
}

Why does this work?

  • The map stores each distinct number only once as a key.
  • For positive B, every valid pair has a smaller value x and a larger value x + B. Checking only x + B prevents counting the same pair twice.
  • For zero difference, checking frequency >= 2 ensures that the pair contains two occurrences of the same value.

5. Complexity Analysis

Approach Time complexity Auxiliary space
Brute force with a set \(O(N^2)\) expected \(O(N^2)\)
HashMap (optimized) \(O(N)\) expected \(O(U)\), at most \(O(N)\)

Why is the optimized approach \(O(N)\)?

  • Building the frequency map takes expected \(O(N)\) time.
  • Iterating through the distinct keys takes \(O(U)\) expected time.
  • Since \(U \le N\), the overall expected time is \(O(N)\).

HashMap operations have expected constant-time performance, though their worst-case performance can be worse.

8. Interview Preparation Notes

Key pattern: Hashing + distinct pair counting.

Common mistakes to avoid:

  • Counting duplicate occurrences as separate pairs.
  • Forgetting the special case B == 0.
  • Counting both (x, y) and (y, x) for positive differences.
  • Assuming the array is sorted when the problem does not guarantee it.

Likely interviewer follow-up questions:

Q1. Why use a HashMap instead of a HashSet?

A HashSet is sufficient for B > 0, but the HashMap also stores frequencies, which makes handling B == 0 straightforward.

Q2. Can this be solved using sorting and two pointers?

Yes. Sort the array, move two pointers according to the difference, and skip duplicate values. This takes \(O(N \log N)\) time.

Q3. What changes if we must count index pairs instead of distinct value pairs?

For B > 0, frequencies must be used to count all valid combinations. For B == 0, a value occurring f times contributes \(f(f-1)/2\) index pairs.

9. Final Recommendation

Use the HashMap solution for this problem. It is efficient, handles duplicate values correctly, and explicitly handles the zero-difference case.

  • Time: \(O(N)\) expected.
  • Auxiliary space: \(O(N)\) worst case.

Remember this simple rule: For positive difference, look for x + B; for zero difference, count values appearing at least twice.

Yes! The Two Pointers approach is also an optimized solution for Pairs with Given Difference.

It takes \(O(N\log N)\) time because we first sort the array, then use two pointers to find pairs in a single pass. The HashMap approach is expected \(O(N)\), so it is asymptotically faster, but Two Pointers is a very good interview solution too.

1. Intuition behind Two Pointers

Suppose:

A = [1, 5, 3, 4, 2], B = 3

First, sort the array:

A = [1, 2, 3, 4, 5]

We need to find distinct pairs satisfying:

\[ A[j] - A[i] = B \]

Maintain two pointers:

  • i: points to the smaller number.
  • j: points to the larger number.

Compare A[j] - A[i] with B:

  • If the difference is less than B, move j forward to increase the difference.
  • If the difference is greater than B, move i forward to decrease the difference.
  • If the difference equals B, count the pair and move both pointers forward, skipping duplicates.

Special case: when B == 0, we must find duplicate values and count each distinct value only once.

2. Java solution — Two Pointers

import java.util.Arrays;

public class Solution {
    public int solve(int[] A, int B) {
        int n = A.length;

        // Sort so that values are in ascending order.
        Arrays.sort(A);

        int count = 0;

        // Special case: when the required difference is zero,
        // we only count each distinct repeated value once.
        if (B == 0) {
            for (int i = 1; i < n; i++) {
                // A[i] is a valid repeated value only if it matches the
                // previous value and is not already counted as part of the
                // same duplicate block.
                if (A[i] == A[i - 1] &&
                    (i == 1 || A[i] != A[i - 2])) {
                    count++;
                }
            }
            return count;
        }

        // Use two pointers on the sorted array.
        // i points to the smaller value and j to the larger value.
        int i = 0;
        int j = 1;

        while (i < n && j < n) {
            // Pointers should not refer to the same index.
            if (i == j) {
                j++;
                continue;
            }

            int diff = A[j] - A[i];

            // Difference too small: move j forward to increase the gap.
            if (diff < B) {
                j++;
            }
            // Difference too large: move i forward to decrease the gap.
            else if (diff > B) {
                i++;
            }
            // Found a valid pair: count it and skip duplicates.
            else {
                count++;

                int leftValue = A[i];
                int rightValue = A[j];

                // Skip all occurrences of the left value to avoid recounting.
                while (i < n && A[i] == leftValue) {
                    i++;
                }

                // Skip all occurrences of the right value to avoid recounting.
                while (j < n && A[j] == rightValue) {
                    j++;
                }
            }
        }

        return count;
    }
}

4. Complexity analysis

Metric Complexity Reason
Sorting \(O(N\log N)\) Sort the array first
Two-pointer traversal \(O(N)\) Each pointer moves forward only
Total time \(O(N\log N)\) Sorting dominates
Auxiliary space \(O(\log N)\) typically Sorting implementation's stack; the pointer logic itself uses \(O(1)\) space

5. HashMap vs. Two Pointers

Feature HashMap Two Pointers
Expected time \(O(N)\) \(O(N\log N)\)
Extra space \(O(N)\) Typically \(O(\log N)\) including sorting
Requires sorting No Yes
Duplicate handling Frequency map Skip duplicate values
Best use case Faster expected lookup When sorted-array techniques are preferred

Interview recommendation: Both are valid optimized approaches. Use HashMap when you want expected linear time without sorting. Use Two Pointers when you want to demonstrate the sorted-array pattern and reduce auxiliary data structures.

Remember: Sort → Compare the difference → Move the appropriate pointer → Skip duplicates.
