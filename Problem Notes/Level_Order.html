Java Algorithm Guide

Level Order Traversal of a Binary Tree

The recommended approach is Breadth-First Search (BFS) using a queue. Process nodes level by level, from left to right, and store each level in a separate ArrayList<Integer>.

Recommended pattern: Capture the queue size, process exactly that many nodes, collect their values, and repeat for the next level.

1. Problem Understanding

Given the root of a binary tree, return a 2D list in which each inner list contains the node values at one level. Visit nodes from left to right. The root is at level 0, its children are at level 1, and so on.

Example tree

        3
       / \
      9  20
         / \
        15  7

Three levels of the example tree.

Related binary tree level-order example

The expected output is:

[
    [3],
    [9, 20],
    [15, 7]
]

This is not a standard preorder, inorder, or postorder traversal. It is a level-by-level traversal.

2. Brute Force Approach

One possible approach is to calculate the height of the tree and then traverse it once for each level, collecting only the nodes that belong to that level.

How it works

  1. Find the height of the tree.
  2. For each level from 0 to height − 1, traverse the tree.
  3. Collect only the nodes at the current level.
  4. Add each collected list to the result.

This works, but revisits many nodes for every level, making it inefficient for a large or skewed tree.

Java implementation

import java.util.*;

public class Solution {

    public ArrayList<ArrayList<Integer>> solve(TreeNode A) {
        ArrayList<ArrayList<Integer>> result = new ArrayList<>();

        // Return an empty result when the tree has no root.
        if (A == null) {
            return result;
        }

        int height = getHeight(A);

        // Collect nodes separately for every level.
        for (int level = 0; level < height; level++) {
            ArrayList<Integer> currentLevel = new ArrayList<>();
            collectLevel(A, level, currentLevel);
            result.add(currentLevel);
        }

        return result;
    }

    private int getHeight(TreeNode node) {
        if (node == null) {
            return 0;
        }

        return 1 + Math.max(
            getHeight(node.left),
            getHeight(node.right)
        );
    }

    private void collectLevel(
        TreeNode node,
        int level,
        ArrayList<Integer> currentLevel
    ) {
        if (node == null) {
            return;
        }

        if (level == 0) {
            currentLevel.add(node.val);
            return;
        }

        collectLevel(node.left, level - 1, currentLevel);
        collectLevel(node.right, level - 1, currentLevel);
    }
}

Time complexity

\(O(NH)\), where \(N\) is the number of nodes and \(H\) is the tree height. In the worst case, a skewed tree can take \(O(N^2)\) time.

Auxiliary space

\(O(H)\) for recursion, excluding the output. The output itself requires \(O(N)\) space.

This approach is useful for understanding levels, but BFS is better for this problem.

3. Optimized Approach — BFS Using a Queue

The best approach is Level Order Traversal using BFS.

Intuition

A queue follows FIFO (First In, First Out). This allows nodes to be processed in the same order in which they are discovered. Record the queue's size before processing a level; that size tells us exactly how many nodes belong to the current level.

Algorithm step by step

  1. Create an empty result list.
  2. If the root is null, return the empty result.
  3. Insert the root into a queue.
  4. While the queue is not empty:
    • Store the current queue size in size.
    • Create a new list for the current level.
    • Remove exactly size nodes from the queue.
    • Add each removed node's value to the current-level list.
    • Add its left and right children to the queue if they exist.
    • Add the completed level list to the result.
  5. Return the result.

Complete Java solution

This solution preserves your platform's required TreeNode class and solve() method signature. 

import java.util.*;

public class Solution {

    public ArrayList<ArrayList<Integer>> solve(TreeNode A) {

        // Stores the final level-by-level traversal.
        ArrayList<ArrayList<Integer>> result = new ArrayList<>();

        // Handle an empty tree.
        if (A == null) {
            return result;
        }

        // Queue processes nodes in FIFO order.
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(A);

        while (!queue.isEmpty()) {

            // Number of nodes belonging to this level.
            int size = queue.size();

            // Stores values of the current level.
            ArrayList<Integer> currentLevel = new ArrayList<>();

            // Process only the nodes present at this level.
            for (int i = 0; i < size; i++) {
                TreeNode current = queue.poll();

                // Add the current node's value.
                currentLevel.add(current.val);

                // Add children for processing at the next level.
                if (current.left != null) {
                    queue.offer(current.left);
                }

                if (current.right != null) {
                    queue.offer(current.right);
                }
            }

            // Add the completed level to the answer.
            result.add(currentLevel);
        }

        return result;
    }
}

4. Dry Run of the Optimized Solution

Consider the example tree:

        3
       / \
      9  20
         / \
        15  7

Initially, the queue contains [3].

Step Queue before processing Nodes processed Current level Result
1[3]3[3][[3]]
2[9, 20]9, 20[9, 20][[3], [9, 20]]
3[15, 7]15, 7[15, 7][[3], [9, 20], [15, 7]]

The queue becomes empty after processing the final level, so the loop stops.

Final output:

[
    [3],
    [9, 20],
    [15, 7]
]

Why is int size = queue.size() important?

Suppose the queue contains [9, 20]. Save size = 2 before processing either node.

  • Process 9 and add its children, if any.
  • Process 20 and add its children, if any.
  • Stop after exactly two nodes.

Even if new children are added to the queue during the loop, they belong to the next level and must not be included in the current level.

Interview tip: Never replace i < size with i < queue.size() in this algorithm. The queue size can change as children are added.

5. Complexity Analysis

Let \(N\) be the number of nodes and \(H\) the tree height.

Approach Time complexity Auxiliary space
Brute force, level-by-level DFS\(O(NH)\)\(O(H)\) recursion stack
Optimized BFS\(O(N)\)\(O(W)\) queue, where \(W\) is maximum tree width
  • Time: \(O(N)\) — every node is inserted into the queue and processed exactly once.
  • Auxiliary space: \(O(W)\) — the queue holds nodes from the current or next level, where \(W\) is the maximum width of the tree. In the worst case, this is \(O(N)\).
  • Output space: \(O(N)\) — every node's value is stored in the returned result.

If output space is included, the total space complexity is \(O(N)\).

8. Interview Preparation Notes

Key concept to remember

Pattern: BFS + Queue + Fixed Level Size

This is a standard tree-traversal pattern used in interviews.

Common mistakes

  1. Forgetting to capture queue.size() before processing a level.
  2. Adding null children to the queue.
  3. Returning a flat list instead of a 2D list.
  4. Accidentally processing newly added children in the current level.

Likely interviewer follow-up questions

Q1. Why use a queue instead of a stack?
A queue follows FIFO, so nodes are processed in breadth-first order. A stack naturally supports depth-first traversal instead.
Q2. Can we solve this using recursion?
Yes. DFS can collect nodes by their depth into separate lists. However, the queue-based BFS solution is more direct for level order traversal.
Q3. What is the maximum queue space complexity?
\(O(N)\) in the worst case, when a level contains a number of nodes proportional to the total number of nodes.
Q4. Does the algorithm work if the tree is unbalanced?
Yes. It processes each existing level and ignores missing children, so a balanced tree is not required.

9. Final Recommendation

Use the BFS queue approach in your interview because it is straightforward, efficient, and easy to explain.

  • Time complexity: \(O(N)\)
  • Auxiliary space: \(O(W)\), worst case \(O(N)\)
  • Pattern: Breadth-First Search (BFS)

Remember this simple rule: capture the queue size, process exactly that many nodes, collect their values, and repeat for the next level.
