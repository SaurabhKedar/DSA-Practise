Consecutive Numbers Sum — Java Solution

The key concept is arithmetic progression. Since A can be as large as 109, avoid checking every possible consecutive sequence. Test each feasible sequence length using a formula instead.

Core pattern: Arithmetic progression + divisibility + a triangular-number bound.

1. Problem Understanding

Given a positive integer A, count how many ways it can be represented as the sum of one or more consecutive positive integers.

Example: A = 15

  • [15] → 15
  • [7, 8] → 15
  • [4, 5, 6] → 15
  • [1, 2, 3, 4, 5] → 15

Therefore, the answer is 4.

Important: A sequence containing just one number is valid. For example, A = 5 has the representation [5].

2. Brute Force Approach

Intuition

Try every possible starting number and keep adding consecutive positive integers until the sum becomes equal to or greater than A.

  1. For each start, initialize sum = 0.
  2. Add start, start + 1, start + 2, and so on.
  3. If the sum equals A, increment the answer.
  4. If the sum exceeds A, stop checking that starting number.

Java code

public class Solution {
    public int solve(int A) {
        int count = 0;

        // Try every possible starting number.
        for (int start = 1; start <= A; start++) {
            long sum = 0;

            // Add consecutive positive integers until the sum reaches A.
            for (int num = start; sum < A; num++) {
                sum += num;

                if (sum == A) {
                    count++;
                    break;
                }
            }
        }

        return count;
    }
}

Complexity

  • Time: \(O(A^2)\) in the worst case, using a simple upper bound for the nested loops.
  • Auxiliary space: \(O(1)\).

This approach is too slow for A as large as 109.

3. Optimized Approach — Arithmetic Progression

Instead of generating every sequence, determine directly whether a sequence of a particular length can sum to A.

Step 1: Understand the mathematical formula

Suppose we want to represent A using k consecutive positive integers starting from s. The sequence is:

\[s,\ s+1,\ s+2,\ \ldots,\ s+k-1\]

Using the sum formula for an arithmetic progression:

\[A=\frac{k}{2}(2s+k-1)\]

Rearranging and solving for the starting number s gives:

\[2A=k(2s+k-1)\] \[s=\frac{A-\frac{k(k-1)}{2}}{k}\]

For a valid sequence, two conditions must hold:

  1. s must be a positive integer.
  2. The numerator must be divisible by k.

Therefore, test different sequence lengths k, rather than generating all the numbers in every sequence.

Step 2: Reduce the search space

The smallest possible sequence of length k is:

\[1+2+\cdots+k=\frac{k(k+1)}{2}\]

If this minimum sum exceeds A, no sequence of length k or greater can work. So stop when:

\[\frac{k(k+1)}{2}>A\]

This means only \(O(\sqrt A)\) possible lengths need to be checked.

Optimized Java code

public class Solution {
    public int solve(int A) {
        int count = 0;

        // Try each possible length of a consecutive sequence.
        for (long k = 1; k * (k + 1) / 2 <= A; k++) {

            // Subtract the offset contributed by the first k - 1 steps.
            long remaining = A - k * (k - 1) / 2;

            // A valid sequence exists when the starting number is an integer.
            if (remaining % k == 0) {
                long start = remaining / k;

                // The starting number must be positive.
                if (start >= 1) {
                    count++;
                }
            }
        }

        return count;
    }
}

Why use long? The input can reach 109, and expressions such as k * (k + 1) can overflow an int in general. Using long makes the intermediate arithmetic safe.

5. Complexity Analysis

Approach Time complexity Auxiliary space
Brute force\(O(A^2)\) upper bound\(O(1)\)
Optimized math\(O(\sqrt A)\)\(O(1)\)

For the optimized solution, the loop stops when:

\[\frac{k(k+1)}2>A\]

Solving approximately gives \(k=O(\sqrt A)\). Each iteration performs a constant number of arithmetic operations, so total time is \(O(\sqrt A)\). For A = 109, only about 44,721 lengths need to be checked, making this approach efficient.

8. Interview Preparation Notes

Pattern to remember: Arithmetic progression + divisibility + mathematical bounds.

Common mistakes

  • Forgetting that a sequence of length one is valid.
  • Checking every possible starting number instead of every possible length.
  • Using int for intermediate multiplication without considering overflow.
  • Counting a sequence when the calculated starting number is not a positive integer.
  • Using a loop bound that does not stop once the minimum possible sum exceeds A.

Likely interviewer follow-ups

Q1. Why does divisibility guarantee a valid starting number?

Because \(s=(A-k(k-1)/2)/k\). If the numerator is divisible by k, the starting number is an integer; the loop bound ensures a positive starting number for every counted length.

Q2. Can this problem be solved using a divisor formula?

Yes. The number of representations of a positive integer as a sum of consecutive positive integers equals its number of odd positive divisors. That gives another mathematical solution, but the arithmetic-progression approach is often easier to derive and explain.

Q3. Why is the loop bound based on the triangular number?

A sequence of length k cannot have a sum smaller than \(1+2+\cdots+k\). Once that minimum exceeds A, longer sequences are impossible.

9. Final Recommendation

Use the optimized arithmetic-progression solution in an interview. It is easy to justify mathematically, avoids generating unnecessary sequences, and handles the maximum constraint efficiently.

  • Time: \(O(\sqrt A)\)
  • Auxiliary space: \(O(1)\)
Remember: Instead of trying every starting number, try each possible sequence length and check whether its starting number is a positive integer.
