Find All Prime Numbers from 1 to $A$ — Java Solution

The best approach for this problem is the Sieve of Eratosthenes. Since $A$ can be as large as $10^6$, this algorithm efficiently finds all prime numbers without checking every number individually for primality.

1. Problem Understanding

We are given an integer A. We need to return all prime numbers from 1 to A in sorted order.

A prime number is a number greater than 1 that has exactly two factors: 1 and itself.

For example:

  • 2 is prime because its factors are 1, 2.
  • 5 is prime because its factors are 1, 5.
  • 6 is not prime because its factors include 1, 2, 3, 6.
  • 1 is not a prime number.

Examples

Input Output
A = 7 [2, 3, 5, 7]
A = 12 [2, 3, 5, 7, 11]
A = 2 [2]
A = 1 []

2. Brute Force Approach

Intuition

Check every number from 2 to A. For each number, check whether it is divisible by any integer from 2 up to its square root.

If no divisor is found, the number is prime and we add it to our result.

Why only check up to $\sqrt{n}$? If a number has a factor greater than its square root, its corresponding factor must be smaller than the square root.

Brute-force code (Java)

import java.util.*;

public class Solution {
    public int[] solve(int A) {
        List<Integer> primes = new ArrayList<>();

        // Check every number from 2 to A.
        for (int num = 2; num <= A; num++) {
            boolean isPrime = true;

            // Check whether num has any divisor other than 1 and itself.
            for (int divisor = 2; divisor * divisor <= num; divisor++) {
                if (num % divisor == 0) {
                    isPrime = false;
                    break;
                }
            }

            // Add the number if no divisor was found.
            if (isPrime) {
                primes.add(num);
            }
        }

        // Convert the list into the required int[] output.
        int[] result = new int[primes.size()];
        for (int i = 0; i < primes.size(); i++) {
            result[i] = primes.get(i);
        }

        return result;
    }
}

Dry run: A = 7

  • 2: no divisor to check, so it is prime.
  • 3: not divisible by 2, so it is prime.
  • 4: divisible by 2, so it is not prime.
  • 5: no divisor up to $\sqrt{5}$, so it is prime.
  • 6: divisible by 2, so it is not prime.
  • 7: no divisor up to $\sqrt{7}$, so it is prime.

Result: [2, 3, 5, 7]

Complexity

  • Time: $O(A\sqrt{A})$ in the worst case, because we test divisors for each number.
  • Auxiliary space: $O(P)$, where $P$ is the number of primes stored in the result. The returned array also requires $O(P)$ space.

This works, but we can do better.

3. Optimized Approach — Sieve of Eratosthenes

Intuition

Instead of repeatedly checking whether every number is prime, we start by assuming every number is prime. Then we mark the multiples of each prime as non-prime.

For example, when A = 12:

  1. Start with the numbers from 0 to 12.
  2. Mark 0 and 1 as non-prime.
  3. Start with 2, which is prime. Mark 4, 6, 8, 10, 12 as non-prime.
  4. Move to 3, which is prime. Mark 6, 9, 12 as non-prime.
  5. Continue with the remaining unmarked numbers.
  6. Collect all unmarked numbers from 2 to 12.

The result is [2, 3, 5, 7, 11].

Why start marking from i * i?

When processing a prime i, all its smaller multiples have already been marked by smaller prime factors.

For example, when processing 5, the multiples 10 and 15 are already handled by 2 and 3. Therefore, we start from 5 * 5 = 25.

We only need to process candidate primes up to $\sqrt{A}$. Any composite number up to A must have a prime factor no greater than that.

Step-by-step algorithm

  1. Create a boolean array isPrime of size A + 1.
  2. Mark every entry from 2 through A as true.
  3. Loop from i = 2 while i * i <= A.
  4. If isPrime[i] is true, mark its multiples starting at i * i as false.
  5. Count the remaining prime numbers.
  6. Create an integer array of the required size and fill it with the unmarked numbers in increasing order.

Optimized Java solution

public class Solution {
    public int[] solve(int A) {
        // isPrime[i] tells us whether i is prime.
        boolean[] isPrime = new boolean[A + 1];

        // Initially, assume every number >= 2 is prime.
        for (int i = 2; i <= A; i++) {
            isPrime[i] = true;
        }

        // We only need to process numbers up to sqrt(A).
        for (int i = 2; i * i <= A; i++) {

            // Skip numbers already identified as composite.
            if (isPrime[i]) {

                // Mark multiples of i as non-prime.
                // Start at i * i because smaller multiples
                // have already been handled.
                for (int j = i * i; j <= A; j += i) {
                    isPrime[j] = false;
                }
            }
        }

        // Count how many primes exist in the range.
        int count = 0;
        for (int i = 2; i <= A; i++) {
            if (isPrime[i]) {
                count++;
            }
        }

        // Create an array of exactly the required size.
        int[] result = new int[count];
        int index = 0;

        // Collect prime numbers in ascending order.
        for (int i = 2; i <= A; i++) {
            if (isPrime[i]) {
                result[index++] = i;
            }
        }

        return result;
    }
}

4. Dry Run of the Optimized Solution

Let's execute the Sieve of Eratosthenes for A = 12. Initially, all numbers from 2 to 12 are considered prime.

Step Number processed Multiples marked non-prime
1 i = 2 4, 6, 8, 10, 12
2 i = 3 9 (6 and 12 are already marked)
3 i = 4 Skipped; already marked non-prime

We stop after i = 3 because the next number, 4, exceeds $\sqrt{12}$.

The unmarked numbers form our answer:

[2, 3, 5, 7, 11]

5. Complexity Analysis

Let $A$ be the input number and $P$ be the number of primes in the range.

Approach Time complexity Auxiliary space
Brute force $O(A\sqrt A)$ $O(P)$ for the list
Sieve of Eratosthenes $O(A\log\log A)$ $O(A)$

Why is the sieve faster?

Each prime marks its multiples rather than testing every candidate independently. The total marking work is approximately:

$$A\left(\frac12+\frac13+\frac15+\cdots\right)$$

where the sum is over primes, giving the standard $O(A\log\log A)$ time complexity.

The sieve uses $O(A)$ auxiliary space for the boolean array. The returned array separately uses $O(P)$ space. Since $P \le A$, the overall space remains $O(A)$.

6. Edge Cases

Input Expected output Reason
A = 1 [] 1 is not prime
A = 2 [2] Smallest prime number
A = 3 [2, 3] Both numbers are prime
A = 4 [2, 3] 4 is composite
A = 10 [2, 3, 5, 7] Only primes are included
A = 1000000 All primes up to one million Efficiently handled by the sieve

The code handles A = 1 correctly because no number is marked prime, so the result array has length zero.

8. Interview Preparation Notes

Key pattern to remember:

Sieve of Eratosthenes — use a boolean array to eliminate multiples of prime numbers.

Common mistakes:

  • Including 1 as a prime.
  • Creating an array of size A instead of A + 1, which would make index A inaccessible.
  • Starting marking at 2 * i instead of i * i. Starting at i * i avoids unnecessary work.
  • Forgetting to collect primes in ascending order.
  • Using i * i with an integer type that could overflow in problems with much larger limits. For this problem, $A \le 10^6$, so int is safe.

Likely interviewer follow-up questions:

  1. Why does the sieve work? Every composite number has a prime factor that marks it as non-prime.
  2. Why start at i * i? Smaller multiples have already been marked by smaller factors.
  3. Can we reduce the memory usage? Yes, an odd-only sieve stores status for odd numbers only, though it adds implementation complexity.
  4. Can we find whether one number is prime without precomputing all primes? Yes. Trial division up to its square root is suitable when checking only a few numbers.

9. Final Recommendation

Use the Sieve of Eratosthenes in an interview for this problem. It is efficient, easy to explain, and handles the maximum constraint comfortably.

  • Time: $O(A\log\log A)$
  • Auxiliary space: $O(A)$
  • Output space: $O(P)$

Remember: Instead of checking every number separately, mark the multiples of each prime, then collect the numbers that remain unmarked.
