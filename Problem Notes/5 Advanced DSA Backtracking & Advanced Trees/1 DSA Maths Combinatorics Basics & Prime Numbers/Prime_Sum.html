Prime Sum — Java Solution

Find two prime numbers that add up to a given even integer, returning the lexicographically smallest pair.

1. Problem Understanding

You are given an even integer A greater than 2. Find two prime numbers whose sum equals A.

If multiple pairs are possible, return the lexicographically smallest pair: the pair with the smallest first number. Check candidate first numbers in ascending order to find it.

Example: A = 10

  • [3, 7] is valid because both numbers are prime and 3 + 7 = 10.
  • [5, 5] is also valid.
  • [3, 7] is lexicographically smaller, so return [3, 7].

2. Brute Force Approach

Intuition

Try every possible first number i, starting from 2. Calculate the second number as A - i. If both are prime, return the pair.

Algorithm

  1. Loop through i from 2 to A - 2.
  2. Check whether i is prime.
  3. Check whether A - i is prime.
  4. Return [i, A - i] as soon as both are prime.

Because i is checked in ascending order, the first valid pair is lexicographically smallest.

Java code

public class Solution {

    // Checks whether a number is prime.
    private boolean isPrime(int n) {
        if (n < 2) {
            return false;
        }

        // Only check divisors up to the square root of n.
        for (int i = 2; i * i <= n; i++) {
            if (n % i == 0) {
                return false;
            }
        }

        return true;
    }

    public int[] primesum(int A) {
        for (int i = 2; i <= A - 2; i++) {
            int j = A - i;

            if (isPrime(i) && isPrime(j)) {
                return new int[]{i, j};
            }
        }

        return new int[0]; // Unreachable under the given guarantee.
    }
}

Complexity and limitation

  • Time: \(O(A\sqrt{A})\) in the worst case, because many candidates may be tested and each primality test takes up to \(O(\sqrt{A})\).
  • Auxiliary space: \(O(1)\), using only a few variables.

With A as large as 2 × 107, repeatedly checking divisors can be slow.

3. Optimized Approach — Sieve of Eratosthenes

Intuition

Instead of checking each number for primality repeatedly, precompute which numbers are prime using the Sieve of Eratosthenes.

  • isPrime[x] = true means x is prime.
  • isPrime[x] = false means x is not prime.
  • Once the sieve is ready, checking whether a number is prime takes \(O(1)\) time.

How the sieve works

Suppose we want to find all primes up to 20:

  1. Initially, mark every number as prime.
  2. Mark 0 and 1 as non-prime.
  3. Starting from 2, mark its multiples (4, 6, 8, ...) as non-prime.
  4. Move to the next number still marked prime, 3, and mark its multiples as non-prime.
  5. Continue until the current number squared exceeds the limit.

Optimized Java code

public class Solution {

    public int[] primesum(int A) {

        // isPrime[i] tells us whether i is prime.
        boolean[] isPrime = new boolean[A + 1];

        // Initially, assume every number is prime.
        for (int i = 2; i <= A; i++) {
            isPrime[i] = true;
        }

        // Mark multiples of each prime as non-prime.
        for (int i = 2; i * i <= A; i++) {
            if (isPrime[i]) {
                // Start from i * i because smaller multiples
                // have already been handled.
                for (int j = i * i; j <= A; j += i) {
                    isPrime[j] = false;
                }
            }
        }

        // Find the first valid pair in ascending order.
        for (int i = 2; i <= A / 2; i++) {
            int j = A - i;

            if (isPrime[i] && isPrime[j]) {
                return new int[]{i, j};
            }
        }

        // A solution is guaranteed to exist.
        return new int[0];
    }
}

Why check only up to A / 2?

Suppose A = 20. If the first prime is 13, the second number must be 7. We would already have considered the pair [7, 13].

Therefore, every pair can be found by checking the first number from 2 through A / 2. This guarantees the returned pair satisfies i <= j.

Why start marking from i * i?

For example, when processing 5, we do not need to mark 10, 15, or 20 again. Those multiples have already been marked while processing 2 or 3. The first multiple that might still need marking is 5 * 5 = 25, which reduces unnecessary work.

5. Complexity Analysis

Let A be the given even number.

ApproachTime complexityAuxiliary space
Brute force\(O(A\sqrt{A})\)\(O(1)\)
Sieve optimization\(O(A\log\log A)\)\(O(A)\)

Why is the optimized time complexity \(O(A\log\log A)\)?

  • Building the sieve takes \(O(A\log\log A)\).
  • Searching for a valid pair takes at most \(O(A)\).
  • The sieve dominates the overall time complexity.

The boolean array requires \(O(A)\) auxiliary space. The returned array contains just two integers, so its output space is \(O(1)\).

8. Interview Preparation Notes

Key concepts to remember

  • Sieve of Eratosthenes: Efficiently precomputes primes up to a limit.
  • Lexicographical ordering: Check possible first numbers in ascending order.
  • Symmetry: Since the sum is fixed, checking first numbers up to A / 2 is sufficient.
  • Early return: The first valid pair is the required answer.

Common mistakes

  1. Checking every divisor repeatedly leads to the slower brute-force approach.
  2. Starting the sieve from 2 * i is correct but performs redundant work; use i * i.
  3. Searching beyond A / 2 is unnecessary because the pair can be reversed.
  4. Returning any valid pair misses the requirement to return the lexicographically smallest pair.

Likely interviewer follow-ups

Q1. Why is 1 not prime?
A prime number has exactly two positive divisors: 1 and itself. The number 1 has only one positive divisor.
Q2. Can we optimize the space complexity?
Yes, more specialized approaches can reduce memory usage, but the standard sieve is simple and practical for \(A \le 2 \times 10^7\).
Q3. Why does the first valid pair give the smallest answer?
Because we examine i in ascending order. No pair with a smaller first element can be skipped.
Q4. Why does the sieve start its outer loop only while i * i <= A?
Every composite number at most A has a prime factor no greater than \(\sqrt{A}\). Therefore, larger outer-loop values are unnecessary.

9. Final Recommendation

Use the Sieve of Eratosthenes in an interview. It avoids repeated primality checks and comfortably suits the given constraint.

  • Time: \(O(A\log\log A)\)
  • Auxiliary space: \(O(A)\)
  • Pattern: Number theory + sieve + greedy ascending search
Remember: Precompute primes once, then scan from 2 upward and return the first pair for which both i and A - i are prime.
