Longest Subarray with Zero Sum

The key pattern for this problem is Prefix Sum + HashMap. It finds the longest zero-sum subarray in \(O(N)\) average time, which is efficient enough for \(N \le 3 \times 10^5\).

Recommended pattern: Store the first index of each prefix sum. When a prefix sum repeats, the elements between its occurrences sum to zero.

1. Problem Understanding

We are given an integer array A. Return the length of the longest contiguous subarray whose sum is zero.

Example

A = [1, -2, 1, 2]

The subarray [1, -2, 1] has sum \(1 + (-2) + 1 = 0\). Its length is \(3\), so the answer is 3.

Important conditions:

  • The subarray must contain consecutive elements.
  • Negative numbers and repeated values are allowed.
  • If no zero-sum subarray exists, return 0.
  • The array can contain up to 300,000 elements, so a quadratic-time solution may be too slow.

2. Brute Force Approach

Intuition

Try every possible starting index and extend the subarray to every possible ending index. Keep a running sum and update the longest length whenever the sum becomes zero.

Java code

public class Solution {
    public int solve(int[] A) {
        int n = A.length;
        int maxLength = 0;

        // Try every possible starting index.
        for (int i = 0; i < n; i++) {
            long sum = 0;

            // Extend the subarray from index i.
            for (int j = i; j < n; j++) {
                sum += A[j];

                // Record the longest subarray when its sum is zero.
                if (sum == 0) {
                    maxLength = Math.max(maxLength, j - i + 1);
                }
            }
        }

        return maxLength;
    }
}

The longest zero-sum subarray found is [1, -2, 1], with length \(3\).

Time complexity

\(O(N^2)\), because we examine all possible subarrays.

Auxiliary space

\(O(1)\), because we use only a few variables.

Limitation: For 300,000 elements, checking all subarrays is too slow.

3. Optimized Approach — Prefix Sum + HashMap

Intuition

If the same prefix sum occurs at two different indices, the elements between those indices sum to zero. A prefix sum is the sum of all elements from index 0 to the current index.

Consider A = [1, -2, 1, 2]:

IndexElementPrefix sum
011
1-2-1
210
322

At index 2, the prefix sum is zero. This means the subarray from index 0 to 2 has sum zero and length \(3\).

Repeated prefix-sum example

For A = [1, 2, -2, 3, -3], the prefix sums are 1, 3, 1, 4, 1. The prefix sum 1 occurs at indices 0, 2, and 4.

  • Between indices 0 and 2, the sum is zero: [2, -2].
  • Between indices 0 and 4, the sum is zero: [2, -2, 3, -3].

The second subarray has length \(4\), so store the first occurrence of each prefix sum to maximize the length.

Why does a repeated prefix sum work?

Let \(P[i]\) represent the prefix sum up to index \(i\). If \(P[i] = P[j]\), where \(i < j\), then:

\[P[j] - P[i] = 0\]

Therefore, the sum of the subarray from index \(i + 1\) to \(j\) is zero. If we imagine a prefix sum of \(0\) occurring before the array starts, at index \(-1\), the same formula also handles zero-sum subarrays beginning at index \(0\).

Optimized Java solution

This is the recommended interview-ready solution for the given method signature.

import java.util.HashMap;
import java.util.Map;

public class Solution {
    public int solve(int[] A) {
        // Store the first index at which each prefix sum appears.
        Map<Long, Integer> firstIndex = new HashMap<>();

        long prefixSum = 0;
        int maxLength = 0;

        for (int i = 0; i < A.length; i++) {
            prefixSum += A[i];

            // A zero prefix sum means the subarray from index 0 to i sums to zero.
            if (prefixSum == 0) {
                maxLength = i + 1;
            }
            // A repeated prefix sum means the intervening subarray sums to zero.
            else if (firstIndex.containsKey(prefixSum)) {
                int previousIndex = firstIndex.get(prefixSum);
                int length = i - previousIndex;
                maxLength = Math.max(maxLength, length);
            }
            // Keep the earliest index so a future match gives the longest length.
            else {
                firstIndex.put(prefixSum, i);
            }
        }

        return maxLength;
    }
}

Step-by-step algorithm

  1. Initialize prefixSum = 0 and maxLength = 0.
  2. Create a HashMap to store each prefix sum's first index.
  3. Traverse the array once and add each element to prefixSum.
  4. If prefixSum == 0, update the length to i + 1.
  5. If the prefix sum already exists in the map, calculate i - previousIndex and update the maximum length.
  6. Otherwise, store the current prefix sum and index.
  7. Return maxLength.

Why store only the first occurrence?

Suppose a prefix sum first appears at index 2 and appears again at index 8. The zero-sum subarray length is \(8 - 2 = 6\). If we overwrite the first index with a later occurrence, we could miss a longer subarray.

Why use long for the prefix sum?

Each element can be as large as \(10^9\) in absolute value, and the array can contain 300,000 elements. The sum can exceed Java's int range, so long prevents integer overflow.

5. Complexity Analysis

ApproachTime complexityAuxiliary space
Brute force\(O(N^2)\)\(O(1)\)
Prefix sum + HashMap\(O(N)\) average\(O(N)\)

Optimized time complexity

We traverse the array once. HashMap lookup and insertion take \(O(1)\) average time, so the total expected time is \(O(N)\).

Optimized space complexity

In the worst case, every prefix sum is different, so the map can store up to \(N\) entries. Therefore, auxiliary space is \(O(N)\).

8. Interview Preparation Notes

Key concept to remember

The same prefix sum at two indices means the subarray between them has sum zero. This is a classic Prefix Sum + HashMap problem.

Common mistakes

  • Overwriting the first index: Always preserve the earliest occurrence to maximize the subarray length.
  • Using int for prefix sums: The sum can exceed the int range, so use long.
  • Forgetting subarrays starting at index 0: Handle prefixSum == 0 with length i + 1.
  • Returning the number of subarrays: The question asks for the maximum length, not the count.

Likely interviewer follow-up questions

1. How would you count all zero-sum subarrays instead of finding the longest?

Use a HashMap to store prefix-sum frequencies. Whenever the current prefix sum has appeared \(f\) times, add \(f\) to the answer.

2. Why can't we use a sliding window?

Because the array contains negative numbers. Adding or removing an element does not change the sum in a predictable direction, so the usual sliding-window strategy is not reliable.

3. What if the array contains only positive numbers?

No non-empty subarray can sum to zero, so the answer is 0.

4. Why is the first occurrence important?

For a repeated prefix sum at index i, the length is i - firstIndex. A smaller first index gives a longer subarray.

9. Final Recommendation

Use Prefix Sum + HashMap in an interview. It reduces the brute-force solution from quadratic time to linear expected time and handles negative numbers correctly.

  • Time: \(O(N)\) average
  • Auxiliary space: \(O(N)\)
  • Pattern: Prefix Sum + HashMap
  • Core intuition: When a running sum repeats, the elements between its occurrences sum to zero.

Remember this formula:

\[\boxed{\text{Length} = \text{Current Index} - \text{First Index of Same Prefix Sum}}\]
