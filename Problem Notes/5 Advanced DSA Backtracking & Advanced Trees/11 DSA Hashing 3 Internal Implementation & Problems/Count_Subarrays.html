Algorithm Notes

Count Subarrays – Sliding Window, HashMap & Two Pointers

Recommended: \(O(N)\) expected time using a HashMap.

There are three useful approaches for this problem:

  1. Brute Force + HashSet – Generate subarrays and check duplicates.
  2. Optimized Sliding Window + HashMap – Track the last occurrence of each element dynamically.
  3. Optimized Sliding Window + Array – Use an array instead of a HashMap because the constraints limit A[i] to 10^6.

The HashMap approach is particularly important for interviews because it works even when array values are negative, very large, or not within a small fixed range.

This note covers all three approaches.

1. Problem Understanding

We are given an integer array A of size N.

We need to count the number of contiguous subarrays that contain only unique elements. A subarray is valid if no element appears more than once inside it.

Return the answer modulo:

\[ \mathrm{MOD} = 10^9 + 7 \]

Example 1

Input:

A = [1, 1, 3]

All possible subarrays:

SubarrayValid?
[1]Yes
[1,1]No
[1,1,3]No
[1]Yes
[1,3]Yes
[3]Yes

Valid subarrays: [1], [1], [1,3], [3]

Answer = 4

Example 2

Input:

A = [2, 1, 2]

Valid subarrays: [2], [2,1], [1], [1,2], [2]

Answer = 5

2. Brute Force Approach – HashSet

Intuition

Generate every possible subarray and check whether it contains duplicate elements. Use a HashSet to remember which elements are already present in the current subarray.

Algorithm

  1. Start a subarray from every index i.
  2. Create an empty HashSet.
  3. Extend the subarray using another pointer j.
  4. If A[j] already exists in the set, stop extending.
  5. Otherwise, add it to the set and increment the answer.

Java Code

import java.util.*;

public class Solution {
    public int solve(int[] A) {

        int n = A.length;
        long count = 0;
        int MOD = 1000000007;

        for (int i = 0; i < n; i++) {

            HashSet<Integer> set = new HashSet<>();

            for (int j = i; j < n; j++) {

                // Stop if the current element is already present
                if (set.contains(A[j])) {
                    break;
                }

                // Add the new unique element
                set.add(A[j]);

                // Current subarray is valid
                count++;
            }
        }

        return (int)(count % MOD);
    }
}

Dry Run

Input: A = [1, 2, 1]

  • Start at index 0: [1] → Valid, count = 1; [1,2] → Valid, count = 2; [1,2,1] → Duplicate, stop.
  • Start at index 1: [2] → Valid, count = 3; [2,1] → Valid, count = 4.
  • Start at index 2: [1] → Valid, count = 5.

Answer = 5

Complexity

  • Time: O(N²) worst case.
  • Space: O(N) for the HashSet.

The approach is too slow for \(N = 100000\).

3. Optimized Approach 1 – Sliding Window + HashMap

Important interview approach

Step 1: Understand the Sliding Window

Instead of generating every subarray, maintain a window containing unique elements.

We use two pointers:

  • left: Starting index of the current window.
  • right: Ending index of the current window.

We also maintain a HashMap:

HashMap<Integer, Integer> lastSeen;

It stores the array element as the key and its most recent index as the value. For example:

A = [1, 2, 1]

After processing the first two elements:

lastSeen = {
    1 = 0,
    2 = 1
}

When we encounter 1 again at index 2, its previous occurrence was at index 0. Therefore, we move left to index 1.

Step 2: Understand the Most Important Condition

if (lastSeen.containsKey(current)
        && lastSeen.get(current) >= left) {

    left = lastSeen.get(current) + 1;
}

Let's understand why we need both conditions.

Condition 1: lastSeen.containsKey(current)

Checks whether this element has appeared before.

Condition 2: lastSeen.get(current) >= left

Checks whether its previous occurrence is inside the current window.

Why is the second condition important? Consider:

A = [1, 2, 1, 3, 2]

When we process the last 2:

  • Previous occurrence of 2 = index 1.
  • Current left = 2.

The previous occurrence is outside our current window. We must not move left backwards. Therefore, we only move it when the previous occurrence is greater than or equal to the current left.

Step 3: Count Valid Subarrays

This is the most important formula:

\[ \boxed{\mathrm{count} \mathrel{+}= \mathrm{right} - \mathrm{left} + 1} \]

Why? Suppose the current valid window is:

[2, 1, 3]

All valid subarrays ending at the current index are:

  1. [3]
  2. [1,3]
  3. [2,1,3]

Total = 3. And \(right - left + 1 = 3\). Therefore, we can count all these subarrays in \(O(1)\) time.

Complete Java Code – HashMap

import java.util.*;

public class Solution {
    public int solve(int[] A) {

        int n = A.length;
        int MOD = 1000000007;

        // Stores the most recent index of each element
        HashMap<Integer, Integer> lastSeen = new HashMap<>();

        int left = 0;
        long count = 0;

        for (int right = 0; right < n; right++) {

            int current = A[right];

            // Check whether the current element has appeared
            if (lastSeen.containsKey(current)) {

                int previousIndex = lastSeen.get(current);

                // Move left only if duplicate is inside
                // the current sliding window
                if (previousIndex >= left) {
                    left = previousIndex + 1;
                }
            }

            // Update the latest occurrence of current element
            lastSeen.put(current, right);

            // Count all valid subarrays ending at right
            count += (right - left + 1);

            // Apply modulo
            count %= MOD;
        }

        return (int) count;
    }
}

Let's understand each iteration

Iteration 1: right = 0

Current element = 1. It is not present in the HashMap. Add 1 → 0. The valid window is [1]. Count = 0 + (0 - 0 + 1) = 1.

Iteration 2: right = 1

Current element = 2. It is not present in the HashMap. Add 2 → 1. The valid window is [1,2]. New valid subarrays: [2], [1,2]. Count = 1 + 2 = 3.

Iteration 3: right = 2

Previous occurrence of 1 = index 0. Since 0 >= left, move left = 0 + 1 = 1. Update the HashMap with 1 → 2. The valid window is [2,1]. New valid subarrays: [1], [2,1]. Count = 3 + 2 = 5.

Iteration 4: right = 3

Current element = 3. It is not present in the HashMap. Add 3 → 3. The valid window is [2,1,3]. New valid subarrays: [3], [1,3], [2,1,3]. Count = 5 + 3 = 8.

Final Answer: 8

Complexity Analysis – HashMap

Time Complexity: \(O(N)\) expected. We traverse the array once, and HashMap containsKey(), get() and put() take \(O(1)\) expected time. Each element is processed once.

\[O(N)\]

Space Complexity: \(O(N)\). In the worst case, all elements are unique, so the HashMap stores N entries.

\[O(N)\]

4. Optimized Approach 2 – Sliding Window + Last Seen Array

Now that you understand the HashMap approach, here's another optimization. Remember the constraints:

1 <= A[i] <= 1000000

Since the maximum element value is known, we don't actually need a HashMap. We can directly use an integer array to store the last-seen index.

Intuition

Instead of:

lastSeen.put(current, right);

We can write:

lastSeen[current] = right;

And instead of checking:

lastSeen.containsKey(current)

We can check:

lastSeen[current] != -1

We initialize every position to -1, meaning the element has never appeared.

Complete Java Code

import java.util.Arrays;

public class Solution {
    public int solve(int[] A) {

        int n = A.length;
        int MOD = 1000000007;

        // Maximum possible element value is 10^6
        int[] lastSeen = new int[1000001];

        // -1 means the element has not appeared
        Arrays.fill(lastSeen, -1);

        int left = 0;
        long count = 0;

        for (int right = 0; right < n; right++) {

            int current = A[right];

            // Check whether the element appeared
            // inside the current window
            if (lastSeen[current] >= left) {

                // Move left beyond its previous occurrence
                left = lastSeen[current] + 1;
            }

            // Update the latest occurrence
            lastSeen[current] = right;

            // Count all valid subarrays ending at right
            count += (right - left + 1);

            count %= MOD;
        }

        return (int) count;
    }
}

Complexity Analysis – Last Seen Array

  • Time: \(O(N + 10^6)\), including initialization of the array.
  • Auxiliary Space: \(O(10^6)\), for the last-seen array.

The array avoids HashMap hashing overhead and provides direct indexing.

Which one should you use?

  • Use HashMap when element values can be arbitrary, negative, or very large.
  • Use Last Seen Array when the constraints provide a small, fixed range of positive integers.
  • Use Brute Force to understand the problem, not for the final submission.

Important overflow consideration

For \(N = 100000\), the maximum possible number of subarrays is:

\[ \frac{N(N+1)}{2}=5,000,050,000 \]

This exceeds Java's int capacity. Therefore, always use:

long count = 0;

Apply modulo during accumulation.

8. Interview Preparation Notes

Key concepts to remember

  1. Sliding Window – Maintain a valid window.
  2. Two Pointers – Use left and right.
  3. HashMap – Remember the last occurrence of each element.
  4. Counting Formula – \(right - left + 1\).

Common interview mistakes

  • Moving left backwards.
  • Forgetting to update the last occurrence.
  • Using int instead of long.
  • Counting only the current window instead of all valid subarrays ending at right.
  • Forgetting modulo.

Likely interviewer follow-up questions

Q1. Can we solve this without a HashMap?

Yes. Use a last-seen array if the element range is bounded.

Q2. Why do we use the last occurrence index instead of simply storing whether an element exists?

Because the index allows us to jump left directly to the next valid position.

Q3. Why is the HashMap solution \(O(N)\)?

We traverse the array once and perform expected \(O(1)\) HashMap operations per element.

Q4. Can this technique solve the longest substring without repeating characters?

Yes. The window maintenance is almost identical. Instead of counting valid subarrays, we maintain the maximum window length.

9. Final Recommendation

Best general-purpose interview solution: HashMap. For this problem, I recommend learning and understanding the HashMap implementation first.

The most important three lines are:

if (lastSeen.containsKey(current)
        && lastSeen.get(current) >= left) {

    left = lastSeen.get(current) + 1;
}

lastSeen.put(current, right);

count += right - left + 1;
Whenever you encounter a duplicate inside your current sliding window, move the left pointer beyond its previous occurrence. Then count all valid subarrays ending at the current right pointer using right - left + 1.

Final complexity:

  • HashMap: \(O(N)\) expected time, \(O(N)\) space.
  • Last Seen Array: \(O(N + 10^6)\) time, \(O(10^6)\) space.

This problem is an excellent example of the Variable Size Sliding Window + Last Occurrence Index pattern.
