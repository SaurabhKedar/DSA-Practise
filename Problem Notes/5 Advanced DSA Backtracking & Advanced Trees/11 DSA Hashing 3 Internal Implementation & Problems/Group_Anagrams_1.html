Group Anagrams — Java Solution

Use a HashMap to group strings that contain the same characters. First consider a brute-force approach, then use sorted strings as canonical keys for an efficient solution.

Recommended pattern: Sort each word to create its group key, then store the original word under that key.

1. Problem Understanding

Two strings are anagrams if they contain exactly the same characters with the same frequencies, regardless of their order.

Examples

  • "eat", "tea", "ate" are anagrams.
  • "tan", "nat" are anagrams.
  • "bat" has no matching anagram in the input.

Given an array of strings A, return a 2D ArrayList where each inner list contains all anagrams belonging to the same group.

Important conditions

  • Only lowercase English letters are allowed.
  • The input can contain up to \(10^4\) strings.
  • Each string can have up to 100 characters.
  • The order of groups and the order of strings within each group do not matter.

2. Brute-Force Approach

Intuition

For every string, compare it with the other strings to determine which ones are anagrams. To check a pair, sort both strings' characters and compare the sorted results.

"eat" sorts to "aet", and "tea" also sorts to "aet". Their sorted forms match, so they are anagrams.

Algorithm

  1. Take the first string that has not been grouped.
  2. Sort its characters.
  3. Compare it with every other ungrouped string.
  4. If their sorted forms match, add that string to the current group.
  5. Repeat until all strings have been grouped.

Java code

import java.util.*;

public class Solution {
    public ArrayList<ArrayList<String>> groupAnagrams(
            ArrayList<String> A) {

        ArrayList<ArrayList<String>> result = new ArrayList<>();
        boolean[] visited = new boolean[A.size()];

        for (int i = 0; i < A.size(); i++) {
            if (visited[i]) {
                continue;
            }

            ArrayList<String> group = new ArrayList<>();
            char[] first = A.get(i).toCharArray();
            Arrays.sort(first);
            String key = new String(first);

            group.add(A.get(i));
            visited[i] = true;

            for (int j = i + 1; j < A.size(); j++) {
                if (visited[j]) {
                    continue;
                }

                char[] current = A.get(j).toCharArray();
                Arrays.sort(current);

                // Add this string when its sorted form matches the group's key.
                if (key.equals(new String(current))) {
                    group.add(A.get(j));
                    visited[j] = true;
                }
            }

            result.add(group);
        }

        return result;
    }
}

Complexity analysis

Let \(n\) be the number of strings and \(k\) the maximum string length.

  • Time: \(O(n^2 k\log k)\) in the worst case, because we compare pairs and sort strings.
  • Auxiliary space: \(O(n+k)\) for the visited array and temporary character arrays, excluding the returned result.

This approach repeats comparisons and sorting. With \(10^4\) strings, it can become inefficient.

3. Optimized Approach — HashMap + Sorted String

This is the recommended interview solution.

Intuition

Instead of comparing every string with every other string, create a unique key for each group of anagrams. The key is the string obtained after sorting its characters.

"eat" → "aet"

"tea" → "aet"

"ate" → "aet"

All three strings produce the same key, so they belong in the same group. Store each key in a HashMap, with its value being the list of original strings in that group.

Step-by-step algorithm

  1. Create a HashMap<String, ArrayList<String>>.
  2. Iterate through every string in A.
  3. Convert the string into a character array and sort it.
  4. Convert the sorted characters back into a string to create the key.
  5. If the key does not exist in the map, create an empty list for it.
  6. Add the original string to the list associated with that key.
  7. Return all the map's values as the result.

Optimized Java code

import java.util.*;

public class Solution {
    public ArrayList<ArrayList<String>> groupAnagrams(
            ArrayList<String> A) {

        // Map each sorted-character key to its original strings.
        HashMap<String, ArrayList<String>> map = new HashMap<>();

        for (String str : A) {
            // Convert the string into a character array for sorting.
            char[] chars = str.toCharArray();

            // Sorting makes anagrams share the same group key.
            Arrays.sort(chars);
            String key = new String(chars);

            // Create a group the first time this key is encountered.
            if (!map.containsKey(key)) {
                map.put(key, new ArrayList<String>());
            }

            // Keep the original string in the result group.
            map.get(key).add(str);
        }

        // Collect the map's groups into the required 2D ArrayList.
        return new ArrayList<ArrayList<String>>(map.values());
    }
}

Why does this work?

Sorting puts the characters of every anagram into the same order. Therefore, anagrams always generate the same key. Strings that are not anagrams have different sorted keys, so they end up in different groups. The original string is stored; sorting is only used to identify the group.

5. Complexity Analysis

Let \(n\) be the number of strings and \(k\) the maximum string length.

Approach Time complexity Auxiliary space
Brute force \(O(n^2 k\log k)\) \(O(n+k)\), excluding output
HashMap + sorting \(O(nk\log k)\) \(O(nk)\), including map keys and group storage

Why is the optimized time complexity \(O(nk\log k)\)?

For each of the \(n\) strings:

  • Converting to a character array takes \(O(k)\).
  • Sorting its characters takes \(O(k\log k)\).
  • Creating the key takes \(O(k)\), plus expected \(O(1)\) map operations aside from hashing the key.

Therefore, the overall expected time complexity is:

\[\boxed{O(nk\log k)}\]

The map stores the keys and grouped strings, requiring \(O(nk)\) space in the worst case. The returned result also contains all \(n\) strings, requiring \(O(nk)\) output space.

The constraints guarantee at least one string, and each string contains only lowercase English letters. The solution handles all these valid cases.

8. Interview Preparation Notes

Key concepts to remember

  • Pattern: hashing + canonical representation.
  • Canonical representation: a standardized form that makes equivalent items share the same key. Here, it is the sorted string.
  • HashMap: efficiently associates each key with its group.
  • Alternative optimization: because the input contains only lowercase English letters, a 26-element frequency array can replace sorting. This can reduce the expected time to \(O(nk)\), though the key must be encoded unambiguously.

Common mistakes

  1. Adding the sorted key instead of the original string. The output must contain the original words.
  2. Comparing only string lengths. Equal lengths do not mean two strings are anagrams.
  3. Overwriting existing groups. Use the existing list when a key is already present.
  4. Assuming output order matters. The problem explicitly allows any order.

Likely follow-up questions

Q1. Can we solve this without sorting each string?

Yes. Count the occurrences of all 26 lowercase letters and use that frequency representation as the key.

Q2. Why use a HashMap?

It lets us find and update the appropriate anagram group efficiently without repeatedly comparing strings.

Q3. What if uppercase letters or Unicode characters are allowed?

The key-generation method must support the expanded character set. Sorting characters remains a straightforward general solution, with appropriate handling of the character encoding.

Q4. What happens if two identical strings appear?

Both are added to the same group. The algorithm preserves duplicates.

9. Final Recommendation

For an interview, implement HashMap + sorted string first. It is simple, reliable, and easy to explain.

  • Time: \(O(nk\log k)\) expected.
  • Auxiliary space: \(O(nk)\) for the map and stored groups, excluding the returned result.
Core intuition: Sort each word to get its key, use that key to find its group, and store the original word in that group.
