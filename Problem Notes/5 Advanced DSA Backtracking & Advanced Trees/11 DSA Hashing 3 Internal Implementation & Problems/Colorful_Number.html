Colorful Number

Interview-ready solution in Java

This problem combines digit manipulation, a HashSet, and nested loops. Generate every consecutive sequence of digits, calculate its product, and check whether that product has appeared before. If two sequences have the same product, the number is not colorful.

1. Problem Understanding

A number is called colorful if the products of all possible consecutive sequences of its digits are unique. Only consecutive sequences count, not arbitrary combinations of digits.

2. Brute Force Approach

Intuition

Convert the number to a string and generate every consecutive substring. For each substring, calculate the product of its digits, compare it with previously calculated products, and return 0 if it is already present. Otherwise, store it. If all products are unique, return 1.

Java Code — Brute Force

import java.util.*;

public class Solution {
    public int colorful(int A) {

        // Convert the number into a string.
        String num = String.valueOf(A);
        int n = num.length();

        // Keep the products calculated so far.
        ArrayList<Long> products = new ArrayList<>();

        // Generate every possible consecutive substring.
        for (int i = 0; i < n; i++) {
            for (int j = i; j < n; j++) {
                long product = 1;

                // Calculate the product of digits from i through j.
                for (int k = i; k <= j; k++) {
                    product *= (num.charAt(k) - '0');
                }

                // A repeated product means the number is not colorful.
                if (products.contains(product)) {
                    return 0;
                }

                // Remember this product for subsequent checks.
                products.add(product);
            }
        }

        return 1;
    }
}

Complexity Analysis

  • Time: \(O(n^4)\). There are \(O(n^2)\) substrings; recalculating each product takes \(O(n)\) across the nested loops, and repeated ArrayList.contains() lookups can add \(O(n^4)\) total work in the worst case.
  • Space: \(O(n^2)\) for storing all possible substring products.

This works, but the duplicate check can be improved with a HashSet.

3. Optimized Approach — HashSet

Recommended approach. Instead of storing substrings, remember only their products.

Intuition

  1. Convert the number into a string and create an empty HashSet for products.
  2. Use an outer loop to choose a starting digit and an inner loop to extend the sequence.
  3. Maintain a running product instead of recalculating it from the start.
  4. If the product already exists in the set, return 0; otherwise, add it.
  5. Return 1 after processing all sequences without a duplicate.

Java Code — Optimized

import java.util.HashSet;

public class Solution {
    public int colorful(int A) {

        // Convert the number into a string so digit order is preserved.
        String num = String.valueOf(A);
        int n = num.length();

        // Store products of consecutive digit sequences.
        HashSet<Long> products = new HashSet<>();

        // Choose each possible starting position.
        for (int i = 0; i < n; i++) {
            long product = 1;

            // Extend the sequence one digit at a time.
            for (int j = i; j < n; j++) {
                // Convert the current character digit into an integer.
                int digit = num.charAt(j) - '0';

                // Reuse the prior product and include the new digit.
                product *= digit;

                // A repeated product means the number is not colorful.
                if (products.contains(product)) {
                    return 0;
                }

                // Record this product for future duplicate checks.
                products.add(product);
            }
        }

        // Every consecutive sequence has a unique product.
        return 1;
    }
}

Understanding the Important Logic

Why do we use two loops?

for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {

i is the starting index and j is the ending index. Together they generate each consecutive sequence. For 236, i = 0 gives 2, 23, 236; i = 1 gives 3, 36; and i = 2 gives 6.

Why initialize the product inside the outer loop?

long product = 1;

Every new starting position begins a new sequence, so the product must reset to 1.

Why update the product instead of using another loop?

product *= digit;

For the sequences starting at 2, the running products are 2 for 2, 6 for 23, and 36 for 236. Each new product reuses the previous one.

Why use a HashSet?

if (products.contains(product)) {
    return 0;
}

A HashSet detects a duplicate product with approximately \(O(1)\) average-time lookup. If the product is already present, the number is not colorful.

5. Complexity Analysis

Let n be the number of digits.

ApproachTime ComplexityAuxiliary Space
Brute force\(O(n^4)\)\(O(n^2)\)
HashSet optimized\(O(n^2)\) average\(O(n^2)\)

Why is optimized time \(O(n^2)\)?

There are two nested loops, each with at most n iterations. HashSet lookup and insertion take \(O(1)\) average time, so the overall time is:

\[O(n \times n) = O(n^2)\]

Why is space \(O(n^2)\)?

The total number of consecutive sequences is:

\[\frac{n(n+1)}{2}\]

In the worst case, the set stores one product for every sequence.

Integer detail: The product uses long because multiplying up to 10 digits can exceed Java's int range.

8. Interview Preparation Notes

Key concepts to remember

  1. Substring generation: Generate all consecutive sequences using two nested loops.
  2. Running product: Maintain the product while extending each sequence.
  3. HashSet: Detect duplicate products efficiently.

Common mistakes

  • Generating non-consecutive subsequences instead of consecutive substrings.
  • Forgetting to reset product = 1 for every new starting position.
  • Recalculating the entire product unnecessarily.
  • Using int instead of long for products.
  • Checking duplicate substrings instead of duplicate products.

Likely interviewer follow-up questions

Q1. Why use a HashSet instead of an ArrayList?

A HashSet provides \(O(1)\) average lookup, whereas ArrayList lookup takes \(O(n)\).

Q2. Can we solve this without converting the number into a String?

Yes. Digits can be extracted using % 10 and / 10, but generating consecutive sequences is less convenient because digit order must be preserved.

Q3. Can we optimize beyond \(O(n^2)\)?

There are exactly \(\frac{n(n+1)}{2}\) consecutive sequences. In the general case, checking every sequence requires at least \(O(n^2)\) work, so this approach is asymptotically optimal.

Q4. What happens if a number contains zero?

Every sequence containing zero has product zero. If two such sequences exist, the HashSet detects the duplicate and returns zero.
