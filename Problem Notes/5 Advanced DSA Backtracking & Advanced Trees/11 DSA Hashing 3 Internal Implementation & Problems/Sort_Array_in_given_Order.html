Sort Array in Given Order

Recommended pattern: HashMap / Frequency Counting + Custom Ordering + Sorting. This relative-sorting problem rearranges one array according to the priority order defined by another.

Elements in B are unique, while A may contain duplicates. Values from B come first in its order; all other values follow in ascending order.

1. Problem understanding

We are given two integer arrays:

  • A: the array to rearrange.
  • B: defines the priority order for values found in B.
  1. If a value exists in B, place its occurrences according to its position in B.
  2. Place values absent from B at the end in ascending order.

Example 1

A = [1, 2, 3, 4, 5, 4]
B = [5, 4, 2]

The priorities are 5, then 4, then 2. Their frequencies in A are:

ElementFrequency in A
51
42
21

The prioritized portion is [5, 4, 4, 2]. The remaining values 1 and 3 are already in ascending order.

Final result = [5, 4, 4, 2, 1, 3]

Example 2

A = [5, 17, 100, 11]
B = [1, 100]

1 does not occur in A; 100 does. The remaining values 5, 11, and 17 are sorted ascending.

Final result = [100, 5, 11, 17]

2. Brute-force approach

Intuition

Process every value in B and search for its occurrences in A. A visited array tracks which positions in A have already been placed.

Algorithm

  1. Create an empty result array and a boolean visited array of the same size as A.
  2. For each value in B, scan all of A.
  3. When an unvisited matching value is found, add it to the result and mark its position visited.
  4. Collect all unvisited values, sort them ascending, and append them to the result.

Java code

import java.util.*;

public class Solution {

    public ArrayList<Integer> solve(
        ArrayList<Integer> A,
        ArrayList<Integer> B
    ) {

        ArrayList<Integer> result = new ArrayList<>();
        int n = A.size();

        // Track which positions in A have already been added.
        boolean[] visited = new boolean[n];

        // Follow B's priority order and find every matching occurrence.
        for (int i = 0; i < B.size(); i++) {
            int target = B.get(i);

            // Scan A to preserve every duplicate occurrence.
            for (int j = 0; j < n; j++) {
                if (!visited[j] && A.get(j) == target) {
                    result.add(A.get(j));
                    visited[j] = true;
                }
            }
        }

        // Gather values that do not appear in B.
        ArrayList<Integer> remaining = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if (!visited[i]) {
                remaining.add(A.get(i));
            }
        }

        // The values outside B must be in ascending order.
        Collections.sort(remaining);
        result.addAll(remaining);
        return result;
    }
}

Dry run

For A = [1, 2, 3, 4, 5, 4] and B = [5, 4, 2]:

Initially:
visited = [false, false, false, false, false, false]
result  = []

After processing 5:
result  = [5]
visited = [false, false, false, false, true, false]

After processing both occurrences of 4 and then 2:
result = [5, 4, 4, 2]

Remaining values = [1, 3]
Final result     = [5, 4, 4, 2, 1, 3]

Complexity analysis

Let N be the length of A and M the length of B.

  • Scanning A once for every value in B takes O(M × N).
  • Collecting leftovers takes O(N); sorting them takes O(N log N).
  • Overall time: \(O(M \times N + N\log N)\).
  • Visited, result, and remaining arrays use \(O(N)\) space.

Limitation: when both arrays can contain up to 100,000 elements, repeatedly scanning A for every value in B is inefficient.

3. Optimized approach — HashMap frequency counting

Recommended approach. Count each value once, emit values in B's order, then sort the remaining distinct keys.

Intuition

A frequency map stores how many times each value appears. For example:

A = [1, 2, 3, 4, 5, 4]
frequency = {1=1, 2=1, 3=1, 4=2, 5=1}

Solve the problem in two phases: process values following B, then process the values that remain in ascending order.

Algorithm

  1. Count the frequencies of all values in A with a HashMap.
  2. Traverse B. For each key present in the map, append it according to its frequency and remove the key.
  3. Sort the keys that remain in the map and append each according to its frequency.
  4. Return the result.

Java code

import java.util.*;

public class Solution {

    public ArrayList<Integer> solve(
        ArrayList<Integer> A,
        ArrayList<Integer> B
    ) {

        // Store the frequency of every value in A.
        HashMap<Integer, Integer> frequency = new HashMap<>();
        for (int num : A) {
            frequency.put(num, frequency.getOrDefault(num, 0) + 1);
        }

        ArrayList<Integer> result = new ArrayList<>();

        // Emit values in B's order, preserving each value's frequency.
        for (int num : B) {
            if (frequency.containsKey(num)) {
                int count = frequency.get(num);

                // Add every occurrence before removing this processed key.
                for (int i = 0; i < count; i++) {
                    result.add(num);
                }
                frequency.remove(num);
            }
        }

        // Only values absent from B remain in the frequency map.
        ArrayList<Integer> remaining = new ArrayList<>(frequency.keySet());
        Collections.sort(remaining);

        // Append remaining values in ascending order, including duplicates.
        for (int num : remaining) {
            int count = frequency.get(num);
            for (int i = 0; i < count; i++) {
                result.add(num);
            }
        }

        return result;
    }
}

Understanding the important code

1. Counting frequencies

frequency.put(num, frequency.getOrDefault(num, 0) + 1);

getOrDefault() returns the current frequency if the key exists, or 0 otherwise; adding one updates the count. For A = [4, 4, 5, 2, 4], the resulting map is {4=3, 5=1, 2=1}.

2. Processing values from B

For B = [5, 4, 2], emit 5 once, 4 twice, and 2 once to get [5, 4, 4, 2]. Removing each processed key makes the remaining map contain only values absent from B, preventing them from being emitted twice.

3. Getting the remaining elements

ArrayList<Integer> remaining = new ArrayList<>(frequency.keySet());
Collections.sort(remaining);

A HashMap does not guarantee sorted key order, so sorting the extracted distinct keys is necessary.

4. Adding remaining elements

For each remaining key, append it as many times as its stored frequency indicates.

5. Complexity analysis

Let N be the length of A, M the length of B, and K the number of distinct keys remaining after processing B.

OperationTime complexity
Build frequency mapO(N) average
Traverse BO(M) average
Add all values to resultO(N)
Extract remaining keysO(K)
Sort remaining keysO(K log K)

Overall time complexity:

\[\boxed{O(N + M + K\log K)}\]

Since K cannot exceed N, the worst case is:

\[\boxed{O(N\log N + M)}\]

The frequency map, remaining keys, and result each use up to O(N) space. Auxiliary space and output space are each O(N).

Can we optimize further?

A TreeMap can keep keys in ascending order automatically, but its operations take O(log N) time. HashMap operations take O(1) on average, so HashMap plus sorting is generally preferable here.

6. Another optimized approach — custom comparator

Build a map from each value in B to its position, then sort A with a comparator that uses these rules:

  • If both values occur in B, compare their positions in B.
  • If only one occurs in B, place that value first.
  • If neither occurs in B, compare their numeric values in ascending order.

Java code

import java.util.*;

public class Solution {

    public ArrayList<Integer> solve(
        ArrayList<Integer> A,
        ArrayList<Integer> B
    ) {

        // Record each prioritized value's position in B.
        HashMap<Integer, Integer> position = new HashMap<>();
        for (int i = 0; i < B.size(); i++) {
            position.put(B.get(i), i);
        }

        // Sort by B's priority, then by numeric value for non-prioritized values.
        Collections.sort(A, (a, b) -> {
            boolean aPresent = position.containsKey(a);
            boolean bPresent = position.containsKey(b);

            // When both are prioritized, their B positions decide the order.
            if (aPresent && bPresent) {
                return Integer.compare(position.get(a), position.get(b));
            }

            // Any value listed in B precedes a value not listed in B.
            if (aPresent) return -1;
            if (bPresent) return 1;

            // Values absent from B are ordered numerically without subtraction.
            return Integer.compare(a, b);
        });

        return A;
    }
}

Why does this work?

For A = [1, 2, 3, 4, 5, 4] and B = [5, 4, 2], the comparator establishes that 5 comes before 4, which comes before 2, followed by the remaining values 1 and 3 in ascending order. Here, “comes before” does not mean numerically smaller.

[5, 4, 4, 2, 1, 3]

Complexity

  • Build the position map: O(M) average.
  • Sort A: O(N log N) comparisons, each with O(1) average HashMap lookup.
  • Overall: \(O(M + N\log N)\).
  • Map space: O(M), excluding sorting implementation overhead.

Which optimized approach should you choose?

The HashMap frequency-counting approach is recommended because it follows the problem directly, avoids sorting all N values, handles duplicates naturally, and is easy to explain in interviews. It is especially useful when B contains only a small subset of the distinct values in A. The comparator approach is also useful for demonstrating custom sorting.

7. Edge cases

Case 1: B contains values that do not exist in A

A = [3, 1, 2]
B = [5, 4]
Output = [1, 2, 3]

Non-existing values from B are simply ignored.

Case 2: All values in A exist in B

A = [4, 2, 4, 5]
B = [5, 4, 2]
Output = [5, 4, 4, 2]

There are no remaining values to sort.

Case 3: No values in A exist in B

A = [8, 3, 6, 1]
B = [5, 4]
Output = [1, 3, 6, 8]

The entire array is sorted in ascending order.

Case 4: A contains duplicates

A = [3, 3, 2, 2, 1]
B = [2, 3]
Output = [2, 2, 3, 3, 1]

Frequency counting ensures that no occurrence is lost.

Case 5: Negative numbers

A = [-5, 3, -2, 1, -5]
B = [-2, -5]
Output = [-2, -5, 1, 3]

HashMap supports negative integer keys without special handling.

Case 6: Single-element array

A = [10]
B = [10, 20]
Output = [10]

This also works correctly.

9. Interview preparation notes

Important concepts to remember

ConceptWhy it is useful
HashMapStore element frequencies
Frequency countingHandle duplicates efficiently
Custom orderingFollow the priority given by B
SortingArrange remaining elements
ComparatorDefine custom sorting rules

Common mistakes

  1. Forgetting duplicates by adding an element only once instead of according to its frequency.
  2. Ignoring elements absent from B; every element of A must appear in the result.
  3. Not sorting the remaining elements; a HashMap does not guarantee ascending order.
  4. Using subtraction in a comparator; avoid a - b because integer overflow is possible. Use Integer.compare(a, b).
  5. Not removing processed keys, which can add already-emitted values again while processing the remaining elements.

Likely interview follow-up questions

Q1. Why use HashMap instead of HashSet?

A HashSet stores only unique values. We need each value's count, so HashMap is more suitable.

Q2. What if B contains duplicate values?

The given constraints guarantee that B contains unique values. If duplicates were allowed, we would need to define how repeated priorities should be interpreted.

Q3. Can we solve this using TreeMap?

Yes. TreeMap maintains ascending key order, but insertion and lookup take O(log N); HashMap operations take O(1) on average.

Q4. Can we solve this using a custom comparator?

Yes. Store each value's position in B using a HashMap and compare values by their positions. Values absent from B are compared numerically.

Remember this intuition

  1. Count: store the frequency of every value in A using HashMap.
  2. Prioritize: process values according to the order in B.
  3. Complete: sort the remaining keys and append their occurrences.
