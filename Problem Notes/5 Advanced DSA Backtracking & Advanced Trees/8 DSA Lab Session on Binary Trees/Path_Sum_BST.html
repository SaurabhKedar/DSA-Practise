Binary Trees · Depth-First Search

Path Sum

Determine whether a binary tree contains a root-to-leaf path whose node values sum to the target.

Recommended approach: Use iterative DFS and carry the remaining target sum with each node. A match counts only when the path ends at a leaf.

1. Problem Understanding

We are given a binary tree with root A and a target sum B. Check whether at least one path from the root to a leaf has a sum equal to B.

  • Root: The first node of the tree.
  • Leaf: A node with no left or right child.
  • Path: Move from parent to child, starting at the root and ending at a leaf.
  • Output: Return 1 if such a path exists; otherwise, return 0.

Important: Reaching a node with the target sum is not enough. That node must also be a leaf.

2. Brute Force Approach

Explore every root-to-leaf path, calculate its sum, and compare it with B.

Algorithm

  1. Start at the root with the current sum equal to zero.
  2. Add the current node's value to the sum.
  3. If the current node is a leaf, check whether the sum equals B.
  4. Otherwise, explore the left and right subtrees.
  5. If either subtree contains a matching path, return 1; otherwise, return 0.

A brute-force implementation could explicitly store each path and calculate its sum at every leaf. Storing paths is unnecessary for the most efficient traversal, but the version below demonstrates the explicit-path approach.

3. Brute Force Solution — Store and Check Each Path

Maintain the current path in a list. At each leaf, calculate the sum of all values in that path and compare it with B. 

import java.util.*;

public class Solution {

    private boolean dfs(TreeNode node, int target, List<Integer> path) {
        if (node == null) {
            return false;
        }

        // Include the current node in the path.
        path.add(node.val);

        boolean found = false;

        // Check the sum only when we reach a leaf.
        if (node.left == null && node.right == null) {
            long sum = 0;

            // Calculate the sum of this complete path.
            for (int value : path) {
                sum += value;
            }

            found = sum == target;
        } else {
            // Explore both subtrees.
            found = dfs(node.left, target, path)
                  || dfs(node.right, target, path);
        }

        // Backtrack: remove the current node before returning.
        path.remove(path.size() - 1);
        return found;
    }

    public int hasPathSum(TreeNode A, int B) {
        return dfs(A, B, new ArrayList<>()) ? 1 : 0;
    }
}

Complexity

Let \(N\) be the number of nodes and \(H\) the tree height.

  • Time: \(O(NH)\) in the worst case, because summing each leaf's path can take up to \(H\) time.
  • Auxiliary space: \(O(H)\) for the path and recursive call stack.

Limitation: A highly skewed tree can make this approach inefficient, and deep recursion can cause a StackOverflowError in Java.

4. Optimized Approach — Iterative DFS

Instead of storing paths and repeatedly adding their values, carry the remaining sum as you traverse the tree.

For example, if the target is 22 and the path is 5 → 4 → 11 → 2:

  • Start with remaining sum 22.
  • Visit 5: remaining sum becomes 22 - 5 = 17.
  • Visit 4: remaining sum becomes 17 - 4 = 13.
  • Visit 11: remaining sum becomes 13 - 11 = 2.
  • Visit 2: remaining sum becomes 2 - 2 = 0.

The path is valid because the remaining sum is zero at a leaf.

Algorithm

  1. Create a stack to perform Depth-First Search (DFS).
  2. Store each stack entry as a pair: (node, remainingSum).
  3. Start by pushing the root and target sum B.
  4. Pop an entry and subtract the current node's value from its remaining sum.
  5. If the node is a leaf and the remaining sum is zero, return 1.
  6. Otherwise, push its existing children with the updated remaining sum.
  7. If the stack becomes empty, return 0.

This iterative version avoids recursion-depth problems, which matters because the constraints permit up to \(10^5\) nodes.

Recommended Java solution

import java.util.*;

public class Solution {

    public int hasPathSum(TreeNode A, int B) {

        // An empty tree has no root-to-leaf path.
        if (A == null) {
            return 0;
        }

        // Each entry stores a node and its remaining target sum.
        Stack<TreeNode> nodes = new Stack<>();
        Stack<Long> sums = new Stack<>();

        nodes.push(A);
        sums.push((long) B);

        while (!nodes.isEmpty()) {

            TreeNode current = nodes.pop();
            long remaining = sums.pop();

            // Subtract the current node's value.
            remaining -= current.val;

            // A valid path must end at a leaf.
            if (current.left == null && current.right == null) {
                if (remaining == 0) {
                    return 1;
                }
                continue;
            }

            // Explore the left subtree, if it exists.
            if (current.left != null) {
                nodes.push(current.left);
                sums.push(remaining);
            }

            // Explore the right subtree, if it exists.
            if (current.right != null) {
                nodes.push(current.right);
                sums.push(remaining);
            }
        }

        // No root-to-leaf path matched the target.
        return 0;
    }
}

Why use long for the remaining sum? The target and individual node values are integers, but a path can contain up to \(10^5\) nodes. Its accumulated sum can exceed Java's int range, so using long prevents overflow.

6. Complexity Analysis

Approach Time complexity Auxiliary space Main drawback
Brute force: recalculate each path sum \(O(NH)\) \(O(H)\) Recalculates sums
Optimized: iterative DFS \(O(N)\) \(O(N)\) worst case Uses explicit stacks

Here, \(N\) is the number of nodes and \(H\) is the tree height.

  • Brute force: A path can contain \(H\) nodes, and summing paths at the leaves may require \(O(NH)\) time.
  • Optimized: Each node is processed at most once, giving \(O(N)\) time.
  • Space: The iterative stack can hold up to \(O(N)\) nodes in a highly branching tree. This extra memory avoids deep recursive calls.

9. Interview Preparation Notes

Pattern to remember: Binary tree DFS with a running sum.

Common mistakes

  • Checking the target sum at every node instead of only at leaves.
  • Assuming node values are positive.
  • Using int for a potentially large accumulated sum.
  • Using recursion without considering the maximum tree depth.

Likely interviewer follow-ups

Q1. Can we solve this recursively?

Yes. Pass the remaining target to each child and return true when a leaf exactly matches it. However, a tree of depth \(10^5\) can overflow Java's call stack.

Q2. Why do we need to check both left == null and right == null?

Because a leaf has neither child. A node with only one child is not a leaf.

Q3. Can we stop when the remaining sum becomes zero?

No. We must also reach a leaf. A later negative node could change the sum.

Q4. Why is the optimized time complexity \(O(N)\)?

Every node is pushed and popped at most once, and the work performed per node is constant.

10. Final Recommendation

For this problem's constraint of up to \(10^5\) nodes, use iterative DFS because it processes every node at most once and avoids recursion-depth issues.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(N)\) worst case
  • Core intuition: Subtract each visited node's value from the remaining target. If the remaining sum becomes zero at a leaf, return 1; otherwise, keep searching.

Remember: The path must start at the root, end at a leaf, and have exactly the target sum.
