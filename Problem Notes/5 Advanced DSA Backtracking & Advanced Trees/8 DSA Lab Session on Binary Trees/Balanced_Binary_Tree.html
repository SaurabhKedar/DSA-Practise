Java Algorithm Guide

Balanced Binary Tree

The key idea is to check whether the height difference between the left and right subtrees of every node is at most 1. The recommended solution calculates height and checks balance together in a single postorder traversal.

Pattern to remember: Postorder traversal + subtree information + early termination.

1. Problem Understanding

A binary tree is height-balanced if, for every node:

\[\left|\text{height(left)}-\text{height(right)}\right|\leq 1\]

Throughout this guide, height means the number of edges on the longest path from a node to a leaf. Therefore, an empty subtree has height -1 and a leaf has height 0.

  • If every node satisfies this condition, return 1.
  • If even one node violates it, return 0.

For this problem, there are two approaches:

  1. Brute force: Calculate the height of both subtrees at every node.
  2. Optimized: Calculate height and check balance together in a single postorder traversal.

The optimized approach is recommended because the tree can contain up to 10^5 nodes.

Example 1 — Balanced

    1
   / \
  2   3

Root 1 has two leaf children. Each subtree has height 0; their difference is 0.

Output: 1

1

    3

This right-skewed tree has a left-subtree height of -1 and right-subtree height of 1 at node 1.

2. Brute Force Approach

Intuition

For every node:

  1. Calculate the height of its left subtree.
  2. Calculate the height of its right subtree.
  3. If the difference is greater than 1, return 0.
  4. Otherwise, repeat the same check for the left and right children.
  5. If all nodes are balanced, return 1.

The problem is that subtree heights are calculated repeatedly.

Java code — brute force

public class Solution {

    // Calculates the height of a subtree.
    private int height(TreeNode root) {
        if (root == null) {
        return -1;
        }

        int leftHeight = height(root.left);
        int rightHeight = height(root.right);

        return 1 + Math.max(leftHeight, rightHeight);
    }

    public int isBalanced(TreeNode A) {
        if (A == null) {
            return 1;
        }

        // Calculate the heights of both subtrees.
        int leftHeight = height(A.left);
        int rightHeight = height(A.right);

        // If the difference is greater than 1, the current node is unbalanced.
        if (Math.abs(leftHeight - rightHeight) > 1) {
            return 0;
        }

        // Both subtrees must also be balanced.
        if (isBalanced(A.left) == 0 ||
            isBalanced(A.right) == 0) {
            return 0;
        }

        return 1;
    }
}

Complexity

  • Time: \(O(n\log n)\) in the worst case for this early-exit implementation. A balanced tree recalculates subtree heights at each level, giving \(O(n)\) work per level across \(O(\log n)\) levels. An unbalanced node stops the recursive balance checks early.
  • Auxiliary space: \(O(h)\) for the recursive call stack, where \(h\) is the tree height.
Limitation: Repeated height calculations make this approach inefficient for large trees.

3. Optimized Approach — Height and Balance Together

Intuition

Instead of calculating height separately and then checking balance, we can do both in a single traversal. Postorder traversal processes the left subtree, then the right subtree, and finally the current node.

We use a special return value:

  • An integer greater than or equal to -1 represents the subtree's height.
  • -1 is the height of an empty subtree.
  • -2 means the subtree is unbalanced; no valid subtree height is less than -1.

Algorithm

  1. If the node is null, return height -1.
  2. Recursively calculate the left subtree's height.
  3. If the left subtree returns the unbalanced sentinel -2, immediately return -2.
  4. Calculate the right subtree's height.
  5. If the right subtree returns -2, immediately return -2.
  6. If the absolute difference between the two heights exceeds 1, return -2.
  7. Otherwise, return 1 + max(leftHeight, rightHeight).
  8. In isBalanced(), convert the result into 1 or 0.

Java code — optimized solution

This is the recommended interview solution for the given platform's signature.

public class Solution {

    // Returns the subtree height, or -2 if it is unbalanced.
    private int checkHeight(TreeNode root) {

        // An empty subtree has height -1, so a leaf has height 0.
        if (root == null) {
            return -1;
        }

        // First, check the left subtree.
        int leftHeight = checkHeight(root.left);

        // No need to continue if the left subtree is unbalanced.
        if (leftHeight == -2) {
            return -2;
        }

        // Next, check the right subtree.
        int rightHeight = checkHeight(root.right);

        // No need to continue if the right subtree is unbalanced.
        if (rightHeight == -2) {
            return -2;
        }

        // The current node is unbalanced if the height difference exceeds 1.
        if (Math.abs(leftHeight - rightHeight) > 1) {
            return -2;
        }

        // Return the height of the current subtree.
        return 1 + Math.max(leftHeight, rightHeight);
    }

    public int isBalanced(TreeNode A) {

        // -2 means unbalanced; otherwise, the tree is balanced.
        return checkHeight(A) == -2 ? 0 : 1;
    }
}

Alternative optimized solution — shared flag

This version tracks imbalance with a shared boolean instead of returning a sentinel height. Reset the flag at the start of every top-level call so results from a previous tree do not affect the next one. 

public class Solution {

    private static boolean balanced;

    // Returns the edge-based height of this subtree; an empty subtree has height -1.
    private static int height(TreeNode node) {
        if (node == null) {
            return -1;
        }

        // Visit both subtrees before checking this node (postorder traversal).
        int leftHeight = height(node.left);
        int rightHeight = height(node.right);

        // Record an imbalance, but keep computing heights for the parent nodes.
        if (Math.abs(leftHeight - rightHeight) > 1) {
            balanced = false;
        }

        return 1 + Math.max(leftHeight, rightHeight);
    }

    public static int isBalanced(TreeNode root) {
        // Reset shared state for each independent invocation.
        balanced = true;
        height(root);
        return balanced ? 1 : 0;
    }
}

This also runs in \(O(n)\) time and uses \(O(h)\) recursive stack space. Because it uses shared static state, it is not safe for concurrent calls; use the sentinel-returning version above in that case. Match the method's static modifier and visibility to the platform's required signature.

The final condition is:

return checkHeight(A) == -2 ? 0 : 1;

Since the result is -2, the method returns 0. Output: 0.

Why check leftHeight == -2 and rightHeight == -2? A parent cannot fix an imbalance in a deep subtree, so there is no need to continue calculating heights. This early return avoids unnecessary work.

5. Complexity Comparison

Approach Time complexity Auxiliary space
Brute force with early exit\(O(n\log n)\) worst case\(O(h)\)
Optimized\(O(n)\)\(O(h)\)

Here, \(n\) is the number of nodes and \(h\) is the height of the tree.

The optimized approach visits each node at most once, so its time complexity is \(O(n)\).

Important Java consideration: Both implementations use recursion. For a highly skewed tree with up to 10^5 nodes, the recursion depth may exceed Java's stack capacity. The optimized algorithm improves time complexity but does not eliminate this risk. An iterative postorder implementation can avoid deep recursive calls if the platform requires handling such worst-case shapes reliably.

8. Interview Preparation Notes

Pattern to remember: Postorder traversal + subtree information + early termination.

Common mistakes

  • Checking only the root's height difference instead of checking every node.
  • Recalculating heights repeatedly, leading to \(O(n\log n)\) worst-case time with this implementation's early exit.
  • Forgetting to propagate the -2 signal from an unbalanced subtree.
  • Assuming that a tree with equal left and right subtree heights at the root must be balanced.

Likely interviewer follow-ups

Q1. Why use postorder traversal?

Because we need the heights of both children before deciding whether the current node is balanced.

Q2. Can we solve this in \(O(n)\) time?

Yes. Calculate the height and check balance together, processing each node once.

Q3. Why return -2 instead of a boolean?

The recursive function needs to communicate both the height and whether the subtree is unbalanced. The sentinel value lets it communicate both using a single integer return value.

Q4. What is the difference between a balanced tree and a complete binary tree?

A balanced tree constrains the height difference between every node's subtrees. A complete binary tree requires every level except possibly the last to be completely filled, with the last level filled from left to right.

9. Final Recommendation

Use the optimized postorder solution in interviews. It avoids repeated height calculations and achieves \(O(n)\) time.

  • Time complexity: \(O(n)\)
  • Auxiliary space: \(O(h)\) for recursion
  • Core intuition: Get the heights from the children, detect imbalance immediately, and pass the result upward.
