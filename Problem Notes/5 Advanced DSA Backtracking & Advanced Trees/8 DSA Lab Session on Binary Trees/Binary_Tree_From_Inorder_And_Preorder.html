Binary Tree From Inorder And Preorder

Reconstruct a binary tree from its preorder and inorder traversals. Preorder tells us the root of each subtree, while inorder divides that subtree into its left and right parts.

Pattern to remember: Pick the root from preorder, locate it in inorder, then build the left subtree before the right subtree.

1. Problem Understanding

You are given two arrays:

  • A — preorder traversal of a binary tree.
  • B — inorder traversal of the same binary tree.

Reconstruct the original binary tree and return its root.

Understand the traversals

  • Preorder: Root → Left → Right
  • Inorder: Left → Root → Right

Example

A = [1, 2, 3]  // Preorder
B = [2, 1, 3]  // Inorder

How the traversals determine the tree

  1. The first preorder element is 1, so 1 is the root.
  2. Find 1 in inorder: [2, 1, 3].
  3. Values to the left of 1 belong to its left subtree: [2]. Values to the right belong to its right subtree: [3].
  4. Repeat the same process for each subtree.

Inorder split

[2, 1, 3]
    ↑
   Root

Resulting tree

    1
   / \
  2   3

Because duplicate values do not exist, the root's position in the inorder traversal uniquely identifies the left and right subtrees.

2. Brute-Force Approach

Intuition

Repeatedly find the root in the inorder array and recursively build the corresponding subtrees.

  1. Take the first preorder element as the root.
  2. Search for that root in the inorder array.
  3. Split inorder into left and right portions.
  4. Use the corresponding preorder portions to recursively build both subtrees.
  5. Return the root.

Java solution

public class Solution {
    public TreeNode buildTree(int[] A, int[] B) {
        return build(A, 0, A.length - 1,
                     B, 0, B.length - 1);
    }

    private TreeNode build(int[] preorder, int ps, int pe,
                           int[] inorder, int is, int ie) {
        // No elements means no subtree.
        if (ps > pe || is > ie) {
            return null;
        }

        // The first preorder element is the root.
        int rootValue = preorder[ps];
        TreeNode root = new TreeNode(rootValue);

        // Find the root's position in inorder.
        int index = is;
        while (index <= ie && inorder[index] != rootValue) {
            index++;
        }

        // Count the nodes in the left subtree.
        int leftSize = index - is;

        // Build the left subtree.
        root.left = build(preorder, ps + 1, ps + leftSize,
                          inorder, is, index - 1);

        // Build the right subtree.
        root.right = build(preorder, ps + leftSize + 1, pe,
                           inorder, index + 1, ie);

        return root;
    }
}

Dry run

For A = [1, 2, 3] and B = [2, 1, 3]:

StepRootInorder splitAction
11[2], 1, [3]Create root 1
222Create left child 2
333Create right child 3

The final tree has 1 as the root, 2 as its left child, and 3 as its right child.

Complexity analysis

  • Time: \(O(N^2)\) in the worst case. Each recursive call may scan most of its inorder segment to find the root.
  • Auxiliary space: \(O(N)\) for recursion in the worst case, excluding the tree and temporary arrays. This implementation uses index ranges rather than allocating new arrays.
Limitation: For up to 10^5 nodes, repeatedly scanning inorder can be too slow, especially for a skewed tree.

3. Optimized Approach — HashMap + Recursion

Recommended approach for interviews.

Why do we need optimization?

The brute-force approach searches for the root in the inorder array during every recursive call, which can take \(O(N^2)\) time. Store each inorder value's index in a HashMap to avoid repeated searching.

Intuition

For the same example:

Preorder = [1, 2, 3]
Inorder  = [2, 1, 3]

Create a map from each value to its inorder index:

Value → Inorder index

2 → 0
1 → 1
3 → 2

This lets us find any root's inorder position in \(O(1)\) average time instead of searching the array. We also maintain preIndex, which points to the next root in preorder.

Algorithm: Step by step

  1. Store every inorder element and its index in a HashMap.
  2. Initialize preIndex = 0.
  3. Take A[preIndex] as the current root and increment preIndex.
  4. Look up the root's position in the inorder map.
  5. Recursively construct the left subtree using the inorder range before the root.
  6. Recursively construct the right subtree using the inorder range after the root.
  7. Return the root when the subtree is complete.

Optimized Java solution

import java.util.HashMap;
import java.util.Map;

public class Solution {

    private Map<Integer, Integer> inorderMap;
    private int preIndex;

    public TreeNode buildTree(int[] A, int[] B) {

        // Store each inorder value and its index.
        inorderMap = new HashMap<>();

        for (int i = 0; i < B.length; i++) {
            inorderMap.put(B[i], i);
        }

        // Points to the next root in preorder.
        preIndex = 0;

        // Initially, the entire inorder range is available.
        return build(A, 0, B.length - 1);
    }

    private TreeNode build(int[] preorder, int inStart, int inEnd) {

        // No elements remain in this subtree.
        if (inStart > inEnd) {
            return null;
        }

        // Preorder visits the root before its children.
        int rootValue = preorder[preIndex];
        preIndex++;
        TreeNode root = new TreeNode(rootValue);

        // Find the root position in O(1) average time.
        int rootIndex = inorderMap.get(rootValue);

        // Build the left subtree first.
        root.left = build(preorder, inStart, rootIndex - 1);

        // Then build the right subtree.
        root.right = build(preorder, rootIndex + 1, inEnd);

        return root;
    }
}
Why build the left subtree first?

Preorder follows Root → Left → Right. After consuming the root, the next preorder values belong to the left subtree before the right subtree, so the recursive calls must process the left subtree first.

5. Complexity Analysis

Let \(N\) be the number of nodes.

OperationBrute forceOptimized
Build inorder lookupNot needed\(O(N)\)
Find each rootUp to \(O(N)\) per call\(O(1)\) average
Total time\(O(N^2)\) worst case\(O(N)\) average
Auxiliary space\(O(N)\)\(O(N)\)

Optimized complexity explained

  • Time: \(O(N)\) average. Each node is created once, each HashMap lookup takes \(O(1)\) average time, and building the map takes \(O(N)\).
  • Auxiliary space: \(O(N)\). The HashMap uses \(O(N)\), and the recursion stack uses up to \(O(N)\) in a skewed tree.
  • Output space: The resulting tree contains \(N\) nodes and requires \(O(N)\) space.
Practical Java consideration: A highly skewed tree with 10^5 nodes can cause a StackOverflowError with recursive solutions. The algorithm is optimal in time, but an iterative construction can avoid deep recursion for that extreme case.

6. Edge Cases

Left-skewed tree: A = [3, 2, 1], B = [1, 2, 3]Construct a chain of left children
Right-skewed tree: A = [1, 2, 3], B = [1, 2, 3]Construct a chain of right children
Negative or zero valuesHashMap supports them

The problem guarantees valid traversals of the same tree and distinct values, so the solution does not need extra validation for inconsistent arrays or duplicate values.

8. Interview Preparation Notes

Key concept to remember

Preorder identifies the root; inorder identifies the left and right subtrees. The HashMap makes it efficient to locate each root's position in inorder.

Common mistakes

  1. Building the right subtree before the left subtree while consuming preorder from left to right.
  2. Forgetting to increment preIndex after selecting a root.
  3. Using the wrong inorder ranges: left is inStart to rootIndex - 1, and right is rootIndex + 1 to inEnd.
  4. Searching the entire inorder array on every recursive call instead of using a HashMap.

Likely interviewer follow-up questions

Q1. Can we construct a unique tree from preorder alone?

Not for a general binary tree. Preorder alone does not tell us which nodes belong to the left and right subtrees. Additional information or constraints are needed.

Q2. Why do we need both traversals?

Preorder tells us the root order, and inorder tells us the subtree boundaries. Together, with distinct values, they uniquely determine the tree.

Q3. What if duplicate values exist?

The HashMap approach cannot uniquely identify a root's position using the value alone. Additional information or different assumptions would be necessary.

Q4. Can we solve this without a HashMap?

Yes. Scanning inorder to locate each root takes \(O(N^2)\) time in the worst case. Alternatively, an iterative solution can use a stack to avoid deep recursion.

9. Final Recommendation

For interviews, use the optimized HashMap + recursion approach.

  • Time complexity: \(O(N)\) average.
  • Auxiliary space: \(O(N)\).
  • Pattern: Binary tree construction, recursion, and traversal indexing.
Remember this sequence: Pick root from preorder → find root in inorder → build left subtree → build right subtree.
