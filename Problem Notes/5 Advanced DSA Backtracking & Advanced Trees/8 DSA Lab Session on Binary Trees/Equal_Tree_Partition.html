Equal Tree Partition

Determine whether removing one edge can split a binary tree into two trees with equal sums.

Recommended approach: Calculate each subtree sum once with an iterative traversal, then check every non-root subtree against half of the total.

1. Problem Understanding

We are given the root of a binary tree A. We must remove exactly one edge so that the two resulting trees have equal sums of node values.

Let the sum of all nodes be \(S\). If a subtree has sum \(X\), removing the edge between that subtree's root and its parent leaves sums \(X\) and \(S-X\). They are equal when:

\[ X=S-X \implies 2X=S \]

Therefore, a valid partition exists if a non-root subtree has half the total sum.

  • If the total sum is odd, an equal partition is impossible.
  • The root cannot be detached by removing an edge above it because it has no parent.
  • Node values can be zero, so a total sum of zero can still allow a valid partition.
  • With up to \(10^5\) nodes, repeatedly calculating subtree sums is inefficient.

2. Brute Force and Recursive Alternative

Consider removing each edge one at a time and calculate the sum of the detached subtree.

  1. Calculate the total sum of the tree.
  2. For every non-root node, calculate the sum of its subtree.
  3. Check whether subtreeSum == totalSum / 2.
  4. Return 1 if any edge gives equal sums; otherwise, return 0.

Every edge connects a node to its parent, so considering each non-root node covers every possible edge removal. However, recalculating the subtree sum for every node can take \(O(N^2)\) time in the worst case.

ComplexityCostReason
Time\(O(N^2)\)Subtree sums may be recalculated for each node.
Auxiliary space\(O(H)\)Recursive calls use space proportional to tree height.

Brute-force Java solution — repeated subtree sums

This version recalculates the subtree sum for each non-root node. The platform provides the TreeNode class. 

public class Solution {
    public int solve(TreeNode A) {
        // An empty tree has no edge that can be removed.
        if (A == null) {
            return 0;
        }

        // Calculate the total once, then test every non-root subtree.
        long totalSum = calculateSubtreeSum(A);
        if (totalSum % 2 != 0) {
            return 0;
        }

        return hasEqualPartition(A, A, totalSum) ? 1 : 0;
    }

    private boolean hasEqualPartition(TreeNode node, TreeNode root, long totalSum) {
        if (node == null) {
            return false;
        }

        // The root has no parent edge, so it cannot be detached.
        if (node != root) {
            long subtreeSum = calculateSubtreeSum(node);
            if (subtreeSum == totalSum / 2) {
                return true;
            }
        }

        // Continue checking the remaining nodes in the tree.
        return hasEqualPartition(node.left, root, totalSum)
                || hasEqualPartition(node.right, root, totalSum);
    }

    private long calculateSubtreeSum(TreeNode node) {
        if (node == null) {
            return 0L;
        }

        // Recompute each candidate subtree's sum recursively.
        return node.val
                + calculateSubtreeSum(node.left)
                + calculateSubtreeSum(node.right);
    }
}

Recursive postorder alternative — linear time

This is not a brute-force solution: it calculates the total in one traversal and all candidate subtree sums in a second, so it runs in \(O(N)\) time. Compared with the iterative solution below, it uses recursion and can reach \(O(H)\) stack space. The platform provides the TreeNode class.

The original snippet's totalSum / 2 == 1 check is not a valid odd-sum test. This version checks totalSum % 2 != 0, uses long to prevent overflow, skips the root as a partition candidate, and resets an instance-level result flag at the start of every call so previous results do not leak into later calls. 

public class Solution {
    private boolean foundHalf;

    public int solve(TreeNode A) {
        // Reset the instance field so repeated calls are independent.
        foundHalf = false;

        // An empty tree has no edge that can be removed.
        if (A == null) {
            return 0;
        }

        // Calculate the total sum before checking whether it can be split evenly.
        long totalSum = calculateTotalSum(A);
        if (totalSum % 2 != 0) {
            return 0;
        }

        calculateSubtreeSumsAndFindHalf(A, A, totalSum);
        return foundHalf ? 1 : 0;
    }

    private long calculateTotalSum(TreeNode node) {
        if (node == null) {
            return 0L;
        }

        return node.val
                + calculateTotalSum(node.left)
                + calculateTotalSum(node.right);
    }

    private long calculateSubtreeSumsAndFindHalf(
            TreeNode node, TreeNode root, long totalSum) {
        if (node == null) {
            return 0L;
        }

        // Postorder: calculate both child sums before this node's subtree sum.
        long leftSum = calculateSubtreeSumsAndFindHalf(node.left, root, totalSum);
        long rightSum = calculateSubtreeSumsAndFindHalf(node.right, root, totalSum);
        long currentSum = node.val + leftSum + rightSum;

        // Only a non-root subtree corresponds to an edge that can be removed.
        if (node != root && currentSum == totalSum / 2) {
            foundHalf = true;
        }

        return currentSum;
    }
}

3. Optimized Approach — Subtree Sum

Intuition

If the total sum is 36 and a subtree has sum 18, removing the edge above it leaves that subtree and the remainder with sums of 18 each.

A postorder traversal lets us calculate a node's subtree sum after its children have been processed. The implementation below uses an iterative traversal so a highly skewed tree does not create deep recursive calls.

Step-by-step algorithm

  1. Traverse the tree and store its nodes in a list.
  2. Process the list in reverse so each node's children are processed before the node itself.
  3. Calculate and store each subtree sum in a HashMap.
  4. Use the root's subtree sum as the total sum.
  5. Check each non-root node for 2 * subtreeSum == totalSum.
  6. Return 1 if a matching subtree exists; otherwise, return 0.

Complete Java solution

import java.util.*;

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {
    public int solve(TreeNode A) {
        // An empty tree cannot be split by removing an edge.
        if (A == null) {
            return 0;
        }

        // Collect nodes iteratively to avoid deep recursive calls.
        List<TreeNode> nodes = new ArrayList<>();
        Deque<TreeNode> stack = new ArrayDeque<>();
        stack.push(A);

        while (!stack.isEmpty()) {
            TreeNode current = stack.pop();
            nodes.add(current);

            // Add each existing child so it appears after its parent.
            if (current.left != null) {
                stack.push(current.left);
            }

            if (current.right != null) {
                stack.push(current.right);
            }
        }

        // Reverse traversal processes children before their parent.
        Map<TreeNode, Long> subtreeSum = new HashMap<>();
        for (int i = nodes.size() - 1; i >= 0; i--) {
            TreeNode current = nodes.get(i);

            // Start with this node's value, then add child subtree sums.
            long sum = current.val;
            if (current.left != null) {
                sum += subtreeSum.get(current.left);
            }
            if (current.right != null) {
                sum += subtreeSum.get(current.right);
            }

            subtreeSum.put(current, sum);
        }

        // The root's subtree sum is the sum of the entire tree.
        long totalSum = subtreeSum.get(A);

        // Only a non-root node has a parent edge that can be removed.
        for (TreeNode node : nodes) {
            if (node == A) {
                continue;
            }

            long sum = subtreeSum.get(node);

            // Use long arithmetic for the doubled subtree sum.
            if (sum * 2L == totalSum) {
                return 1;
            }
        }

        return 0;
    }
}
Why use long? With up to \(10^5\) nodes and values up to \(10^9\), the total can reach \(10^{14}\), beyond Java's int range. The 2L also ensures the multiplication uses long arithmetic.

5. Complexity Analysis

Let \(N\) be the number of nodes and \(H\) the tree height.

ApproachTime complexityAuxiliary space
Brute force\(O(N^2)\)\(O(H)\) recursive stack
Optimized iterative\(O(N)\)\(O(N)\)
  • The first traversal visits every node once: \(O(N)\).
  • The reverse traversal calculates each subtree sum once: \(O(N)\).
  • The final loop checks each node once: \(O(N)\).
  • The list, stack, and hash map use \(O(N)\) additional memory.

The iterative method avoids recursion-depth problems on a highly skewed tree.

8. Interview Preparation Notes

Key concept to remember

Binary Tree + Subtree Sum + Postorder Traversal

A subtree sum is:

\[ \text{subtreeSum}(node) = node.val+\text{leftSum}+\text{rightSum} \]

Once the total sum is known, the partition condition is:

\[ 2 \times \text{subtreeSum}= \text{totalSum} \]

Common mistakes

  • Using int when the total can reach \(10^{14}\); use long.
  • Counting the root as a partition even though it has no parent edge to remove.
  • Recalculating every subtree, which can take \(O(N^2)\) time.
  • Assuming a total sum of zero means the answer is 0; zero-valued trees with at least two nodes can be partitioned.
  • Using recursion without considering tree height; a skewed tree can cause StackOverflowError in Java.

Likely interviewer follow-up questions

Why does an odd total sum rule out a partition?
Equal sums would each have to be half the total, but an odd integer cannot be divided into two equal integer sums.
Why must we exclude the root?
Removing an edge requires a parent-child connection. The root has no parent.
Can we solve this without a hash map?
Yes. A different postorder implementation can track candidate subtree sums; storing sums in a map keeps this solution straightforward.
Why is postorder useful here?
A node's subtree sum depends on its children's sums, so its children must be processed first.

9. Final Recommendation

For an interview, implement the optimized \(O(N)\) approach. The iterative version is particularly suitable when the tree may contain up to \(10^5\) nodes because it avoids recursive stack overflow.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(N)\)
  • Core intuition: Calculate every subtree sum once, then check whether any non-root subtree has exactly half of the total sum.

Remember: find half the total in a non-root subtree, and the tree can be partitioned.
