Next Pointer Binary Tree

The key idea is to connect nodes level by level using the next pointer. Since the problem guarantees a perfect binary tree, we can solve it in \(O(N)\) time and \(O(1)\) auxiliary space without recursion, a queue, or a stack.

Pattern to remember: Connect siblings, connect across parents, and traverse each level using its existing next pointers.

1. Problem Understanding

For every node in the binary tree, set its next pointer to the node immediately to its right on the same level.

  • If a node has a right neighbor, point next to that neighbor.
  • If it is the last node on its level, next must be null.
  • A perfect binary tree has two children for every non-leaf node, and all leaves are at the same depth.

Before connecting

    1
   / \
  2   3

All next pointers are null.

After connecting

1 → null
2 → 3 → null

Each level is linked from left to right, ending in null.

2. Brute-force approach

Use a queue to perform level-order traversal (BFS).

  1. Add the root to the queue.
  2. Process all nodes at the current level.
  3. Connect each node to the next node in that level.
  4. Set the last node's next to null.
  5. Add the current node's children to the queue.

Complexity

Time

\(O(N)\), because each node is processed once.

Auxiliary space

\(O(N)\) in the worst case for the queue.

This works, but we can do better on space because the tree is guaranteed to be perfect.

3. Optimized approach — Constant extra space

Intuition

Because the tree is perfect, every parent has both a left and a right child. This gives us two simple connection rules.

Rule 1: Connect siblings

Connect the left child to the right child of the same parent.

2 → 3

Rule 2: Connect across parents

If the parent has a next node, connect its right child to the next parent's left child.

4 → 6

We use the already-established next pointers to move horizontally across each level. This eliminates the need for a queue.

Java solution

Use the exact method signature provided by the platform.

/**
 * Definition for binary tree with next pointer.
 * public class TreeLinkNode {
 *     int val;
 *     TreeLinkNode left, right, next;
 *     TreeLinkNode(int x) { val = x; }
 * }
 */
public class Solution {
    public void connect(TreeLinkNode root) {

        // An empty tree needs no connections.
        if (root == null) {
            return;
        }

        // Points to the first node of the current level.
        TreeLinkNode levelStart = root;

        // Continue while the current level has children.
        while (levelStart.left != null) {

            // Start traversing this level using next pointers.
            TreeLinkNode current = levelStart;

            while (current != null) {

                // Rule 1: Connect the left child to its sibling.
                current.left.next = current.right;

                // Rule 2: Connect across adjacent parents.
                if (current.next != null) {
                    current.right.next = current.next.left;
                }

                // Move to the next parent in the same level.
                current = current.next;
            }

            // Move down to the first node of the next level.
            levelStart = levelStart.left;
        }
    }
}

Understanding the important lines

  • levelStart = root: identifies the beginning of the current level.
  • current.left.next = current.right: connects sibling nodes.
  • current.right.next = current.next.left: connects nodes belonging to adjacent parents.
  • current = current.next: traverses horizontally using the pointers we have created.
  • levelStart = levelStart.left: moves down one level.
  • while (levelStart.left != null): stops when the current level contains only leaf nodes.

Why don't we explicitly set the last node's next to null?

Initially, every next pointer is null. The algorithm assigns a next pointer to a node only when its right neighbor exists. Therefore, the rightmost node on each level remains connected to null.

5. Complexity analysis

Let \(N\) be the number of nodes and \(H\) the height of the tree.

Time and auxiliary-space complexities of the two approaches
Approach Time complexity Auxiliary space
BFS using a queue\(O(N)\)\(O(N)\)
Optimized next pointers\(O(N)\)\(O(1)\)

Why is the optimized time \(O(N)\)?

Each node is visited once as current, and each visit performs a constant number of pointer operations.

Why is auxiliary space \(O(1)\)?

We use only two references, levelStart and current, regardless of the number of nodes. We don't allocate a queue, stack, or recursive call stack.

6. Edge cases

  • Single node: The root is already correctly connected to null. No loop iteration is needed.
  • Two nodes: The root's left child is connected to its right child.
  • Maximum \(100{,}000\) nodes: The algorithm remains linear and uses constant auxiliary space.
  • Rightmost node on any level: Its next remains null.
  • Empty tree: The null check returns immediately, although an empty tree is outside the stated constraints.

8. Interview preparation notes

Pattern to remember: Level-by-level traversal using existing pointers.

Common mistakes

  • Connecting current.right.next to current.next instead of current.next.left.
  • Forgetting the current.next != null condition.
  • Using the queue-based approach when the interviewer specifically asks for constant extra space.
  • Assuming this exact implementation works for arbitrary binary trees. It relies on the perfect-tree guarantee.

Likely follow-up questions

Q1. Can this solution handle an imperfect binary tree?

Not in its current form. Missing children can break the direct left/right connections. A different constant-space approach can handle arbitrary trees, as in LeetCode 117.

Q2. Why do we process levels from top to bottom?

The next pointers of a level let us traverse its parents horizontally, allowing us to connect the children on the level below.

Q3. Can we solve it recursively?

Yes, but recursion uses \(O(H)\) call-stack space in the worst case. The iterative approach avoids that extra space.
