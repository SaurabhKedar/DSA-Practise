Top View of a Binary Tree

The top view contains the nodes visible when a binary tree is viewed from above. Breadth-First Search (BFS) with horizontal distance finds the shallowest node at each position.

Recommended approach: Traverse level by level, keep the first node seen at each horizontal distance, and return values from left to right.

1. Problem Understanding

Assign every node a horizontal distance (HD): the root has HD 0, a left child has its parent's HD minus one, and a right child has its parent's HD plus one. For each HD, only the first node visible from above is included.

Example 1

          1
        /   \
       2     3
      / \   / \
     4   5 6   7
    /
   8

The visible nodes from left to right are [8, 4, 2, 1, 3, 7]. The problem permits any order, so [1, 2, 4, 8, 3, 7] contains the same top-view nodes.

Nodes 5 and 6 share HD 0 with the root, but are deeper and hidden. In another example, nodes 4 and 5 are hidden behind node 3, giving top view [1, 2, 3].

The example is also discussed in Scaler's Top View of Binary Tree guide.

2. Brute-Force Approach

Visit every node and record its horizontal distance, depth, and value. For each horizontal distance, keep the node with the minimum depth. Then sort the distinct horizontal distances and collect their values.

Java code — brute force

import java.util.*;

public class Solution {
    // Store the shallowest node found at each horizontal distance.
    private Map<Integer, int[]> topNodes = new HashMap<>();

    private void dfs(TreeNode node, int hd, int depth) {
        if (node == null) {
            return;
        }

        // Keep this node if its HD is new or it is closer to the root.
        if (!topNodes.containsKey(hd)
                || depth < topNodes.get(hd)[1]) {
            topNodes.put(hd, new int[]{node.val, depth});
        }

        // Move one HD left and one level deeper.
        dfs(node.left, hd - 1, depth + 1);
        // Move one HD right and one level deeper.
        dfs(node.right, hd + 1, depth + 1);
    }

    public ArrayList<Integer> solve(TreeNode A) {
        topNodes.clear();

        dfs(A, 0, 0);

        // Sort HDs so the output runs from left to right.
        ArrayList<Integer> distances =
                new ArrayList<>(topNodes.keySet());
        Collections.sort(distances);

        ArrayList<Integer> result = new ArrayList<>();
        for (int hd : distances) {
            result.add(topNodes.get(hd)[0]);
        }

        return result;
    }
}

Complexity

  • Time: \(O(N + K\log K)\), where \(K\) is the number of distinct horizontal distances.
  • Auxiliary space: \(O(N)\) for the map and recursion stack in the worst case.
Limitation: The recursive approach may use a deep call stack on a highly skewed tree. BFS avoids that recursion risk and makes shallowest-first selection direct.

3. Optimized Approach — BFS

BFS visits nodes in nondecreasing depth order. Therefore, the first node encountered at any horizontal distance is at the shallowest possible depth. A TreeMap keeps the recorded distances sorted.

Algorithm

  1. Put the root in a queue with HD 0.
  2. Remove the next node from the queue.
  3. If its HD is not recorded, store its value.
  4. Add its left child with HD minus one and its right child with HD plus one.
  5. Continue until the queue is empty, then collect values in increasing HD order.

Interview-ready Java solution

import java.util.*;

public class Solution {

    // Pair each queued tree node with its horizontal distance.
    class Pair {
        TreeNode node;
        int hd;

        Pair(TreeNode node, int hd) {
            this.node = node;
            this.hd = hd;
        }
    }

    public ArrayList<Integer> solve(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();

        // An empty tree has no nodes in its top view.
        if (A == null) {
            return result;
        }

        // TreeMap keeps horizontal distances ordered from left to right.
        TreeMap<Integer, Integer> topView = new TreeMap<>();
        Queue<Pair> queue = new LinkedList<>();
        queue.offer(new Pair(A, 0));

        while (!queue.isEmpty()) {
            Pair current = queue.poll();
            TreeNode node = current.node;
            int hd = current.hd;

            // BFS reaches the shallowest node at this HD first.
            if (!topView.containsKey(hd)) {
                topView.put(hd, node.val);
            }

            // Enqueue children with their corresponding HD values.
            if (node.left != null) {
                queue.offer(new Pair(node.left, hd - 1));
            }
            if (node.right != null) {
                queue.offer(new Pair(node.right, hd + 1));
            }
        }

        // TreeMap values follow ascending horizontal distance.
        result.addAll(topView.values());
        return result;
    }
}

Why BFS works

BFS visits nodes in nondecreasing order of depth. Once an HD is first recorded, no later node at that HD can be closer to the root. Processing left children before right children also makes selection consistent when nodes share both depth and HD.

5. Complexity Analysis

Let \(N\) be the number of nodes and \(K\) the number of distinct horizontal distances.

Approach Time complexity Auxiliary space
DFS + map + sorting\(O(N + K\log K)\)\(O(N)\)
BFS + TreeMap\(O(N\log K)\)\(O(N)\)
BFS + HashMap + sortingExpected \(O(N + K\log K)\)\(O(N)\)

BFS with a HashMap, followed by sorting the horizontal distances, gives expected linear traversal time plus sorting. The TreeMap version is also correct and keeps the implementation straightforward. Queue, map, and stored distances use \(O(N)\) auxiliary space in the worst case; the returned list is output space.

6. Important Edge Cases

  • Single node: The root is the entire top view.
  • Left-skewed tree: Every node has a distinct HD, so every node appears.
  • Right-skewed tree: Every node appears as well.
  • Complete or balanced tree: Multiple nodes can share an HD; retain only the shallowest.
  • Same depth and same HD: Left-first BFS consistently selects the first node encountered.
  • Up to 100,000 nodes: Iterative BFS avoids recursion stack overflow on a deep tree.
  • Null root: The code returns an empty list, although the given constraints require at least one node.

8. Interview Preparation Notes

Pattern to remember: Binary tree + top view → BFS + horizontal distance + first occurrence.

Common mistakes

  • Replacing a stored node with a deeper node at the same HD.
  • Assigning the left and right children the wrong horizontal distances.
  • Returning nodes in arbitrary map iteration order when left-to-right order is expected.
  • Using DFS without comparing depths, which can retain a deeper node incorrectly.

Likely follow-up questions

Why is BFS preferred over DFS?

BFS visits shallower nodes first, so the first node at each HD is automatically the correct top-view candidate.

Can we solve it with DFS?

Yes. Track the minimum depth for each HD and replace a stored node only when a shallower one is found.

What is the difference between top view and vertical order traversal?

Top view retains only one visible node per HD. Vertical order traversal groups all nodes by HD, usually with additional ordering rules.

Can we achieve expected \(O(N)\) time?

Use BFS with a HashMap to record the first node at each HD, then sort the \(K\) distinct distances. The total is \(O(N + K\log K)\); sorting cost should be accounted for separately.

9. Final Recommendation

For interviews, use BFS with a HashMap and sorted horizontal distances. It avoids recursive stack issues and runs in expected \(O(N + K\log K)\) time.

Assign each node a horizontal distance. Traverse level by level, keep the first node at each distance, and return those nodes in horizontal-distance order.
