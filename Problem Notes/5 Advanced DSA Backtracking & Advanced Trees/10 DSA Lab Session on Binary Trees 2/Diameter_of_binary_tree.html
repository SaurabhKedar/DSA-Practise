Java Algorithm Guide

Diameter of Binary Tree

Find the longest path between any two nodes in a binary tree, counting its edges. The optimized solution computes subtree heights in one postorder traversal while tracking the best diameter found.

Pattern to remember: Postorder DFS + subtree heights + a global maximum.

1. Problem Understanding

The diameter of a binary tree is the number of edges in the longest path between any two nodes.

  • The longest path can pass through the root, but it does not have to.
  • Count edges, not nodes.
  • An empty tree has diameter 0.

Example 1

        1
       / \
      2   3
     /
    4

One longest path is 4 → 2 → 1 → 3.

Diameter: 3 edges

There are two approaches:

  1. Brute force: Recalculate subtree heights at each node.
  2. Optimized: Calculate each subtree height once and update the diameter during postorder traversal.

2. Brute Force Approach

At every node, calculate the height of its left and right subtrees. Their sum gives the length in edges of the path passing through that node. Then compare it with the best diameter inside either subtree.

  1. Find the height of the left subtree.
  2. Find the height of the right subtree.
  3. Calculate leftHeight + rightHeight.
  4. Repeat for every node and keep the maximum.

In this implementation, height() counts nodes and returns 0 for a null node. A leaf therefore has height 1; the sum of its child heights still counts the path through a node in edges.

Java code — brute force

/**
 * Brute-force approach: O(N^2) worst-case time.
 */
public class Solution {

    // Returns the subtree height measured in nodes.
    private int height(TreeNode node) {
        if (node == null) {
            return 0;
        }

        return 1 + Math.max(height(node.left), height(node.right));
    }

    // Calculates the diameter independently at each node.
    private int diameter(TreeNode node) {
        if (node == null) {
            return 0;
        }

        int leftHeight = height(node.left);
        int rightHeight = height(node.right);

        // The child heights count the edges on each side of this node.
        int throughNode = leftHeight + rightHeight;

        // Also consider paths contained entirely in either subtree.
        int leftDiameter = diameter(node.left);
        int rightDiameter = diameter(node.right);

        return Math.max(throughNode,
               Math.max(leftDiameter, rightDiameter));
    }

    public int solve(TreeNode A) {
        return diameter(A);
    }
}

Why is brute force inefficient?

The height() method revisits nodes that earlier height calculations already visited. For a skewed tree, this repeated work can take O(N^2) time. We can avoid it by calculating height and diameter together in one traversal.

3. Optimized Approach — Postorder DFS

At each node, calculate the left and right subtree heights once, then use their sum to update the maximum diameter.

\[\text{diameter through node}=\text{left height}+\text{right height}\]

The helper returns subtree height in nodes (with null height 0). These child heights represent the numbers of edges extending from the current node down each branch, so their sum is the number of edges on the path through it.

Algorithm

  1. Initialize maxDiameter = 0.
  2. Recursively calculate the left subtree height.
  3. Recursively calculate the right subtree height.
  4. Update maxDiameter with leftHeight + rightHeight.
  5. Return 1 + max(leftHeight, rightHeight) as the current subtree height.
  6. Return maxDiameter from solve().

This is postorder traversal because both children are processed before the current node.

Optimized Java solution

This solution uses the class name and method signature Solution.solve(TreeNode A).

/**
 * Definition for binary tree:
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {

    // Stores the maximum diameter found anywhere in the tree.
    private int maxDiameter;

    // Returns the height of a subtree, measured in nodes.
    private int height(TreeNode node) {

        // An empty subtree has height 0.
        if (node == null) {
            return 0;
        }

        // Calculate child heights before processing this node.
        int leftHeight = height(node.left);
        int rightHeight = height(node.right);

        // The path through this node contains this many edges.
        int diameterThroughNode = leftHeight + rightHeight;

        // Keep the largest diameter found so far.
        maxDiameter = Math.max(maxDiameter, diameterThroughNode);

        // Return the height needed by the parent node.
        return 1 + Math.max(leftHeight, rightHeight);
    }

    public int solve(TreeNode A) {
        maxDiameter = 0;

        height(A);

        return maxDiameter;
    }
}

How the important variables work

  • leftHeight: height of the left subtree.
  • rightHeight: height of the right subtree.
  • diameterThroughNode: longest path that passes through the current node.
  • maxDiameter: maximum path length found anywhere in the tree.
  • 1 + Math.max(...): height of the current subtree, including the current node.
Important distinction: Return the height to the parent, but update the diameter separately. The diameter might lie entirely inside a subtree and never pass through the root.

  1. Node 4: Both children are null. Its height is 1 + max(0, 0) = 1, and its diameter through the node is 0.
  2. Node 5: Similarly, its height is 1, and its diameter through the node is 0.
  3. Node 2: Both child heights are 1. Its diameter is 1 + 1 = 2 edges along 4 → 2 → 5.
  4. Node 3: It is a leaf, so its height is 1.
  5. Node 1: Its left subtree height is 2 and right subtree height is 1. Its diameter through the node is 2 + 1 = 3.
Final result: 3 edges — longest path: 4 → 2 → 1 → 3.

5. Complexity Analysis

Let N be the number of nodes and H the height of the tree.

Time and auxiliary space complexity by approach
Approach Time complexity Auxiliary space
Brute force\(O(N^2)\) worst case\(O(H)\), worst case \(O(N)\)
Optimized DFS\(O(N)\)\(O(H)\), worst case \(O(N)\)
  • Brute force can calculate height in \(O(N)\) per node, resulting in \(O(N^2)\) time on a skewed tree.
  • The optimized solution visits each node once, so it takes \(O(N)\) time.
  • Recursive calls use \(O(H)\) stack space: \(O(\log N)\) for a balanced tree and \(O(N)\) for a skewed tree.
  • The optimized solution therefore uses \(O(N)\) worst-case auxiliary stack space. The returned integer uses \(O(1)\) additional space.

6. Edge Cases

Case Expected diameter Why

The solution handles these cases because maxDiameter starts at zero, null subtrees return height zero, and the diameter is updated at every node.

8. Interview Preparation Notes

Pattern to remember: Tree DFS + postorder traversal + global maximum.

Common mistakes

  • Counting nodes instead of edges. A path with k nodes has k - 1 edges.
  • Assuming the diameter must pass through the root.
  • Recalculating subtree heights repeatedly instead of computing them once.
  • Returning the diameter from the recursive helper when the parent actually needs the subtree height.

Likely interviewer follow-ups

Q1. Why do we use a global variable?

It preserves the best diameter found across all nodes, including paths that do not pass through the root.

Q2. Can the diameter pass through a leaf?

Yes, but a leaf contributes zero to the diameter through itself because it has no child branches.

Q3. Can we solve this iteratively?

Yes. A postorder traversal using an explicit stack can avoid recursive stack overflow on highly skewed trees.

Q4. What if the problem asks for the number of nodes on the longest path?

The answer is the diameter in edges plus one, because a path with d edges contains d + 1 nodes.

9. Final Recommendation

Implement the optimized postorder DFS solution in interviews.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(H)\), worst case \(O(N)\)
  • Core intuition: At every node, combine the left and right subtree heights to calculate the longest path through that node, and keep track of the maximum across the tree.

Remember this distinction: return height, update diameter. That is the central idea behind the solution.
