Java Algorithm Guide

Generate All Parentheses II

A complete guide to generating every well-formed parentheses combination with brute force and optimized backtracking in Java.

Recommended pattern: Add ( while opening parentheses remain, and add ) only when an opening parenthesis is available to match.

1. Problem Understanding

You are given an integer A, representing the number of pairs of parentheses. Generate all possible combinations of well-formed parentheses and return them as a sorted String[].

A well-formed parentheses string follows two rules:

  • Every opening parenthesis ( must have a matching closing parenthesis ).
  • At no point can the number of closing parentheses exceed the number of opening parentheses.

For example, if A = 3, every valid string must contain exactly 3 opening and 3 closing parentheses, making its length 6.

Examples

Example 1

Input: A = 3

["((()))", "(()())", "(())()", "()(())", "()()()"]

Example 2

Input: A = 1

["()"]

Constraints

  • 1 <= A <= 10
  • The output must contain every valid combination.
  • The output must be sorted lexicographically.

2. Brute-Force Approach

The simplest approach is to generate every possible string of length 2 * A using ( and ), then check which strings are valid.

Steps

  1. Generate all strings of length 2 * A.
  2. Check each string by maintaining a balance counter.
  3. Increase the balance for ( and decrease it for ).
  4. If the balance ever becomes negative, the string is invalid.
  5. If the final balance is zero, the string is valid.
  6. Sort the valid strings and return them.

Brute-force Java code

import java.util.*;

public class Solution {

    public String[] generateParenthesis(int A) {
        List<String> all = new ArrayList<>();
        List<String> valid = new ArrayList<>();

        // Generate every possible string of length 2 * A.
        generateAll("", 2 * A, all);

        // Keep only well-formed strings.
        for (String s : all) {
            if (isValid(s)) {
                valid.add(s);
            }
        }

        // Sort the valid combinations.
        Collections.sort(valid);

        return valid.toArray(new String[0]);
    }

    private void generateAll(String current, int length,
                             List<String> all) {
        if (current.length() == length) {
            all.add(current);
            return;
        }

        generateAll(current + "(", length, all);
        generateAll(current + ")", length, all);
    }

    private boolean isValid(String s) {
        int balance = 0;

        for (char ch : s.toCharArray()) {
            if (ch == '(') {
                balance++;
            } else {
                balance--;
            }

            // A closing parenthesis cannot be unmatched.
            if (balance < 0) {
                return false;
            }
        }

        return balance == 0;
    }
}

Why is brute force inefficient?

There are \(2^{2A} = 4^A\) possible strings. Most of them are invalid, so we spend time generating and checking combinations that can never be answers.

Complexity analysis

Time

\(O(A \cdot 4^A)\), plus sorting the valid results.

Auxiliary space

\(O(A)\) for recursion, excluding stored strings.

Intermediate space

\(O(A \cdot 4^A)\) for storing all possible strings.

Limitation: This solution is straightforward but inefficient for larger values of A, because it generates and checks strings that cannot be answers.

3. Optimized Approach — Backtracking

Instead of generating every possible string and checking it afterward, build only strings that can become valid parentheses combinations. This technique is called backtracking with pruning.

Intuition

Maintain three important things:

  • open: Number of opening parentheses added so far.
  • close: Number of closing parentheses added so far.
  • current: The string being built.

Follow two rules:

Rule 1: Add an opening parenthesis

If open < A, add ( because not all available opening parentheses have been used.

Rule 2: Add a closing parenthesis

If close < open, add ) because there is an unmatched opening parenthesis available to close.

When open == A and close == A, we have constructed a complete valid string, so add it to the result.

Optimized Java code

This uses the implementation with String current and current + "(" / current + ")".

import java.util.*;

public class Solution {

    public String[] generateParenthesis(int A) {
        List<String> result = new ArrayList<>();

        // Start with no opening or closing parentheses.
        backtrack(A, 0, 0, "", result);

        // Convert the list to the required String[] output.
        return result.toArray(new String[0]);
    }

    private void backtrack(int A, int open, int close,
                           String current, List<String> result) {

        // Both opening and closing parentheses are complete.
        if (open == A && close == A) {
            result.add(current);
            return;
        }

        // Option 1: Add '(' if opening parentheses remain.
        if (open < A) {
            backtrack(A, open + 1, close, current + "(", result);
        }

        // Option 2: Add ')' only if an opening parenthesis
        // is available to be matched.
        if (close < open) {
            backtrack(A, open, close + 1, current + ")", result);
        }
    }
}

Explanation of the important code

  1. Starting the recursion 
    backtrack(A, 0, 0, "", result);

    Initially, we have no opening parentheses, no closing parentheses, and an empty string.

  2. Base condition 
    if (open == A && close == A) {
    result.add(current);
    return;
}

    Once both counts equal A, the current string is complete and valid. Save it and stop exploring that path.

  3. Adding ( 
    if (open < A) {
    backtrack(A, open + 1, close, current + "(", result);
}

    Add an opening parenthesis only if some remain. The recursive call receives an updated count and a new string.

  4. Adding ) 
    if (close < open) {
    backtrack(A, open, close + 1, current + ")", result);
}

    Add a closing parenthesis only when the number of closing parentheses is less than the number of opening parentheses. This prevents invalid strings from being generated.

  5. Returning the result 
    return result.toArray(new String[0]);

    The problem requires String[], so convert the List<String> into a string array.

Why don't we need sorting? We always try ( before ). This explores combinations in lexicographical order, so the output is already sorted.

Understanding backtracking in your code

Your code uses immutable String objects:

current + "("

This creates a new string for the recursive call. The original current remains unchanged, so you do not need to remove the last character manually when returning from recursion.

For example, from "(", the algorithm explores "((" and later explores "()". The original "(" is preserved.

5. Complexity Analysis

The number of valid parentheses combinations is given by the Catalan number:

\[C_A = \frac{1}{A+1}\binom{2A}{A}\]

For example, when A = 3, there are 5 valid combinations. When A = 10, there are 16,796.

Complexity comparison of brute force and backtracking
Approach Time complexity Auxiliary space Output space
Brute force \(O(A \cdot 4^A)\), excluding sorting \(O(A)\) \(O(A \cdot 4^A)\) for all generated strings
Backtracking \(O(A \cdot C_A)\) \(O(A^2)\) for recursive strings in this implementation \(O(A \cdot C_A)\)

Why does your implementation use \(O(A^2)\) auxiliary space?

The recursion can reach a depth of 2A. At each level, current + "(" or current + ")" creates a new string, and the parent call retains its own string while the recursive call executes. The combined string storage along the active recursion path can therefore reach \(O(A^2)\).

If we instead use a mutable StringBuilder and undo each character after a recursive call, the auxiliary space can be reduced to \(O(A)\), excluding the output.

The optimized algorithm is output-sensitive: it generates only valid combinations, and producing all \(C_A\) strings of length \(2A\) already requires \(O(A \cdot C_A)\) time.

8. Interview Preparation Notes

Key concept to remember

Backtracking = choose, explore, and return.

For this problem, remember the two conditions:

if (open < A) {
    // Add '('
}

if (close < open) {
    // Add ')'
}

These conditions ensure we explore only valid paths.

Common mistakes

  • Using close < A instead of close < open when adding ).
  • Forgetting to check the base condition when both counts reach A.
  • Generating every possible string and filtering invalid ones.
  • Thinking the original current changes after a recursive call. Since String is immutable, it does not.
  • Sorting unnecessarily when opening parentheses are explored before closing parentheses.

Likely interviewer follow-up questions

Q1. Why is this a backtracking problem?

Because we explore different choices at each step and recursively build every valid combination.

Q2. Why do we use close < open?

To ensure every closing parenthesis has an opening parenthesis available to match.

Q3. Why is the output already sorted?

Because we explore ( before ) and follow the same ordering recursively.

Q4. Can we reduce auxiliary space?

Yes. A mutable StringBuilder with append-and-undo operations avoids retaining a separate string at every recursive level.
