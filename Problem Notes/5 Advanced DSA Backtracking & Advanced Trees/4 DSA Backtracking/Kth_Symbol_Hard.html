K-th Symbol

We can solve the K-th Symbol problem using recursive parent traversal, then recognize why bit manipulation gives a faster solution. The recursive approach is sometimes called backtracking here, but it does not explore alternative choices.

The examples use the required method signature:

public int solve(int A, long B)

1. Problem Understanding

Row 1 contains only 0. For each subsequent row, replace every symbol as follows:

  • 0 becomes 01.
  • 1 becomes 10.

Return the symbol at zero-based index B in row A.

The first four rows of the generated symbol sequence
RowSequence
10
201
30110
401101001

Example 1

Input: A = 3, B = 0

Row 3 is 0110. The symbol at index 0 is 0.

Output: 0

Example 2

Input: A = 4, B = 4

Row 4 is 01101001. The symbol at index 4 is 1.

Output: 1

Important constraints

  • \(1 \le A \le 10^5\)
  • \(0 \le B \le \min(2^{A-1}-1, 10^{18})\)

Since B can be as large as \(10^{18}\), generating the entire row is not practical. We need an approach that works without constructing the sequence.

2. Brute Force Approach

Idea

Generate each row until reaching row A. For every symbol in the previous row, append 01 if it is 0, or 10 if it is 1. Then return the symbol at index B.

Java code — Brute Force

public class Solution {
    public int solve(int A, long B) {
        String row = "0";

        // Build each row until the requested row is reached.
        for (int i = 2; i <= A; i++) {
            StringBuilder nextRow = new StringBuilder();

            for (int j = 0; j < row.length(); j++) {
                char symbol = row.charAt(j);

                // Apply the replacement rule for the current symbol.
                if (symbol == '0') {
                    nextRow.append("01");
                } else {
                    nextRow.append("10");
                }
            }

            row = nextRow.toString();
        }

        // Convert the requested character from '0' or '1' to an integer.
        return row.charAt((int) B) - '0';
    }
}

Dry run

Index 2 contains 1, so the answer is 1.

Complexity

  • Time: \(O(2^A)\), due to generating exponentially growing rows.
  • Auxiliary space: \(O(2^A)\), to store the generated rows.

This approach is unsuitable for the given constraints.

3. Backtracking Approach

First, understand the idea

Backtracking commonly means exploring choices, undoing a choice, and exploring another possibility. This problem has no choices to explore, so the more accurate description is recursive parent traversal. We can move backward to the parent symbol, then determine the current symbol while returning from recursion.

Key observation

Every symbol in a row comes from a symbol in the previous row. The parent and children are:

Parent symbols and their children at even and odd indexes
Parent symbolChild at even indexChild at odd index
001
110
  • The parent index for B is B / 2.
  • If B is even, the current symbol equals its parent's symbol.
  • If B is odd, the current symbol is the opposite of its parent's symbol.

Step-by-step algorithm

  1. If we reach row 1, return 0, because the first row contains only 0.
  2. Find the parent index using B / 2.
  3. Recursively find the parent's symbol in row A - 1.
  4. If B is even, return the parent's symbol.
  5. If B is odd, flip the parent's symbol using 1 - parent.

Java code — Recursive parent traversal

public class Solution {
    public int solve(int A, long B) {
        // Begin tracing the requested symbol back to row 1.
        return backtrack(A, B);
    }

    private int backtrack(int row, long index) {
        // The first row contains only symbol 0.
        if (row == 1) {
            return 0;
        }

        // Find the parent's symbol in the previous row.
        int parent = backtrack(row - 1, index / 2);

        // Even indexes preserve the parent symbol.
        if (index % 2 == 0) {
            return parent;
        }

        // Odd indexes contain the opposite of the parent symbol.
        return 1 - parent;
    }
}

Important constraint warning

This recursive solution has a call-stack depth of up to A. Since A can reach \(10^5\), it may cause a StackOverflowError in Java. Use it to understand the recursion, but prefer the iterative or bit-manipulation solution for the actual constraints.

Complexity analysis

  • Time: \(O(A)\), because each recursive call moves back one row.
  • Auxiliary space: \(O(A)\), because the recursive call stack can grow to depth \(A\).

This is much better than generating the rows, but the recursion depth makes it risky for the maximum constraint.

4. Optimized Approach — Bit Manipulation

We can eliminate recursion by recognizing a mathematical pattern.

Key observation

Every time we move from a symbol to its parent, the symbol flips if the current index is odd. Repeatedly dividing B by 2 reveals its bits. Each set bit (1) corresponds to one flip.

\[\boxed{\text{Answer}=\operatorname{popcount}(B)\bmod 2}\]

Here, popcount(B) means the number of 1 bits in the binary representation of B.

  • An even number of set bits gives 0.
  • An odd number of set bits gives 1.

Example

Suppose B = 5. Its binary representation is 101.

  • Number of set bits = 2.
  • 2 % 2 = 0, so the answer is 0.

Java code — Optimized solution

public class Solution {
    public int solve(int A, long B) {
        // Count the 1 bits in the binary representation of B.
        int setBits = Long.bitCount(B);

        // The symbol is 1 for an odd number of flips, otherwise 0.
        return setBits % 2;
    }
}

Java's Long.bitCount() counts the set bits in a long and safely handles B values up to \(10^{18}\).

The row number A is not needed in the calculation because the symbol is determined by index B. The problem guarantees that B is valid for row A.

9. Interview Preparation Notes

Key concepts

  • Recursion: solve a smaller version of the same problem.
  • Parent traversal: move from index B to index B / 2.
  • Bit manipulation: each set bit represents a symbol flip.
  • Parity: only whether the number of flips is odd or even matters.

Common mistakes

  1. Generating the entire row despite its exponential size.
  2. Using int for B instead of long.
  3. Confusing the one-based row number with the zero-based symbol index.
  4. Using deep recursion when the constraints permit up to \(10^5\) levels.
  5. Forgetting to take the set-bit count modulo 2.

Likely interviewer follow-ups

Q1. Can we use recursion?

Yes. Find the parent's symbol at index B / 2, then flip it if B is odd. However, deep recursion can overflow the Java stack.

Q2. Why does the number of set bits matter?

Every set bit represents an odd-index step, which flips the symbol. The final value depends on whether the total number of flips is odd or even.

Q3. Can we solve it iteratively without Long.bitCount()?

Yes. Repeatedly check B & 1, toggle a result when the bit is 1, and shift B right until it becomes zero. This takes \(O(\log B)\) time and \(O(1)\) space.

public class Solution {
    public int solve(int A, long B) {
        int result = 0;

        // Process each bit; a set bit means one symbol flip.
        while (B > 0) {
            if ((B & 1) == 1) {
                result ^= 1;
            }
            B >>= 1;
        }

        // Return the parity of the total number of flips.
        return result;
    }
}

Q4. Is this a classic backtracking problem?

Not exactly. Classic backtracking explores alternative choices and reverses state changes. Here, there are no alternatives to explore, so recursive parent traversal and bit manipulation are more accurate descriptions.

10. Final Recommendation

For learning, understand the three approaches in this order:

  1. Brute force: understand how the rows are generated.
  2. Recursive parent traversal: understand why even indices preserve the parent's symbol and odd indices flip it.
  3. Bit manipulation: recognize that the number of flips equals the number of set bits.

For an interview, implement the optimized solution:

public class Solution {
    public int solve(int A, long B) {
        // The symbol is the parity of the set-bit count in B.
        return Long.bitCount(B) % 2;
    }
}
  • Time complexity: \(O(1)\)
  • Auxiliary space: \(O(1)\)

Remember: Each 1 bit in B represents a flip. An odd number of flips gives 1; an even number gives 0.
