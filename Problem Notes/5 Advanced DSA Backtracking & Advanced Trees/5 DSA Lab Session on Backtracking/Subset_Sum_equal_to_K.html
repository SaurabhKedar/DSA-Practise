Subset Sum Equal to K

Java — recursion and Meet in the Middle

Given an integer array and a target, determine whether any subset sums to the target. This guide covers an include-or-exclude recursive search and a faster Meet in the Middle approach.

1. Problem Understanding

You are given an integer array A and a target sum B. Check whether any subset of the array has a sum equal to B.

  • For each element, choose to include it or exclude it.
  • A subset does not need to contain consecutive elements.
  • Negative numbers and zero are allowed.
  • Each element can be used at most once.
  • The empty subset is valid and has a sum of \(0\).

Return 1 if such a subset exists; otherwise, return 0.

Example 1

A = [3, 34, -3, 12, 5, 2], B = 9

One valid subset is [-3, 12].

\[-3 + 12 = 9\]

Therefore, the output is 1.

Example 2

A = [-8, 34, 4, 0, -5, -2], B = -20

Even the sum of all negative elements is:

\[-8 + (-5) + (-2) = -15\]

The other elements cannot reduce the sum below \(-15\), so reaching \(-20\) is impossible. The output is 0.

Constraint

\(N \leq 17\). This is small enough for an exhaustive search over all subsets.

2. Brute Force Approach — Recursion

Intuition

For every element, there are exactly two choices: include it in the subset or exclude it. Explore both possibilities until every element has been processed. At the end, if the selected elements sum to B, return true.

  1. Consider the current element.
  2. Recursively explore the branch that includes it.
  3. Recursively explore the branch that excludes it if needed.
  4. When all elements have been processed, compare the running sum with the target.

Java code

public class Solution {

    public int SubsetSum(int[] A, int B) {
        return solve(A, 0, 0, B) ? 1 : 0;
    }

    private boolean solve(int[] A, int index, long sum, int target) {

        // All elements have been processed; check whether this subset hits the target.
        if (index == A.length) {
            return sum == target;
        }

        // Choice 1: include the current element.
        if (solve(A, index + 1, sum + A[index], target)) {
            return true;
        }

        // Choice 2: exclude the current element.
        return solve(A, index + 1, sum, target);
    }
}

The running sum uses long to reduce the risk of integer overflow when adding several values.

Dry run

For A = [3, -3, 12], B = 9, one unsuccessful path is:

StepDecisionRunning sum
1Include 33
2Exclude -33
3Include 1215

Another path succeeds:

StepDecisionRunning sum
1Exclude 30
2Include -3-3
3Include 129

We reach the target, so recursion returns true, and the method returns 1.

Complexity

  • Time: \(O(2^N)\), because each element has two choices.
  • Auxiliary space: \(O(N)\), due to the recursion stack.

There are at most \(2^{17} = 131072\) subsets, which is manageable under the given constraints.

3. Optimized Approach — Meet in the Middle

The brute-force approach explores up to \(2^N\) subsets. We can reduce the number of combinations by splitting the array into two halves. This technique is called Meet in the Middle.

Intuition

Consider A = [3, 34, -3, 12, 5, 2] with target B = 9. Split the array into:

  • Left: [3, 34, -3]
  • Right: [12, 5, 2]

If a subset of the left half has sum leftSum, the right half must contain a subset with sum:

\[\text{rightSum} = B - \text{leftSum}\]

For example, the left half can produce \(-3\). We need a right-half sum of \(9 - (-3) = 12\). The right half contains [12], so a valid subset is [-3, 12].

Instead of exploring all combinations together, calculate possible sums for each half and look for matching pairs.

Algorithm

  1. Divide the array into two halves.
  2. Generate every possible subset sum of the left half and store them in a HashSet.
  3. Generate every possible subset sum of the right half.
  4. For each right-half sum sum, check whether B - sum exists in the left-half set.
  5. If a match exists, return 1. Otherwise, return 0.

Java solution

import java.util.HashSet;
import java.util.Set;

public class Solution {

    public int SubsetSum(int[] A, int B) {
        int mid = A.length / 2;

        // Store every possible subset sum of the left half.
        Set<Long> leftSums = new HashSet<>();
        generateSums(A, 0, mid, 0L, leftSums);

        // Generate every possible subset sum of the right half.
        Set<Long> rightSums = new HashSet<>();
        generateSums(A, mid, A.length, 0L, rightSums);

        // Look for a left sum and right sum that add up to the target.
        for (long rightSum : rightSums) {
            long required = (long) B - rightSum;

            if (leftSums.contains(required)) {
                return 1;
            }
        }

        return 0;
    }

    private void generateSums(
            int[] A,
            int start,
            int end,
            long sum,
            Set<Long> sums) {

        // Every element in this half has been considered.
        if (start == end) {
            sums.add(sum);
            return;
        }

        // Choice 1: exclude the current element.
        generateSums(A, start + 1, end, sum, sums);

        // Choice 2: include the current element.
        generateSums(
            A, start + 1, end, sum + A[start], sums
        );
    }
}

4. Dry Run of the Optimized Solution

For A = [3, 34, -3, 12, 5, 2], B = 9:

The left half is [3, 34, -3]. Its possible subset sums are:

\[\{0, 3, 34, -3, 37, 0, 31, 34\}\]

The right half is [12, 5, 2]. Its possible subset sums include 0, 12, 5, 2, 17, 14, 7, and 19.

Now check the right-half sums:

Right sumRequired left sum (9 - right)Found in left set?
09No
12-3Yes
54No
27No

As soon as the algorithm checks right sum 12, it finds -3 in the left set.

\[12 + (-3) = 9\]

The algorithm returns 1.

Note: A HashSet stores unique sums, so repeated sums such as 0 only appear once. This does not affect correctness because we only need to know whether a matching sum exists.

5. Complexity Analysis

Let \(N\) be the array length.

ApproachTime complexityAuxiliary space
Brute-force recursion\(O(2^N)\)\(O(N)\)
Meet in the Middle\(O(2^{N/2})\) expected\(O(2^{N/2})\)

For Meet in the Middle, each half has approximately \(N/2\) elements, so each generates at most \(2^{N/2}\) subset sums. Hash-set lookups take expected \(O(1)\) time.

For the maximum constraint \(N = 17\):

  • Brute force: at most \(131,072\) subset combinations.
  • Meet in the Middle: each half has at most \(512\) combinations.

Both approaches are practical here. Meet in the Middle is asymptotically faster, while brute force is simpler and uses less extra memory.

8. Interview Preparation Notes

Key concepts to remember

  • Include/exclude recursion: Every element has two choices.
  • Subset sums: The order of selected elements does not matter.
  • Meet in the Middle: Split a large search space into two smaller ones.
  • Negative numbers: They prevent many sum-based pruning optimizations.
  • Empty subset: The target 0 is always achievable, even if no elements are selected.

Common mistakes

  1. Using a greedy approach, such as always choosing the largest or smallest element.
  2. Assuming all numbers are positive.
  3. Using int for intermediate sums when long is safer.
  4. Forgetting that each array element can only be selected once.
  5. Treating an empty subset as invalid when the target is zero.

Likely interviewer follow-up questions

Q1. Why not use ordinary dynamic programming with an array indexed by sum?

Because the values can range from \(-10^9\) to \(10^9\). A DP array indexed by possible sums would be impractical. Meet in the Middle depends on the number of elements rather than the numerical range of the values.

Q2. What if the array contains only positive numbers?

You can use classic subset-sum dynamic programming when the target and sum range are small enough. For a small \(N\), recursion or Meet in the Middle can still be appropriate.

Q3. Can recursion be optimized using memoization?

Yes, if many states repeat. However, the state includes both the current index and the current sum, and the sum range here is huge. Meet in the Middle gives a more predictable improvement for these constraints.

Q4. What happens when B = 0?

The answer is always 1 because the problem explicitly permits the empty subset. Both implementations correctly handle this case.

9. Final Recommendation

For this exact problem, both implementations are efficient enough because \(N \leq 17\).

  • For the simplest interview solution: use include/exclude recursion — \(O(2^N)\) time and \(O(N)\) auxiliary space.
  • For the optimized solution: use Meet in the Middle — expected \(O(2^{N/2})\) time and \(O(2^{N/2})\) auxiliary space.
Memorable intuition: Every element is either selected or skipped. When the array is small enough to split into halves, calculate their subset sums separately and find two sums that add up to the target.
