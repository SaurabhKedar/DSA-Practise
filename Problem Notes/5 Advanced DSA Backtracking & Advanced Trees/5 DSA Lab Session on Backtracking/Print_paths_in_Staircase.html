Java Algorithm Guide

Print Paths in Staircase

Generate every distinct sequence of one-step and two-step moves that reaches the top, in lexicographical order.

Recommended pattern: Use backtracking: choose a step, explore the remaining staircase, and undo the choice.

1. Problem Understanding

You are given an integer A, the total number of staircase steps. At each move, you can climb either one step or two steps. Return all distinct sequences of moves that add up to A.

For A = 3, the valid paths are:

  • [1, 1, 1], because 1 + 1 + 1 = 3
  • [1, 2], because 1 + 2 = 3
  • [2, 1], because 2 + 1 = 3

The output is:

[[1, 1, 1], [1, 2], [2, 1]]

Important conditions

  • Every path must sum exactly to A.
  • Each move must be either 1 or 2.
  • Different move orders are distinct paths; for example, [1, 2] and [2, 1].
  • Return paths in lexicographical order. Exploring 1 before 2 naturally produces this order.
  • Constraint: 2 <= A <= 25.

2. Brute Force Approach

Generate possible sequences of 1s and 2s, tracking their current sum. Save a sequence when its sum equals A, and stop exploring when the sum exceeds A.

Algorithm

  1. Generate sequences by choosing 1 or 2 at each position.
  2. Track the sum of the chosen steps.
  3. If the sum equals A, store a copy of the sequence.
  4. If the sum exceeds A, stop exploring that sequence.
  5. Explore 1 before 2 to preserve lexicographical order.

Java code

import java.util.*;

public class Solution {

    public ArrayList<ArrayList<Integer>> WaysToClimb(int A) {
        ArrayList<ArrayList<Integer>> result = new ArrayList<>();
        generate(A, 0, new ArrayList<>(), result);
        return result;
    }

    private void generate(
            int A,
            int sum,
            ArrayList<Integer> path,
            ArrayList<ArrayList<Integer>> result) {

        // A complete valid path has been found.
        if (sum == A) {
            result.add(new ArrayList<>(path));
            return;
        }

        // This sequence cannot lead to a valid answer.
        if (sum > A) {
            return;
        }

        // Try climbing 1 step.
        path.add(1);
        generate(A, sum + 1, path, result);
        path.remove(path.size() - 1); // Undo the choice.

        // Try climbing 2 steps.
        path.add(2);
        generate(A, sum + 2, path, result);
        path.remove(path.size() - 1); // Undo the choice.
    }
}

Why does it work?

It explores every possible choice of 1 and 2. A path is stored only when its sum is exactly A, so every stored path is valid. Since both choices are explored, no valid path is missed. The approach can still explore sequences that overshoot; tracking the remaining steps avoids that unnecessary exploration.

3. Optimized Approach — Backtracking with Remaining Steps

Instead of tracking the current sum, maintain remaining, the number of staircase steps still left to climb. A move is only considered when enough steps remain.

Intuition

Suppose A = 3:

  • Choose 1: remaining steps become 2.
  • Choose another 1: remaining steps become 1.
  • Choose another 1: remaining steps become 0. Store [1, 1, 1].
  • Backtrack and try 2 at the appropriate positions to generate [1, 2] and [2, 1].

Backtracking means making a choice, exploring it, then undoing the choice so another possibility can be explored.

Algorithm

  1. Start with remaining = A and an empty path.
  2. If remaining == 0, copy the current path into the result.
  3. If remaining >= 1, choose 1, recurse, and remove that choice.
  4. If remaining >= 2, choose 2, recurse, and remove that choice.
  5. Return all generated paths.

Complete Java solution

This preserves the exact method signature required by the platform.

import java.util.*;

public class Solution {

    public ArrayList<ArrayList<Integer>> WaysToClimb(int A) {
        ArrayList<ArrayList<Integer>> result = new ArrayList<>();

        // Stores the current sequence of steps.
        ArrayList<Integer> path = new ArrayList<>();

        // Generate every valid path from A remaining steps.
        backtrack(A, path, result);

        return result;
    }

    private void backtrack(
            int remaining,
            ArrayList<Integer> path,
            ArrayList<ArrayList<Integer>> result) {

        // No steps remain, so we have found a valid path.
        if (remaining == 0) {
            // Store a copy because path will change during backtracking.
            result.add(new ArrayList<>(path));
            return;
        }

        // Option 1: Climb one step.
        if (remaining >= 1) {
            path.add(1);
            backtrack(remaining - 1, path, result);

            // Undo the choice to explore other paths.
            path.remove(path.size() - 1);
        }

        // Option 2: Climb two steps.
        if (remaining >= 2) {
            path.add(2);
            backtrack(remaining - 2, path, result);

            // Undo the choice to explore other paths.
            path.remove(path.size() - 1);
        }
    }
}

Step-by-step dry run for A = 3

WaysToClimb(3) initializes result = [] and path = [], then calls backtrack(3, path, result). The recursion uses depth-first search: it explores a choice fully, removes it, and then tries the next choice.

  1. Start: remaining = 3, path = []. Since remaining is not zero, try the one-step option.
  2. Choose 1: Add 1, giving path = [1], then call backtrack(2, path, result).
  3. Choose 1 again: At remaining = 2, add 1, giving path = [1, 1], then call backtrack(1, path, result).
  4. Choose 1 a third time: At remaining = 1, add 1, giving path = [1, 1, 1], then call backtrack(0, path, result). Since remaining == 0, save a copy of the path: result = [[1, 1, 1]].
  5. Backtrack: Remove the last element to restore path = [1, 1]. The two-step option is skipped because remaining = 1, which is less than 2. Return and remove the previous choice, restoring path = [1].
  6. Try 2 from remaining = 2: Add 2, giving path = [1, 2], then call backtrack(0, path, result). Save the path: result = [[1, 1, 1], [1, 2]]. Return and remove 2, restoring path = [1].
  7. Return to the start: Remove the first 1, restoring path = [], then choose 2. The path becomes [2], and the recursive call has remaining = 1.
  8. Complete the final path: Choose 1, giving path = [2, 1] and remaining = 0. Save it: result = [[1, 1, 1], [1, 2], [2, 1]]. Backtracking removes the 1, skips the two-step option at remaining = 1, then removes the 2, restoring path = [].
Final output: 
[
    [1, 1, 1],
    [1, 2],
    [2, 1]
]

Why is this approach optimized?

It never explores a path that overshoots the staircase and avoids maintaining a separate running sum. Both approaches have exponential growth because the problem requires generating every valid path. The optimization reduces unnecessary exploration and makes the recursion easier to reason about.

5. Complexity Analysis

Let \(K\) be the number of valid paths returned. The number of valid paths follows the Fibonacci recurrence:

\[ K(A)=K(A-1)+K(A-2), \qquad K(0)=1,\quad K(1)=1 \]

Therefore, \(K(A)\) grows exponentially, approximately as \(\phi^A\), where \(\phi \approx 1.618\).

Approach Time complexity Auxiliary space
Brute force\(O(2^A)\)\(O(A)\)
Optimized backtracking\(O(2^A + KA)\)\(O(A)\)
  • Time: The optimized approach visits a recursion tree with exponentially many nodes in the worst-case bound. Copying each valid path costs up to \(O(A)\), giving \(O(2^A + KA)\).
  • Auxiliary space: The recursion stack and current path each require at most \(O(A)\).
  • Output space: The result requires \(O(KA)\) space in the worst case because there are \(K\) paths, each containing at most \(A\) integers.

The brute-force and optimized approaches share the same worst-case exponential upper bound. The optimized version avoids exploring invalid overshooting paths.

8. Interview Preparation Notes

Key concept to remember

Backtracking = Choose → Explore → Undo.

  • Choose: Add 1 or 2 to path.
  • Explore: Recursively solve the remaining staircase.
  • Undo: Remove the last step so the next choice starts from the correct state.

Common mistakes

  1. Forgetting to undo a choice, leaving the current path with steps from previously explored branches.
  2. Saving the original list instead of using new ArrayList<>(path).
  3. Ignoring lexicographical order; explore 1 before 2.
  4. Returning only a count when the problem requires all paths.
  5. Sorting unnecessarily; recursive choices already generate the paths in the correct order.

Likely interviewer follow-up questions

Q1. Why do we need backtracking?
Because we must explore multiple possible sequences while reusing the same path list.
Q2. Why do we choose 1 before 2?
To generate the sequences in lexicographical order without sorting the final output.
Q3. Can dynamic programming solve this problem?
Dynamic programming can count the ways efficiently, but generating all paths still requires constructing each valid sequence. Backtracking is a natural fit for enumerating them.
Q4. Why is the problem exponential?
The number of valid paths grows exponentially with A, and the algorithm must return every path.

9. Final Recommendation

For an interview, implement the optimized backtracking solution using remaining, path, and result.

  • Time complexity: \(O(2^A + KA)\), where \(K\) is the number of valid paths.
  • Auxiliary space: \(O(A)\), excluding the output.
  • Output space: \(O(KA)\).
Remember the intuition: at every step, try 1, explore all resulting paths, undo it, then try 2. Save the path only when no steps remain.
