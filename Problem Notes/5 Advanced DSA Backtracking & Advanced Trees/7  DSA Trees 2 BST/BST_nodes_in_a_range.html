Java Algorithm Guide

BST Nodes in a Range

Count the nodes in a Binary Search Tree whose values fall within an inclusive range. Compare a straightforward traversal with a pruned traversal that uses the BST ordering property.

Key pattern: Too small means go right. Too large means go left. Inside the range means count the node and search both sides.

1. Problem Understanding

You are given the root of a Binary Search Tree (BST) and two integers, B and C. Count the nodes whose values are in the inclusive range [B, C].

A node is counted exactly when:

\[B \leq \text{node.val} \leq C\]

Remember the BST property:

  • All values in the left subtree are smaller than the current node.
  • All values in the right subtree are greater than the current node.

Example 1

Range: B = 12, C = 20

The values in the range are 12, 14, 15, 16, 20.

Output: 5

Example 2

BST values: 8, 6, 21, 1, 7

For the range 2 to 20, the values in range are 6, 7, 8.

Output: 3

The range includes both boundaries, so values equal to B or C must also be counted.

2. Brute Force Approach — Traverse Every Node

Intuition

Visit every node in the tree, regardless of its value. For each node, check whether its value lies between B and C. If it does, increment the count. A recursive traversal can visit every node.

Java code

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {

    public int solve(TreeNode A, int B, int C) {
        // An empty subtree contains no nodes.
        if (A == null) {
            return 0;
        }

        // Count the current node if it lies in the range.
        int count = 0;
        if (A.val >= B && A.val <= C) {
            count = 1;
        }

        // Count valid nodes in both subtrees.
        count += solve(A.left, B, C);
        count += solve(A.right, B, C);

        return count;
    }
}

Why does it work?

Every node is visited exactly once. For each node, we check the range condition and add 1 only if the condition is satisfied. Therefore, the final count is correct.

Complexity analysis

  • Time: \(O(N)\), because every node is visited.
  • Auxiliary space: \(O(H)\), due to recursive call stack space, where \(H\) is the tree height. In the worst case, this can be \(O(N)\).

Limitation: Even if a node's value is outside the range, we still visit both of its subtrees. This wastes work because a BST lets us skip certain subtrees.

3. Optimized Approach — Use BST Properties (Pruning)

Intuition

Since the tree is a BST, we do not need to visit every node:

  • If A.val < B, the current node and its entire left subtree are smaller than B. Ignore them and search only the right subtree.
  • If A.val > C, the current node and its entire right subtree are greater than C. Ignore them and search only the left subtree.
  • Otherwise, the current node is within the range. Count it and search both subtrees.

This technique is called BST pruning because we avoid traversing subtrees that cannot contain valid answers.

Algorithm step by step

  1. If the current node is null, return 0.
  2. If its value is smaller than B, recursively search the right subtree.
  3. If its value is greater than C, recursively search the left subtree.
  4. Otherwise, count the current node and add the counts from both subtrees.

Optimized Java code

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {

    public int solve(TreeNode A, int B, int C) {

        // Base case: no node means no valid value.
        if (A == null) {
            return 0;
        }

        int count = 0;

        // Current node is in range.
        if (A.val >= B && A.val <= C) {
            count++;
        }

        // Left subtree contains smaller values.
        if (A.val > B) {
            count += solve(A.left, B, C);
        }

        // Right subtree contains larger values.
        if (A.val < C) {
            count += solve(A.right, B, C);
        }

        return count;
    }
}

Important: Use < B and > C, not <= B or >= C, because the range is inclusive.

5. Complexity Analysis

Let \(N\) be the total number of nodes, \(H\) the height of the BST, and \(K\) the number of nodes visited by the optimized algorithm.

Approach Time complexity Auxiliary space
Brute force\(O(N)\)\(O(H)\)
Optimized pruning\(O(K)\), worst case \(O(N)\)\(O(H)\)

The optimized approach is often faster because it skips irrelevant subtrees. However, its worst-case time complexity is still \(O(N)\), for example when the range includes every node.

For a balanced BST, the height is \(O(\log N)\). The recursive stack uses \(O(H)\) space, so it is \(O(\log N)\) for a balanced tree and \(O(N)\) for a highly skewed tree.

8. Interview Preparation Notes

Key concept to remember

BST pruning: If the current node is smaller than the lower boundary, go right. If it is greater than the upper boundary, go left. Otherwise, count it and explore both sides.

Common mistakes

  • Excluding the boundary values by using the wrong comparison operators.
  • Traversing both subtrees even when one can be eliminated.
  • Forgetting the null base case.
  • Claiming the optimized solution always runs in \(O(\log N)\). That is not guaranteed for an arbitrary BST.

Likely interviewer follow-up questions

Q1. Why can we skip the left subtree when A.val < B?

Every value in the left subtree is less than A.val, so all those values are also less than B.

Q2. What if the range includes all nodes?

The algorithm may visit every node, so the worst-case time complexity remains \(O(N)\).

Q3. Can we solve this iteratively?

Yes. Use a stack to traverse the tree, pushing only the subtrees that could contain valid values. This avoids relying on the Java call stack.

Q4. Is this approach applicable to a normal binary tree?

Not directly. The pruning logic depends on the BST ordering property. Without that property, we generally need to examine every node.

9. Final Recommendation

For an interview, implement the optimized recursive solution because it is concise, easy to explain, and uses the BST property to avoid unnecessary traversal.

  • Time: \(O(N)\) worst case, often better due to pruning.
  • Auxiliary space: \(O(H)\) for the recursive call stack.
Memory trick: Too small → go right. Too large → go left. Inside range → count and explore both sides.
