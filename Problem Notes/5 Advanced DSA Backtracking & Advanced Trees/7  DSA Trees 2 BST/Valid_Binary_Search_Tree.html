Java Algorithm Guide

Valid Binary Search Tree (BST)

Determine whether a binary tree satisfies the Binary Search Tree ordering rules. This guide compares four approaches, from a straightforward subtree scan to efficient inorder and range-based validations.

Key property: A binary tree is a valid BST if and only if its inorder traversal is strictly increasing.

1. Problem Understanding

We are given the root A of a binary tree. Return 1 if it is a valid BST; otherwise, return 0.

A valid BST follows these rules:

  • Every value in the left subtree is strictly smaller than the current node.
  • Every value in the right subtree is strictly greater than the current node.
  • Both subtrees must also be valid BSTs.

Example 1 — Invalid BST

  1
 /
2

The left child 2 is greater than the root 1.

Output: 0

Example 2 — Valid BST

    2
   / \
  1   3

Both children satisfy the BST property.

Output: 1

Important constraints

  • Up to \(10^5\) nodes.
  • Duplicate values are not allowed.
  • The provided TreeNode stores values as Java int. If the platform truly supports values up to \(2^{32}-1\), its node type must also support that range; ordinary Java int cannot represent all such values.

2. Approach 1 — Brute Force

Intuition

For every node, find the maximum value in its left subtree and the minimum value in its right subtree. Check that both satisfy the node's ordering rule, then recursively validate both subtrees.

public class Solution {

    // Returns the largest value in this subtree.
    private long findMax(TreeNode node) {
        if (node == null) {
            return Long.MIN_VALUE;
        }

        return Math.max(node.val,
                Math.max(findMax(node.left), findMax(node.right)));
    }

    // Returns the smallest value in this subtree.
    private long findMin(TreeNode node) {
        if (node == null) {
            return Long.MAX_VALUE;
        }

        return Math.min(node.val,
                Math.min(findMin(node.left), findMin(node.right)));
    }

    // Validates this node and both of its subtrees.
    private boolean check(TreeNode node) {
        if (node == null) {
            return true;
        }

        long leftMax = findMax(node.left);
        long rightMin = findMin(node.right);

        if (leftMax >= node.val || rightMin <= node.val) {
            return false;
        }

        return check(node.left) && check(node.right);
    }

    public int isValidBST(TreeNode A) {
        return check(A) ? 1 : 0;
    }
}

Complexity

  • Time: \(O(n^2)\) worst case, because subtree values can be scanned repeatedly.
  • Auxiliary space: \(O(h)\), where \(h\) is the tree height.

This is correct but inefficient for large trees.

3. Approach 2 — Inorder Traversal + Store Values in an Array/List

The inorder traversal of a valid BST always produces values in strictly increasing order. Store the traversal in an ArrayList, then verify that every element is greater than the previous one.

Example

Valid BST

    2
   / \
  1   3

Inorder traversal: [1, 2, 3]. The list is strictly increasing.

Invalid BST

    1
   / \
  2   3

Inorder traversal: [2, 1, 3]. It is not strictly increasing, so the tree is invalid.

Complete Java solution

import java.util.ArrayList;

public class Solution {

    // Stores node values in inorder: Left -> Root -> Right.
    private void inorder(TreeNode node, ArrayList<Integer> values) {
        if (node == null) {
            return;
        }

        inorder(node.left, values);
        values.add(node.val);
        inorder(node.right, values);
    }

    public int isValidBST(TreeNode A) {
        ArrayList<Integer> values = new ArrayList<>();

        // Store the inorder traversal.
        inorder(A, values);

        // Check whether the values are strictly increasing.
        for (int i = 1; i < values.size(); i++) {
            // Equality is invalid because duplicates are not allowed.
            if (values.get(i) <= values.get(i - 1)) {
                return 0;
            }
        }

        // Every adjacent pair is strictly increasing.
        return 1;
    }
}

Dry run

For the valid BST containing 1, 2, and 3, inorder traversal creates this list:

22[1, 2]
33[1, 2, 3]

Then compare adjacent elements:

No violation is found. Output: 1

Complexity analysis

  • Time: \(O(n)\) — Every node is visited once, and the list is checked once.
  • Auxiliary space: \(O(n)\) — The ArrayList stores all \(n\) node values. The recursive traversal also uses \(O(h)\) stack space, so total auxiliary space remains \(O(n)\).

Important: We do not need to sort the array. Sorting would destroy the original traversal order and could make an invalid BST appear valid. We only check whether the inorder output is already strictly increasing.

4. Approach 3 — Inorder Traversal + Previous Value

This approach uses the same property as the array method without storing all node values. Maintain prev as the value of the previously visited node. During inorder traversal, reject a node when its value is less than or equal to prev.

Complete Java solution

public class Solution {

    // Stores the previously visited node's value.
    private long prev = Long.MIN_VALUE;

    private boolean inorder(TreeNode node) {
        if (node == null) {
            return true;
        }

        // Visit the left subtree first.
        if (!inorder(node.left)) {
            return false;
        }

        // The current value must be greater than the previous value.
        if (node.val <= prev) {
            return false;
        }

        // Update prev only after the comparison succeeds.
        prev = node.val;

        // Finish the inorder traversal by visiting the right subtree.
        return inorder(node.right);
    }

    public int isValidBST(TreeNode A) {
        // Reset state if this Solution instance is reused.
        prev = Long.MIN_VALUE;
        return inorder(A) ? 1 : 0;
    }
}

Dry run

For the valid BST containing 1, 2, and 3:

All comparisons succeed, so the output is 1. For an invalid tree with root 1 and left child 2, inorder traversal visits 2 and then 1. The comparison 1 <= 2 fails, so the output is 0.

Complexity analysis

  • Time: \(O(n)\) — Each node is visited at most once.
  • Auxiliary space: \(O(h)\) — Only the recursive stack and a constant number of variables are needed.

This approach is more space-efficient than storing the complete inorder list.

5. Approach 4 — Minimum and Maximum Range Validation

Every node must satisfy the restrictions imposed by all its ancestors. Pass an exclusive minimum and maximum range to each node. A node is valid when:

\[\text{min} < \text{node.val} < \text{max}\]

For the left child, update the upper bound to the current node's value. For the right child, update the lower bound to the current node's value.

Complete Java solution

public class Solution {

    private boolean validate(TreeNode node, long min, long max) {
        if (node == null) {
            return true;
        }

        // The current value must be strictly inside the allowed range.
        if (node.val <= min || node.val >= max) {
            return false;
        }

        // Left subtree values must be smaller than this node.
        if (!validate(node.left, min, node.val)) {
            return false;
        }

        // Right subtree values must be greater than this node.
        return validate(node.right, node.val, max);
    }

    public int isValidBST(TreeNode A) {
        return validate(A, Long.MIN_VALUE, Long.MAX_VALUE) ? 1 : 0;
    }
}

Complexity

  • Time: \(O(n)\).
  • Auxiliary space: \(O(h)\).

This approach is also optimal in time complexity for checking every node.

9. Interview Preparation Notes

Common mistakes to avoid

  1. Checking only immediate parent-child relationships instead of validating the entire BST.
  2. Using < rather than <= when comparing the current node with the previous node, which would allow duplicates.
  3. Sorting the inorder array before checking it. This can hide an invalid BST.
  4. Forgetting to reset the prev variable if the same solution object is reused.
  5. Ignoring recursion depth for a highly skewed tree with \(10^5\) nodes.

Likely interviewer follow-up questions

Q1. Why does inorder traversal work?

Because a valid BST's inorder traversal produces values in strictly increasing order.

Q2. Why is the array approach less space-efficient?

It stores every node's value, requiring \(O(n)\) auxiliary space. The previous-value approach stores only one value besides the recursive stack.

Q3. Can we implement inorder traversal iteratively?

Yes. Use an explicit stack to traverse the tree without recursive calls, which is useful for highly skewed trees.

Q4. Which approach is best for an interview?

The inorder-plus-previous approach is concise and efficient. The array approach is also easy to explain, particularly when first learning the connection between BSTs and sorted sequences.

10. Final Recommendation

For interview preparation, understand the approaches in this order:

  1. Inorder + ArrayList: Easiest to visualize and debug.
  2. Inorder + Previous: Same logic with less extra space; a strong interview solution.
  3. Range validation: Equally efficient and directly checks every node's ancestor constraints.
  4. Brute force: Useful for understanding why repeated subtree scans are inefficient.
A binary tree is a valid BST if and only if its inorder traversal is strictly increasing.

For a production interview solution, inorder traversal with a previous-value variable is recommended, giving \(O(n)\) time and \(O(h)\) auxiliary space. For extremely deep trees, use an iterative inorder traversal with a stack to avoid Java recursion limits.
