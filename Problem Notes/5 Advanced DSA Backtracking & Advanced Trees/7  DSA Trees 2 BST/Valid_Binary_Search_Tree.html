Java Algorithm Guide

Valid Binary Search Tree

Validate a binary tree by checking whether its values follow the strict ordering rules of a Binary Search Tree (BST). The main solution uses inorder traversal and compares each node with the previously visited node.

Pattern to remember: A valid BST produces a strictly increasing sequence during inorder traversal.

1. Problem Understanding

We are given the root A of a binary tree. Return 1 if it is a valid Binary Search Tree, and 0 otherwise.

A valid BST follows three rules:

  1. Every value in the left subtree is strictly smaller than the current node.
  2. Every value in the right subtree is strictly greater than the current node.
  3. Both subtrees must also be valid BSTs.

Example 1 — Invalid

  1
 /
2

The left child 2 is greater than the root 1.

Output: 0

Example 2 — Valid

  2
 / \
1   3

The left value is smaller and the right value is greater than the root.

Output: 1

2. Brute Force Approach

At each node, find the maximum value in its left subtree and the minimum value in its right subtree. Reject the tree if the left maximum is not smaller than the node, or the right minimum is not greater. Then recursively check both subtrees. 

public class Solution {

    // Find the largest value anywhere in this subtree.
    private long findMax(TreeNode node) {
        if (node == null) {
            return Long.MIN_VALUE;
        }

        return Math.max(node.val,
                Math.max(findMax(node.left), findMax(node.right)));
    }

    // Find the smallest value anywhere in this subtree.
    private long findMin(TreeNode node) {
        if (node == null) {
            return Long.MAX_VALUE;
        }

        return Math.min(node.val,
                Math.min(findMin(node.left), findMin(node.right)));
    }

    // Check this node and then validate both of its subtrees.
    private boolean check(TreeNode node) {
        if (node == null) {
            return true;
        }

        long leftMax = findMax(node.left);
        long rightMin = findMin(node.right);

        if (leftMax >= node.val || rightMin <= node.val) {
            return false;
        }

        return check(node.left) && check(node.right);
    }

    // Convert the boolean validation result to the required integer output.
    public int isValidBST(TreeNode A) {
        return check(A) ? 1 : 0;
    }
}
Complexity: Time is \(O(n^2)\) in the worst case because values may be scanned repeatedly. Auxiliary space is \(O(h)\) for recursion, where \(h\) is the tree height. This is inefficient for a tree with up to \(10^5\) nodes.

3. Optimized Approach 1 — Inorder Traversal

Inorder traversal visits nodes in this order: Left subtree → Current node → Right subtree. For a valid BST, the resulting values must be strictly increasing.

Valid tree

  2
 / \
1   3

Inorder sequence: 1 → 2 → 3

Invalid tree

  1
 / \
2   3

Inorder sequence: 2 → 1 → 3. The sequence decreases at 1.

The key idea: previous and current

  1. Recursively validate the left subtree.
  2. Compare the current node's value with prev.
  3. If current.val <= prev, return false.
  4. Update prev = current.val.
  5. Recursively validate the right subtree.

Complete Java solution

public class Solution {

    // Stores the value of the previously visited node.
    private long prev = Long.MIN_VALUE;

    private boolean inorder(TreeNode node) {
        // An empty subtree is valid.
        if (node == null) {
            return true;
        }

        // Visit the left subtree first.
        if (!inorder(node.left)) {
            return false;
        }

        // The current value must be greater than the previous value.
        if (node.val <= prev) {
            return false;
        }

        // Update prev only after the current value passes the check.
        prev = node.val;

        // Visit the right subtree.
        return inorder(node.right);
    }

    public int isValidBST(TreeNode A) {
        // Reset state in case the same Solution object is reused.
        prev = Long.MIN_VALUE;

        return inorder(A) ? 1 : 0;
    }
}
Why use long prev = Long.MIN_VALUE? The initial value must be smaller than any valid node value. The problem's values are nonnegative, so this sentinel works safely and does not mistake a valid value of 0 for an invalid value.

Dry run — valid tree

For the tree with root 2, left child 1, and right child 3:

Complexity: Time is \(O(n)\), since each node is visited at most once. Auxiliary space is \(O(h)\) for the recursive call stack. A balanced tree uses \(O(\log n)\) stack space, while a skewed tree may use \(O(n)\). A very deep tree can overflow the Java call stack; the iterative version mentioned below avoids recursive calls.

4. Optimized Approach 2 — Minimum and Maximum Range

Pass the allowed minimum and maximum values down the tree. Each node must satisfy the exclusive range:

\[\text{min} < \text{node.val} < \text{max}\]

The left child inherits the current node's value as its upper bound. The right child inherits it as its lower bound. 

public class Solution {

    private boolean validate(TreeNode node, long min, long max) {
        // An empty subtree satisfies the BST rules.
        if (node == null) {
            return true;
        }

        // Reject values outside the allowed exclusive range.
        if (node.val <= min || node.val >= max) {
            return false;
        }

        // Restrict the left subtree below this value and the right above it.
        return validate(node.left, min, node.val)
                && validate(node.right, node.val, max);
    }

    public int isValidBST(TreeNode A) {
        // Start with bounds wide enough to include all node values.
        return validate(A, Long.MIN_VALUE, Long.MAX_VALUE) ? 1 : 0;
    }
}

Complexity: \(O(n)\) time and \(O(h)\) auxiliary space. This approach catches violations involving distant ancestors, not just immediate parent-child relationships.

Which optimized approach should you choose?

Choose inorder traversal with a previous-value variable to practice tree traversals and see how traversal order solves the problem. Choose range validation when you want to enforce each node's restrictions explicitly. Both are correct and efficient.

6. Edge Cases to Remember

  • Single node: Valid, so return 1.
  • Duplicate values: Invalid, because the sequence must be strictly increasing.
  • Invalid descendant: Inorder traversal detects it when the sequence stops increasing.
  • Node value zero: Valid when its position satisfies the BST property.
  • Highly skewed tree: Recursive implementations may hit Java's stack limit. Use iterative inorder traversal for safer handling of deep trees.

8. Interview Preparation Notes

Key pattern: Inorder traversal + previous node/value tracking.

Common mistakes

  • Checking only the current node against its immediate parent.
  • Using current.val < prev instead of current.val <= prev, which would allow duplicates.
  • Updating prev before comparing it with the current value.
  • Forgetting to reset prev when the same Solution instance may be reused.

Likely follow-up questions

  • Why does inorder traversal work? A BST's inorder sequence is strictly increasing.
  • Can we stop early? Yes. Return false as soon as a violation is detected.
  • Can we use an iterative approach? Yes. Use a stack to perform inorder traversal without recursion.
  • What if duplicates are allowed? The comparison rules must change according to the problem's definition of where duplicates are permitted.

9. Final Recommendation

Practice the inorder traversal solution first. The core logic is that a valid BST must produce a strictly increasing sequence during inorder traversal. 

// Validate the left subtree before checking this node.
if (!inorder(node.left)) return false;

// Reject values that do not strictly increase.
if (node.val <= prev) return false;

// Record this value before visiting the right subtree.
prev = node.val;

// Continue with the right subtree.
return inorder(node.right);
