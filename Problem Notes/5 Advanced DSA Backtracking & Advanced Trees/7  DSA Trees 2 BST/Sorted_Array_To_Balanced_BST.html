Sorted Array to Balanced BST

Convert a sorted integer array into a height-balanced Binary Search Tree (BST). The key is to choose a middle element as the root, then recursively build subtrees from the remaining halves.

Pattern to remember: Middle becomes root; the left half becomes the left subtree, and the right half becomes the right subtree.

1. Problem Understanding

You are given an integer array sorted in ascending order. Convert it into a height-balanced Binary Search Tree (BST) and return its root node.

A BST follows these rules:

  • Every value in the left subtree is smaller than the root.
  • Every value in the right subtree is greater than the root.
  • For every node, the heights of its left and right subtrees differ by at most 1.

Input

A = [1, 2, 3, 5, 10]

Balanced BST

        3
       / \
      1   5
       \   \
        2   10

The output is not another array. It is the root node of the constructed tree.

2. Brute Force Approach

A straightforward approach is to insert each sorted element into a normal BST one by one.

How it works

  1. Start with an empty BST.
  2. Insert 1, then 2, then 3, and so on.
  3. Return the root.

Why it is inefficient

Because the array is sorted, inserting elements in ascending order creates a skewed tree:

1
 \
  2
   \
    3
     \
      5
       \
        10

This tree is not height-balanced.

  • Time complexity: \(O(n^2)\) in the worst case, because each insertion may traverse the existing tree.
  • Auxiliary space: \(O(n)\) for the tree, with potentially \(O(n)\) recursive call-stack depth if insertion is recursive.
Limitation: This approach does not guarantee a balanced tree.

3. Optimized Approach — Divide and Conquer

Intuition

Since the array is already sorted, there is no need to search for the correct position of an element. The middle element is a good choice for the root because approximately half the elements fall on each side.

For A = [1, 2, 3, 5, 10]:

  1. The middle element is 3; make it the root.
  2. The left half is [1, 2]; recursively build the left subtree.
  3. The right half is [5, 10]; recursively build the right subtree.
  4. Repeat until there are no elements left in a range.

Two pointers, start and end, represent the current portion of the array.

Java code — interview-ready solution

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */

public class Solution {

    // DO NOT MODIFY THE ARGUMENTS WITH "final" PREFIX.
    public TreeNode sortedArrayToBST(final int[] A) {
        return buildBST(A, 0, A.length - 1);
    }

    private TreeNode buildBST(int[] A, int start, int end) {

        // No elements are available in this range.
        if (start > end) {
            return null;
        }

        // Select the middle element as the root.
        int mid = start + (end - start) / 2;

        TreeNode root = new TreeNode(A[mid]);

        // Construct the left subtree from the left half.
        root.left = buildBST(A, start, mid - 1);

        // Construct the right subtree from the right half.
        root.right = buildBST(A, mid + 1, end);

        // Return the root of this subtree.
        return root;
    }
}

Understanding the important lines

  1. Base condition 
    if (start > end) {
    return null;
}

    When start becomes greater than end, the current range has no elements, so that child is null.

  2. Finding the middle 
    int mid = start + (end - start) / 2;

    This finds the middle index without directly adding start + end, which is safer against integer overflow.

  3. Creating the root 
    TreeNode root = new TreeNode(A[mid]);

    The middle element becomes the root of the current subtree.

  4. Building the left subtree 
    root.left = buildBST(A, start, mid - 1);

    Only elements before the middle index are considered.

  5. Building the right subtree 
    root.right = buildBST(A, mid + 1, end);

    Only elements after the middle index are considered.

  6. Returning the root 
    return root;

    The completed subtree is returned to its parent node.

5. Complexity Analysis

Let \(n\) be the length of the array.

  • Time complexity: \(O(n)\). Every array element is selected exactly once to create a tree node. The work per node, excluding recursive calls, is constant.
  • Auxiliary space: \(O(\log n)\). The recursive calls divide the array approximately in half each time, so the recursion depth is \(O(\log n)\) for a balanced tree.
  • The tree itself requires \(O(n)\) space for its nodes. If total memory including the output tree is counted, space complexity is \(O(n)\).

8. Interview Preparation Notes

Key concept to remember: Divide and Conquer + Recursion.

Whenever a sorted array needs to become a balanced BST, choose the middle element as the root and recursively process the left and right halves.

Common mistakes

  1. Using mid - 1 for the left range and mid + 1 for the right range incorrectly, or accidentally including mid again. This can cause infinite recursion.
  2. Forgetting the base condition start > end.
  3. Building the tree by inserting sorted values one by one, which can produce a skewed tree.
  4. Claiming \(O(n)\) total space when discussing only auxiliary space; the recursive stack is \(O(\log n)\), but the output tree takes \(O(n)\).

Likely interviewer follow-up questions

Q1. Why does choosing the middle element produce a balanced BST?

It divides the sorted elements into two portions whose sizes differ by at most one. Repeating this at every recursive call keeps the subtree heights balanced.

Q2. Why is the time complexity \(O(n)\)?

Each element is processed exactly once to create one node.

Q3. Can you solve it iteratively?

Yes. You can use a stack or queue of range boundaries and parent-node references, but recursion is simpler and naturally expresses the divide-and-conquer approach.

Q4. What if the array contains duplicates?

The stated problem does not specify duplicate handling. If duplicates are allowed, the BST ordering convention must be defined. The midpoint construction preserves nondecreasing inorder order, but strict BST rules may not hold for equal values.

9. Final Recommendation

Use the recursive midpoint approach in an interview. It is simple, optimal, and guarantees a height-balanced BST for a sorted array.

  • Time: \(O(n)\)
  • Auxiliary space: \(O(\log n)\)
  • Total space including the tree: \(O(n)\)
One-line intuition: Middle becomes root, left half becomes left subtree, right half becomes right subtree.
