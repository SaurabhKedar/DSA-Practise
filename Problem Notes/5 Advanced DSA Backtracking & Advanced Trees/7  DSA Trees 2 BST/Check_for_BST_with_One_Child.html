Check for BST with One Child

Given an integer array representing a preorder traversal, determine whether it can describe a Binary Search Tree (BST) where every internal node has exactly one child. This guide compares a brute-force construction, a tempting but incorrect boundary check, and the recommended range-based validation.

Key idea: Each value in preorder must respect the valid range established by earlier values. Tracking those boundaries correctly gives an \(O(N)\) time, \(O(1)\) auxiliary-space solution.

1. Problem Understanding

You are given an integer array A representing the preorder traversal of a binary tree. Determine whether it is possible for this array to represent the preorder traversal of a BST where every internal node has exactly one child.

A BST follows these rules:

  • Values in the left subtree are smaller than the parent.
  • Values in the right subtree are greater than the parent.
  • Every non-leaf node has exactly one child.

Preorder traversal visits nodes in this order: Root → Left → Right.

Return "YES" if such a BST is possible; otherwise, return "NO".

Example 1 — Valid

Input: A = [4, 10, 5, 8]

One possible BST:

4
 \
  10
  /
 5
  \
   8

Preorder: 4 → 10 → 5 → 8.

  • 10 > 4, so 10 is the right child of 4.
  • 5 < 10, so 5 is the left child of 10.
  • 8 > 5, so 8 is the right child of 5.

Every internal node has one child, and the BST ordering is valid.

Output: "YES"

Example 2 — Invalid

Input: A = [1, 5, 6, 4]

After moving right from 1 through 5 and then right again to 6, the value 4 is less than 5, violating the boundary established when entering 5's right subtree.

Output: "NO"

2. Brute Force Approach

A straightforward approach is to construct a BST by inserting the array elements in order, then check whether any node has both a left and a right child.

  1. Insert each element into a BST.
  2. Traverse the tree.
  3. If any node has two children, return "NO".
  4. Otherwise, return "YES".

Java Implementation

public class Solution {

    static class Node {
        int val;
        Node left, right;

        Node(int val) {
            this.val = val;
        }
    }

    private Node insert(Node root, int val) {
        if (root == null) {
            return new Node(val);
        }

        if (val < root.val) {
            root.left = insert(root.left, val);
        } else if (val > root.val) {
            root.right = insert(root.right, val);
        }

        return root;
    }

    private boolean checkOneChild(Node root) {
        if (root == null) {
            return true;
        }

        // A node with two children violates the required condition.
        if (root.left != null && root.right != null) {
            return false;
        }

        // Check the remaining child subtree or subtrees.
        return checkOneChild(root.left)
            && checkOneChild(root.right);
    }

    public String solve(int[] A) {
        Node root = null;

        // Insert elements in their given order.
        for (int val : A) {
            root = insert(root, val);
        }

        // Accept only if every internal node has at most one child.
        return checkOneChild(root) ? "YES" : "NO";
    }
}

Complexity

  • Time: \(O(N^2)\) in the worst case, due to repeated insertion into a skewed BST.
  • Auxiliary space: \(O(N)\) for the constructed tree, plus recursion stack space.

This approach works conceptually, but it performs unnecessary work. The preorder can be validated directly in \(O(N)\) time.

3. Optimized Approach 1 — Last-Element Boundary

This approach uses the last element as a boundary and compares each adjacent pair against it.

Intuition

  • If A[i] < A[i + 1], check whether A[i] > last.
  • Otherwise, check whether A[i] < last.
  • If either condition is violated, return "NO".

Java Implementation

public class Solution {
    public String solve(int[] A) {
        int n = A.length;

        // The last value acts as the final BST boundary.
        int last = A[n - 1];

        // Check each adjacent pair against the boundary.
        for (int i = 0; i < n - 1; i++) {
            if (A[i] < A[i + 1]) {
                // An increasing pair requires the current value below last.
                if (A[i] > last) {
                    return "NO";
                }
            } else {
                // A decreasing pair requires the current value above last.
                if (A[i] < last) {
                    return "NO";
                }
            }
        }

        // No adjacent pair violated this boundary check.
        return "YES";
    }
}

Important correctness warning

This approach is not correct for all valid inputs. It can reject a valid preorder because the last node is not necessarily a boundary for every adjacent pair. Do not use it as the final interview solution.

Consider A = [10, 5, 7, 6], which is a valid preorder:

       10
       /
      5
       \
        7
       /
      6

Every internal node has exactly one child, and the BST ordering is valid. The correct answer is "YES".

However, the last-element approach compares 5 < 7 and checks whether 5 > 6. That condition is false, so it incorrectly returns "NO".

This is an example of an appealing but insufficient boundary check.

4. Optimized Approach 2 — Range-Based Validation (Recommended)

In a BST, every node must respect the boundaries established by its ancestors. Maintain the smallest and largest allowed values as the preorder is scanned. If a value falls outside the current range, the traversal is invalid.

The range starts unrestricted. For each value after the root, compare it with the previous value. If it is greater, the traversal moves to a right child and raises the minimum boundary. Otherwise, it moves to a left child and lowers the maximum boundary.

Maintain: min as the smallest allowed value and max as the largest allowed value.

Recommended Java Implementation

public class Solution {
    public String solve(int[] A) {
        int n = A.length;

        // One or two distinct values always form a valid one-child BST.
        if (n <= 2) {
            return "YES";
        }

        // Initially, every integer is within the valid range.
        int min = Integer.MIN_VALUE;
        int max = Integer.MAX_VALUE;

        for (int i = 1; i < n; i++) {
            // Reject a value outside the boundaries established so far.
            if (A[i] < min || A[i] > max) {
                return "NO";
            }

            if (A[i] > A[i - 1]) {
                // Move to a right child; future values must exceed A[i - 1].
                min = A[i - 1];
            } else {
                // Move to a left child; future values must be below A[i - 1].
                max = A[i - 1];
            }
        }

        // Every value satisfied the valid range.
        return "YES";
    }
}

10. Interview Preparation Notes

Key concept: Validate preorder using the boundaries imposed by previous nodes.

Common mistakes

  • Checking only adjacent elements without tracking all previous constraints.
  • Assuming the last element is a universal boundary for every pair.
  • Forgetting that a value must respect the bounds established by all relevant ancestors.
  • Constructing a tree when direct validation is sufficient.

Final recommendation

Implement the range-based solution in your interview.

  • Time complexity: \(O(N)\)
  • Auxiliary space: \(O(1)\)
  • Pattern: BST preorder validation using range boundaries
Takeaway: A locally reasonable adjacent-pair check can fail. Maintaining valid ranges captures the constraints established by the traversal.
