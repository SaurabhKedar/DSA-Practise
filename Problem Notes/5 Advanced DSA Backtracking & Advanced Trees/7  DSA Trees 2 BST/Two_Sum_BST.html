Java Algorithm Guide

Two Sum in a Binary Search Tree

Find two different nodes whose values add up to the target B. The BST property supports a two-iterator solution, while a HashSet offers a simple linear-time approach.

Recommended approach: Use a HashSet for an easy-to-explain \(O(N)\)-time solution, or two BST iterators for \(O(N)\) time and \(O(H)\) auxiliary space.

1. Problem Understanding

You are given:

  • A: the root of a Binary Search Tree.
  • B: the target sum.

Check whether two different nodes have values that add up to B. Return 1 if a pair exists, and 0 otherwise.

Example 1 — Pair found

    10
   /  \
  9    20

For target B = 19, the values 10 and 9 belong to different nodes and sum to 19.

Output: 1

Example 2 — No pair

Using the same tree with target B = 40, the possible pair sums are 10 + 9 = 19, 10 + 20 = 30, and 9 + 20 = 29. None equals 40.

Output: 0

Important Conditions

  • The tree can contain up to \(100{,}000\) nodes, so an \(O(N^2)\) solution may be too slow.
  • Node values are positive integers.
  • The same node cannot be used twice. A single node with value 10 cannot satisfy a target of 20.
  • Depending on the BST's duplicate-value convention, equal values may exist in different nodes. Two distinct nodes with equal values can form a valid pair.

2. Brute-Force Approach — Store Values and Check Every Pair

Intuition

Collect every node's value into a list, then check all possible pairs. For [9, 10, 20], check 9 + 10, 9 + 20, and 10 + 20. Return 1 if any pair equals B; otherwise, return 0.

Java Solution

import java.util.ArrayList;
import java.util.List;

public class Solution {

    private void inorder(TreeNode root, List<Integer> values) {
        if (root == null) {
            return;
        }

        // Store every node's value in sorted order.
        inorder(root.left, values);
        values.add(root.val);
        inorder(root.right, values);
    }

    public int t2Sum(TreeNode A, int B) {
        List<Integer> values = new ArrayList<>();

        // Collect all values from the BST.
        inorder(A, values);

        // Check every pair of different positions.
        for (int i = 0; i < values.size(); i++) {
            for (int j = i + 1; j < values.size(); j++) {
                if (values.get(i) + values.get(j) == B) {
                    return 1;
                }
            }
        }

        return 0;
    }
}

Complexity

  • Time: \(O(N^2)\) for checking pairs, plus \(O(N)\) traversal; overall \(O(N^2)\).
  • Auxiliary space: \(O(N)\) for stored values and the recursion stack.

Limitation: Checking every pair is too expensive for a tree containing up to \(100{,}000\) nodes.

3. Optimized Approach 1 — HashSet

Intuition

For a current node with value x, calculate the value needed to complete the target:

\[\text{required} = B - x\]

If required has already been visited, the pair is found. For B = 19, visiting 10 requires 9, so store 10. When 9 is visited, its required value is 10, which is already in the set.

Algorithm

  1. Create a HashSet<Integer> to store visited node values.
  2. Traverse the tree.
  3. For each node, calculate B - node.val.
  4. If the required value is in the set, return 1.
  5. Otherwise, add the current value and continue.
  6. If traversal finishes without a pair, return 0.

Java Solution — Recommended

import java.util.HashSet;
import java.util.Set;

public class Solution {

    private boolean findPair(
            TreeNode root, int B, Set<Integer> seen) {

        // An empty subtree cannot contain a pair.
        if (root == null) {
            return false;
        }

        // Find the value needed to reach the target.
        int required = B - root.val;

        // Check before inserting so this node cannot match itself.
        if (seen.contains(required)) {
            return true;
        }

        // Remember this value for the nodes visited afterward.
        seen.add(root.val);

        // Search both subtrees.
        return findPair(root.left, B, seen)
                || findPair(root.right, B, seen);
    }

    public int t2Sum(TreeNode A, int B) {
        Set<Integer> seen = new HashSet<>();

        return findPair(A, B, seen) ? 1 : 0;
    }
}

This preserves the required InterviewBit method signature: public int t2Sum(TreeNode A, int B).

Why Check Before Inserting?

If the tree contains only one node with value 10 and B = 20, inserting first and then checking would let that node match itself. Checking first ensures that a match must come from a previously visited node.

Complexity Analysis

  • Time: \(O(N)\) average, since each node is visited at most once and HashSet operations take \(O(1)\) average time.
  • Auxiliary space: \(O(N)\) for the HashSet and up to \(O(H)\) for recursion; overall \(O(N)\).

A highly skewed tree can cause deep recursion. An iterative traversal avoids that recursion-stack risk.

4. Optimized Approach 2 — Two-Pointer BST Traversal

Intuition

An inorder traversal of a BST produces ascending values. For the example tree, that sequence is [9, 10, 20]. A sorted sequence can be searched with two pointers: start at the smallest and largest values, move the smaller pointer forward when the sum is too small, and move the larger pointer backward when the sum is too large.

Two stack-based BST iterators implement these pointers without storing every node in an array.

Algorithm

  1. Create an ascending iterator using inorder traversal.
  2. Create a descending iterator using reverse inorder traversal.
  3. Get the smallest and largest nodes.
  4. While the iterators refer to different nodes, calculate their sum. Return 1 if it equals B.
  5. Advance the ascending iterator if the sum is too small; advance the descending iterator if it is too large.
  6. Return 0 when the iterators meet or cross without finding a pair.

Java Solution

import java.util.ArrayDeque;
import java.util.Deque;

public class Solution {

    // Iterates through BST nodes in ascending or descending order.
    private static class BSTIterator {
        private final Deque<TreeNode> stack = new ArrayDeque<>();
        private final boolean ascending;

        BSTIterator(TreeNode root, boolean ascending) {
            this.ascending = ascending;
            pushPath(root);
        }

        // Store the path to the next smallest or largest node.
        private void pushPath(TreeNode node) {
            while (node != null) {
                stack.push(node);
                node = ascending ? node.left : node.right;
            }
        }

        // Return the next node in the chosen order.
        TreeNode next() {
            if (stack.isEmpty()) {
                return null;
            }

            TreeNode node = stack.pop();

            // After visiting a node, explore its opposite subtree.
            if (ascending) {
                pushPath(node.right);
            } else {
                pushPath(node.left);
            }

            return node;
        }
    }

    public int t2Sum(TreeNode A, int B) {

        // Start one iterator at the smallest value.
        BSTIterator leftIterator = new BSTIterator(A, true);

        // Start the other iterator at the largest value.
        BSTIterator rightIterator = new BSTIterator(A, false);

        TreeNode left = leftIterator.next();
        TreeNode right = rightIterator.next();

        // Node identity ensures the same node is never used twice.
        while (left != null && right != null && left != right) {
            long sum = (long) left.val + right.val;

            if (sum == B) {
                return 1;
            } else if (sum < B) {
                // The sum needs a larger value.
                left = leftIterator.next();
            } else {
                // The sum needs a smaller value.
                right = rightIterator.next();
            }
        }

        return 0;
    }
}

Compare node references with left != right, not their values. Distinct nodes may have equal values. The long sum also avoids integer overflow if node value limits are expanded.

Complexity Analysis

  • Time: \(O(N)\). Each iterator pushes and pops each node at most once.
  • Auxiliary space: \(O(H)\) for the iterator stacks; \(O(\log N)\) for a balanced BST and \(O(N)\) for a skewed BST.

This method uses less memory than storing all node values in an array when the BST is balanced.

Which Should You Choose?

  • For a straightforward, efficient solution, use the HashSet approach.
  • To demonstrate deeper understanding of BST properties and reduce auxiliary space for balanced trees, use two BST iterators.
  • Avoid brute force for the maximum constraint of \(100{,}000\) nodes.

8. Interview Preparation Notes

Key Concepts to Remember

  • Complement: For a current value x, search for B - x.
  • HashSet: Provides average \(O(1)\) membership lookup.
  • BST property: Inorder traversal returns values in ascending order.
  • Two pointers: Increase the smaller value when the sum is too small; decrease the larger value when the sum is too large.

Common Mistakes

  1. Using one node twice: Ensure the matching node is different from the current node.
  2. Returning a boolean instead of an integer: The platform expects 1 or 0.
  3. Using nested loops for large inputs: This takes \(O(N^2)\) time.
  4. Comparing node values instead of node identity in the iterator approach: Distinct nodes can have equal values.
  5. Ignoring recursion depth: A highly skewed tree can cause a StackOverflowError in recursive traversal.

Likely Interviewer Follow-up Questions

Q1. Can we solve it without a HashSet?

Yes. Use ascending and descending BST iterators with two stacks. This requires \(O(H)\) auxiliary space.

Q2. Why does the two-pointer method work?

The BST iterators generate values in sorted order. If the sum is too small, advancing the smallest pointer is the useful direction; if it is too large, moving the largest pointer backward is the useful direction.

Q3. What if duplicate values are present?

Two different nodes can form a valid pair even if their values are equal. The HashSet solution works when the second occurrence is encountered, because the first occurrence has already been inserted.

Q4. What is the best approach for a balanced BST?

Both optimized approaches take \(O(N)\) time. The iterator approach uses \(O(\log N)\) auxiliary space for a balanced BST, while the HashSet approach uses \(O(N)\).

9. Final Recommendation

For an InterviewBit submission, start with the HashSet approach because it is easy to explain, concise, and efficient for up to \(100{,}000\) nodes.

  • Time: \(O(N)\) average.
  • Auxiliary space: \(O(N)\).
  • Core intuition: For every node, check whether B - node.val has already been visited.
Two Sum = current value + required complement. Store previously visited values so you do not need to check every pair.
