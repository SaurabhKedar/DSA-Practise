Java Algorithm Guide

Deserialize Binary Tree

Reconstruct a binary tree from its level-order array representation using Breadth-First Search (BFS) and a queue.

Pattern to remember: Process parents in level order, read their left and right child values, attach valid children, and enqueue them. The value -1 represents a missing child.

1. Problem Understanding

We are given an array representing a binary tree in level-order format, where -1 means a missing (null) child. Reconstruct the tree and return its root.

Example input

A = [1, 2, 3, 4, 5, -1, -1, -1, -1, -1, -1]

Tree represented by the array

        1
       / \
      2   3
     / \
    4   5
  • 1 is the root.
  • 2 and 3 are the left and right children of 1.
  • 4 and 5 are the left and right children of 2.
  • -1 indicates that a child does not exist.

Important: -1 is a marker, not a node that should be created.

2. Brute-Force Approach

A simple way to reconstruct the tree is to process the array from left to right and search for the parent of every value. Repeatedly searching for parents can take \(O(N^2)\) time.

A better solution uses a queue, which lets us process parents in exactly the same order as level-order traversal.

3. Optimized Approach — Queue (BFS)

Intuition

When reconstructing a tree from level order, create nodes in the same order in which their parents appear. A queue remembers which parents still need their children assigned.

For the example array, create node 1 and put it in the queue. Remove it, read 2 and 3 as its children, and add those children to the queue. Next, process node 2, assigning children 4 and 5.

Java solution

Use the exact method signature required by the platform.

import java.util.*;

public class Solution {
    public TreeNode solve(ArrayList<Integer> A) {

        // Handle an empty tree or a null root.
        if (A == null || A.size() == 0 || A.get(0) == -1) {
            return null;
        }

        // The first element is the root.
        TreeNode root = new TreeNode(A.get(0));

        // Queue stores nodes whose children we must process.
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);

        // Index of the next value to read from the array.
        int i = 1;
        int n = A.size();

        while (!queue.isEmpty() && i < n) {

            // Get the next parent in level order.
            TreeNode parent = queue.poll();

            // Process the left child.
            int leftValue = A.get(i);
            i++;

            if (leftValue != -1) {
                TreeNode leftChild = new TreeNode(leftValue);
                parent.left = leftChild;
                queue.offer(leftChild);
            }

            // Process the right child, if an entry exists.
            if (i < n) {
                int rightValue = A.get(i);
                i++;

                if (rightValue != -1) {
                    TreeNode rightChild = new TreeNode(rightValue);
                    parent.right = rightChild;
                    queue.offer(rightChild);
                }
            }
        }

        return root;
    }
}

How the code works

  1. Create the root: The first element becomes the root node.
  2. Initialize the queue: Add the root because its children have not been processed.
  3. Remove a parent: Take the front node from the queue.
  4. Process the left child: Read the next array element. If it is not -1, create and attach the left child, then enqueue it.
  5. Process the right child: Repeat the same process for the right child.
  6. Repeat: Continue until there are no parents left to process or the array is exhausted.
  7. Return the root: The complete tree is now reconstructed.

The check i < n before reading the right child prevents accessing an index beyond the array boundary if the input ends after a left-child entry.

5. Brute-Force vs. Optimized Approach

A naive approach would repeatedly scan the array to find the next parent and determine its children. This can cause unnecessary repeated work. The queue-based approach avoids repeated searching by processing each parent once, in level-order sequence.

Approach Time complexity Auxiliary space
Repeated parent searching\(O(N^2)\) in a naive implementation\(O(N)\)
Queue-based BFS\(O(N)\)\(O(N)\)

The queue-based method is recommended. Each array element is read at most once, and each actual node is enqueued and dequeued at most once.

6. Complexity Analysis

Let \(N\) be the number of elements in the array.

  • Time: \(O(N)\) — every array element is processed at most once, and each tree node is processed once.
  • Auxiliary space: \(O(N)\) — in the worst case, the queue can contain a large number of nodes.
  • Total tree storage: \(O(N)\) — the newly constructed binary tree contains at most \(N\) nodes.

The auxiliary-space figure counts the queue, excluding the returned tree itself.

7. Edge Cases

  • Single node: [10] returns a tree with root 10 and no children.
  • Missing left child: [1, -1, 2] creates root 1 with only a right child 2.
  • Missing right child: [1, 2, -1] creates root 1 with only a left child 2.
  • All children missing: [1, -1, -1] returns a single-node tree.
  • Negative values other than -1: These are valid node values if permitted by the constraints. Only -1 is treated as null.
  • Maximum input size: The algorithm runs in linear time, making it suitable for \(N \le 10^5\).

9. Interview Preparation Notes

Pattern to remember: Queue-based Breadth-First Search (BFS).

Common mistakes

  • Creating a node when the array value is -1.
  • Forgetting to enqueue newly created child nodes.
  • Reading beyond the array's last index.
  • Assuming that each node has two actual children instead of treating -1 as a missing child.

Possible interviewer follow-ups

Q1. Why use a queue instead of a stack?

A queue processes nodes in first-in, first-out order, matching level-order traversal. A stack would naturally process them in a different order.

Q2. Can we solve this recursively?

Yes, but a recursive solution needs to preserve the level-order parent-processing order. A queue expresses that requirement more naturally.

Q3. What is the time complexity?

\(O(N)\), because every array element is consumed at most once.

Q4. Why don't we enqueue -1?

Because -1 represents a missing child, not a real node. Enqueuing it would require processing a nonexistent parent.

10. Final Recommendation

Implement the queue-based BFS solution in an interview. It is straightforward, efficient, and directly matches the level-order representation.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(N)\)

Memory trick: Create a parent, read its left and right values, attach valid children, and enqueue those children. Repeat until the array is processed.
