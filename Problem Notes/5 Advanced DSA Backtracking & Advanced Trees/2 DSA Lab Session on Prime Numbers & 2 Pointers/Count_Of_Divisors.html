Count of Divisors — Java Solution

This problem is a good example of number theory and the Sieve technique. Since the array can contain up to 100,000 elements and each element can be as large as 10^6, we should avoid repeatedly checking every possible divisor.

1. Problem Understanding

You are given an integer array A. For every element, count how many positive integers divide it completely, and return those counts in the same order.

For example, for A = [2, 3, 4, 5]:

  • 2 → divisors are [1, 2] → count = 2
  • 3 → divisors are [1, 3] → count = 2
  • 4 → divisors are [1, 2, 4] → count = 3
  • 5 → divisors are [1, 5] → count = 2

Output: [2, 2, 3, 2]

Important observations:

  • Only positive divisors are counted.
  • Every number has at least one divisor: 1.
  • Every number is divisible by itself.
  • The order of the answer must match the input order.
  • 1 ≤ A[i] ≤ 10^6.

2. Brute Force Approach

Intuition

For each number, check every integer from 1 to that number. If the number is divisible by the current integer, increment the divisor count.

For example, for A[i] = 6:

Candidate divisor 6 % divisor == 0? Count
1Yes1
2Yes2
3Yes3
4No3
5No3
6Yes4

The total number of divisors is 4.

Java code — Brute Force

import java.util.*;

public class Solution {
    public ArrayList<Integer> solve(ArrayList<Integer> A) {
        ArrayList<Integer> result = new ArrayList<>();

        // Process every number in the input array.
        for (int num : A) {
            int count = 0;

            // Check every possible divisor from 1 to num.
            for (int d = 1; d <= num; d++) {
                if (num % d == 0) {
                    count++;
                }
            }

            result.add(count);
        }

        return result;
    }
}

Complexity analysis

Let n be the array length and M = max(A).

  • Time: \(O(nM)\) in the worst case, because each number may require checking up to M candidates.
  • Auxiliary space: \(O(1)\), excluding the returned array.
  • Limitation: With n = 100,000 and M = 10^6, this can require far too many operations.

We can improve this by using the fact that divisors come in pairs.

3. Optimized Approach 1 — Check Divisors up to √N

Intuition

Divisors occur in pairs. For example, the divisors of 36 are:

(1, 36), (2, 18), (3, 12), (4, 9), (6, 6)

Notice that if d divides num, then num / d is also a divisor. Therefore, we only need to check divisors up to \(\sqrt{num}\). When a divisor is found, count both members of the pair. If both are the same number, count only once.

For example, 36 has five divisor pairs, but (6, 6) contributes only one divisor. Its total divisor count is 9.

Java code

import java.util.*;

public class Solution {
    public ArrayList<Integer> solve(ArrayList<Integer> A) {
        ArrayList<Integer> result = new ArrayList<>();

        for (int num : A) {
            int count = 0;

            // We only need to check divisors up to sqrt(num).
            for (int i = 1; i * i <= num; i++) {
                if (num % i == 0) {
                    if (i == num / i) {
                        count++;
                    } else {
                        count = count + 2;
                    }
                }
            }

            result.add(count);
        }

        return result;
    }
}

Complexity

  • Time: \(O(n\sqrt{M})\), where M is the maximum element.
  • Auxiliary space: \(O(1)\), excluding the returned array.

This is much faster than brute force. However, we can do even better when many numbers need their divisor counts calculated.

4. Recommended Optimized Approach — Sieve of Divisors

Intuition

Instead of calculating the divisor count separately for every array element, precompute the divisor counts for every number up to the maximum value in the array. This is similar to the Sieve of Eratosthenes, which finds prime numbers by processing their multiples.

The key idea is simple:

  • 1 divides every number.
  • 2 divides 2, 4, 6, 8, ....
  • 3 divides 3, 6, 9, 12, ....
  • 4 divides 4, 8, 12, 16, ....

Whenever we visit a multiple of d, we increase its divisor count by one.

Algorithm steps

  1. Find the maximum value max in the input array.
  2. Create an integer array divisors of size max + 1, initialized to zero.
  3. For every possible divisor d from 1 to max, visit all multiples of d.
  4. Increase divisors[multiple] by one for every multiple visited.
  5. Traverse the original array and retrieve divisors[num] for each element.
  6. Return the result array in the original order.

Java code — Interview-ready solution

import java.util.*;

public class Solution {
    public ArrayList<Integer> solve(ArrayList<Integer> A) {
        int max = 0;

        // Step 1: Find the maximum element.
        for (int num : A) {
            max = Math.max(max, num);
        }

        // divisors[x] stores the number of divisors of x.
        int[] divisors = new int[max + 1];

        // Step 2: Count divisors for every number using a sieve.
        for (int d = 1; d <= max; d++) {

            // Every multiple of d is divisible by d.
            for (int multiple = d; multiple <= max; multiple += d) {
                divisors[multiple]++;
            }
        }

        // Step 3: Retrieve the precomputed counts in input order.
        ArrayList<Integer> result = new ArrayList<>();

        for (int num : A) {
            result.add(divisors[num]);
        }

        return result;
    }
}

Notice that the sieve calculates the count for each possible number only once. If the input contains duplicates, we can reuse the same precomputed count.

6. Complexity Analysis

Let \(n\) be the array length and \(M\) be its maximum element.

In the sieve approach, each divisor d visits approximately M/d multiples. Therefore, the total number of updates is:

\[\sum_{d=1}^{M}\left\lfloor\frac{M}{d}\right\rfloor = O(M\log M)\]
Approach Time complexity Auxiliary space
Brute force\(O(nM)\)\(O(1)\)
Square-root optimization\(O(n\sqrt{M})\)\(O(1)\)
Sieve of divisors\(O(M\log M+n)\)\(O(M)\)

The sieve also uses \(O(n)\) space for the returned result, which is output space rather than auxiliary space.

Recommendation: Use the sieve approach for this problem because the maximum element is bounded by 10^6, making precomputation practical.

9. Interview Preparation Notes

Key concept to remember: Sieve of divisors — instead of asking which divisors belong to every number individually, iterate over each divisor and update all its multiples.

Common mistakes

  • Counting d and num / d twice when they are equal in the square-root approach.
  • Returning results in sorted order instead of preserving input order.
  • Forgetting that 1 has exactly one positive divisor.
  • Using brute force when the input constraints make it too slow.

Likely interviewer follow-up questions

Q1. Why does the sieve work?

Every positive divisor of a number visits that number as one of its multiples. Thus, each number's count is incremented exactly once for each of its positive divisors.

Q2. What if the array contains many duplicate values?

The sieve calculates each number's divisor count once. Every occurrence can then retrieve the same precomputed result.

Q3. Can we reduce the sieve's space usage?

Yes. If we only need a small number of divisor counts and the maximum value is large, checking divisors up to the square root may use less memory. The best choice depends on the constraints.

Q4. How is this related to the Sieve of Eratosthenes?

Both techniques process a number and its multiples. The prime sieve marks multiples as composite, while this sieve increments divisor counts for multiples.

10. Final Recommendation

For interview preparation, understand all three approaches, but implement the sieve of divisors for these constraints.

  • Time: \(O(M\log M+n)\)
  • Auxiliary space: \(O(M)\)
  • Pattern: Number theory + sieve/precomputation

Remember the core intuition: Every divisor contributes one count to each of its multiples. Precompute those counts once, then answer each array element in \(O(1)\) time.
