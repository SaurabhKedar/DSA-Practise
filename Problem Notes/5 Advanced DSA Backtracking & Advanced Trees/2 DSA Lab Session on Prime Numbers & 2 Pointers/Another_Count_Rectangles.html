Java Algorithm Guide

Another Count Rectangles

Count ordered length-and-breadth choices whose area is strictly below a limit. Sorting makes a linear two-pointer solution possible.

1. Problem Understanding

You are given a sorted array A of distinct positive integers and an integer B, the maximum allowed area. Choose a length and a breadth from A and count all ordered pairs whose product is strictly less than B:

\[A[i] \times A[j] < B\]

Ordered pairs are distinct: (1, 2) and (2, 1) count as two different rectangles. The same number may be chosen for both dimensions, as in (2, 2).

For A = [1, 2] and B = 5:

Length Breadth Area Valid?
111Yes
122Yes
212Yes
224Yes

Answer: 4.

For A = [1, 2] and B = 1, the answer is 0, because even the smallest area, \(1 \times 1 = 1\), is not strictly less than B.

2. Brute-Force Approach

Intuition

Try every possible ordered pair (A[i], A[j]). If its product is less than B, increment the count.

Java code

public class Solution {
    public int solve(int[] A, int B) {
        int n = A.length;
        long count = 0;
        int mod = 1_000_000_007;

        // Try every possible ordered pair.
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {

                // Use long to avoid integer overflow.
                if ((long) A[i] * A[j] < B) {
                    count++;
                }
            }
        }

        return (int) (count % mod);
    }
}

Complexity

  • Time: \(O(N^2)\), because we check all \(N \times N\) pairs.
  • Auxiliary space: \(O(1)\), because we use only a few variables.

With \(N = 10^5\), the nested loops may examine up to \(10^{10}\) pairs, which is too slow.

3. Optimized Approach — Two Pointers

Intuition

Because the array is sorted, we can avoid checking every pair. Start with two pointers:

  • left = 0: the smallest remaining element.
  • right = n - 1: the largest remaining element.

At each step, check the product A[left] * A[right].

Case 1: Product is less than B

Since the array is sorted, every element from A[left] through A[right] can pair with A[left] and satisfy the condition. Count these pairs at once:

\[\text{valid pairs} = 2(right - left) + 1\]

Each element after left forms two ordered pairs with A[left], while (A[left], A[left]) is counted once. Then increment left.

Case 2: Product is greater than or equal to B

The largest remaining element, A[right], cannot form a valid pair with any remaining element, because all those elements are at least A[left]. Therefore, decrement right.

Optimized Java solution

public class Solution {
    public int solve(int[] A, int B) {
        int n = A.length;
        int left = 0;
        int right = n - 1;

        long count = 0;
        final int MOD = 1_000_000_007;

        while (left <= right) {

            // Use long because A[i] can be as large as 10^9.
            long area = (long) A[left] * A[right];

            if (area < B) {

                // Count both ordered pairs for each distinct index,
                // plus the single diagonal pair (A[left], A[left]).
                long pairs = 2L * (right - left) + 1;

                count = (count + pairs) % MOD;

                // The current left element has been fully processed.
                left++;

            } else {

                // The current right element cannot form a valid
                // pair with any remaining element.
                right--;
            }
        }

        return (int) count;
    }
}

5. Complexity Analysis

Approach Time complexity Auxiliary space
Brute force\(O(N^2)\)\(O(1)\)
Two pointers\(O(N)\)\(O(1)\)

In the optimized approach, each iteration moves either left forward or right backward. Neither pointer moves more than \(N\) times, so the total time complexity is \(O(N)\). The solution uses constant extra memory, giving \(O(1)\) auxiliary space.

8. Interview Preparation Notes

Pattern to remember: Sorted array + monotonic condition + two pointers.

Common mistakes

  1. Counting only right - left + 1 misses reversed ordered pairs. Use 2L * (right - left) + 1.
  2. Using <= B is incorrect; the condition is strictly < B.
  3. Multiplying as int can overflow. Cast before multiplication: (long) A[left] * A[right].
  4. Using nested loops is unnecessary; the sorted array lets us count multiple pairs in one step.

Likely follow-up questions

  • Why count both directions? Because (x,y) and (y,x) are distinct configurations.
  • Why is the diagonal counted once? (x,x) is the same ordered pair in either direction.
  • Why move right when the product is too large? No remaining element can pair with the current largest element to produce a smaller product.
  • Can we use binary search? Yes. We can find valid partner ranges for each element in \(O(N \log N)\), but two pointers are more efficient at \(O(N)\).

9. Final Recommendation

Implement the two-pointer solution in interviews. It takes advantage of the sorted array, avoids checking every pair, and handles the constraints efficiently.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(1)\)

One-line intuition: If the smallest remaining element multiplied by the largest remaining element is below B, count every valid ordered pair involving that smallest element at once; otherwise, discard the largest element.
