Pairs with Given Sum II — Java Solution

This problem is a classic Two Pointers problem. Since the array is already sorted, we can count matching pairs efficiently.

  • 1 Brute Force — check every possible pair of distinct indices.
  • 2 Two Pointers — utilize sorted order and count duplicate combinations efficiently. Recommended

1. Problem Understanding

You are given:

  • A: A sorted integer array. Duplicate values are allowed.
  • B: The target sum.

You need to count the number of index pairs $(i,j)$ such that $i \ne j$ and $A[i] + A[j] = B$. Return the answer modulo $10^9+7$.

Important: Different indices count as different pairs, even if their values are identical.

Example:

A = [1, 1, 1]
B = 2

The valid pairs of indices are (0,1), (0,2), and (1,2). Therefore, the answer is 3.

2. Brute Force Approach

Intuition

Check every possible pair of distinct indices. If their sum equals $B$, increment the count.

Java Code

public class Solution {
    public int solve(int[] A, int B) {
        int n = A.length;
        long count = 0;
        long MOD = 1_000_000_007L;

        // Try every possible pair of indices.
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {

                // Check whether the pair has the target sum.
                if ((long) A[i] + A[j] == B) {
                    count++;
                }
            }
        }

        return (int) (count % MOD);
    }
}

Dry Run

For A = [1, 1, 1], B = 2:

i j Sum Count
0 1 1 + 1 = 2 1
0 2 1 + 1 = 2 2
1 2 1 + 1 = 2 3

Final answer: 3.

Complexity & Limitation

  • Time: $O(N^2)$, because we examine every pair.
  • Auxiliary space: $O(1)$, because we use only a few variables.

Limitation: With up to $100,000$ elements, checking every pair is too slow.

3. Optimized Approach — Two Pointers

Intuition

Because the array is sorted, we can use two pointers:

  • left starts at the beginning.
  • right starts at the end.

Calculate $A[left] + A[right]$ and decide what to do:

  1. Sum is smaller than $B$: Move left forward to get a larger value.
  2. Sum is greater than $B$: Move right backward to get a smaller value.
  3. Sum equals $B$: Count all valid pairs formed by the duplicate values at both pointers.

Handling Duplicates

Suppose $A = [1, 1, 1, 3, 3, 3]$ and $B = 4$. There are three occurrences of 1 and three occurrences of 3. Every 1 can pair with every 3, so the number of pairs is:

$$3 imes 3 = 9$$

Now suppose $A = [2, 2, 2, 2]$ and $B = 4$. All four values are equal. The number of distinct index pairs is:

$$\frac{4(4-1)}{2} = 6$$

Java Code

public class Solution {
    public int solve(int[] A, int B) {
        final long MOD = 1_000_000_007L;

        int left = 0;
        int right = A.length - 1;
        long count = 0;

        while (left < right) {
            long sum = (long) A[left] + A[right];

            if (sum < B) {
                // The sum is too small.
                // Increase the left value.
                left++;

            } else if (sum > B) {
                // The sum is too large.
                // Decrease the right value.
                right--;

            } else {
                // We found a valid sum.

                // If both values are equal, every remaining
                // element has this same value.
                if (A[left] == A[right]) {
                    long n = right - left + 1L;

                    // Choose any 2 distinct indices from n.
                    count += n * (n - 1) / 2;
                    count %= MOD;

                    break;
                }

                // Count duplicate occurrences on the left.
                long leftCount = 1;
                while (left + 1 < right
                        && A[left] == A[left + 1]) {
                    leftCount++;
                    left++;
                }

                // Count duplicate occurrences on the right.
                long rightCount = 1;
                while (right - 1 > left
                        && A[right] == A[right - 1]) {
                    rightCount++;
                    right--;
                }

                // Every left occurrence pairs with every
                // right occurrence.
                count = (count + leftCount * rightCount) % MOD;

                // Move past both groups of duplicates.
                left++;
                right--;
            }
        }

        return (int) (count % MOD);
    }
}

Why use long? The number of pairs can exceed Java's int range before the modulo is applied. Using long prevents overflow in pair-count calculations.

4. Dry Run of the Optimized Solution

Input: A = [1, 1, 2, 2, 3, 3], B = 4. Initially, left = 0, right = 5, and count = 0.

Step Left Value Right Value Sum Action
1 1 3 4 Count 2 ones × 2 threes (= 4 pairs)
2 2 2 4 Two remaining twos: $2(2-1)/2 = 1$ pair

Final count: $4 + 1 = \mathbf{5}$.

5. Complexity Analysis

Approach Time Complexity Auxiliary Space
Brute Force $O(N^2)$ $O(1)$
Two Pointers $O(N)$ $O(1)$

Why is the optimized approach $O(N)$? Each pointer (left and right) traverses the array at most once. Duplicate-counting loops move pointers inward without redundant re-scanning, requiring no extra data structures.

8. Interview Preparation Notes

Key Pattern:

Sorted array + two pointers + duplicate counting.

Common Interviewer Follow-ups

Q1. Why not use a HashMap?

A HashMap can solve a general two-sum problem in expected $O(N)$ time, but the sorted array lets us use two pointers with $O(1)$ auxiliary space.

Q2. Why multiply the duplicate frequencies?

Every occurrence of the left value can pair with every occurrence of the right value, so the number of pairs is leftCount * rightCount.

Q3. Why use combinations when both values are equal?

Because we must select two distinct indices from the same group of $k$ occurrences. The number of ways is $k(k-1)/2$.

Q4. Why take modulo $10^9+7$?

The total number of pairs can be very large. Modulo keeps the result within the required range while preserving the requested answer.

9. Final Recommendation

Use the Two-Pointer Approach in Interviews

  • Time: $O(N)$
  • Auxiliary space: $O(1)$

Core rule to remember:

If the sum is too small, move left; if too large, move right; if equal, count all combinations of matching duplicates.

Finding a matching sum and counting every matching index pair are different tasks. Handling duplicates correctly is what makes this solution complete.
