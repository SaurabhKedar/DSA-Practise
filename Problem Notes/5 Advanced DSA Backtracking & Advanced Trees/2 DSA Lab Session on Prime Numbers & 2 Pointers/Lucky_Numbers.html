Java Algorithm Guide

Lucky Numbers — Java Solution

Count the numbers from 1 through A that have exactly two distinct prime factors. A modified Sieve of Eratosthenes counts those factors efficiently.

1. Problem Understanding

A number is called a lucky number if it has exactly two distinct prime factors. Given an integer A, count how many lucky numbers exist from 1 to A, including both endpoints.

Examples:

  • 6 = 2 × 3 → two distinct prime factors, 2 and 3 → Lucky.
  • 10 = 2 × 5 → two distinct prime factors, 2 and 5 → Lucky.
  • 12 = 2 × 2 × 3 → two distinct prime factors, 2 and 3 → Lucky. Repeated factors count only once.
  • 8 = 2 × 2 × 2 → only one distinct prime factor, 2 → Not lucky.
  • 30 = 2 × 3 × 5 → three distinct prime factors → Not lucky.

Constraint: \(1 \le A \le 50000\).

2. Brute Force Approach

Intuition

Check every number from 1 to A. For each number, find its prime factors and count how many are distinct. If the count is exactly 2, increase the answer.

Algorithm

  1. Iterate through every number num from 1 to A.
  2. Find its distinct prime factors by checking possible divisors.
  3. Count each prime factor only once, even if it divides the number repeatedly.
  4. If the number has exactly two distinct prime factors, increment the result.
  5. Return the result.

Brute-force Java code

public class Solution {
    public int solve(int A) {
        int luckyCount = 0;

        // Check every number from 1 to A.
        for (int num = 1; num <= A; num++) {
            int distinctFactors = 0;
            int remaining = num;

            // Try dividing by every possible divisor.
            for (int divisor = 2; divisor <= remaining; divisor++) {
                if (remaining % divisor == 0) {
                    distinctFactors++;

                    // Remove all occurrences of this factor.
                    while (remaining % divisor == 0) {
                        remaining /= divisor;
                    }
                }
            }

            if (distinctFactors == 2) {
                luckyCount++;
            }
        }

        return luckyCount;
    }
}

Complexity analysis

  • Time: \(O(A\sqrt A)\) is a typical optimized bound for trial division up to the square root. The exact code above can take \(O(A^2)\) in the worst case because its divisor loop does not stop at the square root.
  • Auxiliary space: \(O(1)\).

The brute-force method repeats factorization for every number, so we can do better.

3. Optimized Approach — Sieve of Eratosthenes

The recommended approach counts the distinct prime factors of every number at once using a modified sieve.

Intuition

Instead of finding the prime factors of each number separately, identify prime numbers and visit all their multiples. For each prime p, increment the prime-factor count of p, 2*p, 3*p, 4*p, .... Each prime contributes exactly once to each multiple, regardless of how many times that prime divides the multiple.

For example, prime 2 contributes to 2, 4, 6, 8, 10, 12...; prime 3 contributes to 3, 6, 9, 12....

Algorithm

  1. Create an integer array primeFactors of size A + 1, initialized to zero.
  2. Iterate through each number p from 2 to A.
  3. If primeFactors[p] == 0, then p is prime because no smaller prime has marked it as a multiple.
  4. Increment the count for every multiple of p.
  5. Count all numbers whose factor count equals 2.
  6. Return the total.

Optimized Java solution

public class Solution {
    public int solve(int A) {
        // primeFactors[i] stores the number of distinct
        // prime factors of i.
        int[] primeFactors = new int[A + 1];

        // Find primes and count their contribution
        // to every multiple.
        for (int p = 2; p <= A; p++) {

            // A zero count means p is prime.
            if (primeFactors[p] == 0) {

                // Each multiple of p gets one additional
                // distinct prime factor.
                for (int multiple = p;
                     multiple <= A;
                     multiple += p) {

                    primeFactors[multiple]++;
                }
            }
        }

        int luckyCount = 0;

        // Count numbers having exactly two distinct
        // prime factors.
        for (int num = 2; num <= A; num++) {
            if (primeFactors[num] == 2) {
                luckyCount++;
            }
        }

        return luckyCount;
    }
}

5. Complexity Analysis

Let \(A\) be the input number.

Time and auxiliary-space complexities of the two approaches
Approach Time complexity Auxiliary space
Brute force, as coded\(O(A^2)\) worst case\(O(1)\)
Modified sieve\(O(A\log\log A)\)\(O(A)\)

Why is the sieve efficient?

The inner loop visits multiples of each prime p. The total number of updates is approximately:

\[A\sum_{\substack{p\text{ prime}\\p\le A}}\frac{1}{p} = O(A\log\log A).\]

The array stores one integer per number, requiring \(O(A)\) auxiliary space.

6. Edge Cases

  • A = 1: No lucky numbers; return 0.
  • A = 2 or A = 3: Both are prime, so each has only one distinct prime factor; return 0.
  • A = 4: The number 4 has only one distinct prime factor; return 0.
  • A = 6: Only 6 is lucky; return 1.
  • A = 12: 6, 10, and 12 are lucky; return 3.
  • A = 50000: The sieve comfortably handles the maximum constraint.

8. Interview Preparation Notes

Key pattern: Modified Sieve of Eratosthenes. Remember that a prime number contributes exactly one distinct prime factor to each of its multiples.

Common mistakes

  • Counting repeated factors multiple times. For example, 12 = 2 × 2 × 3 has only two distinct prime factors.
  • Treating every number with a nonzero count as prime. A number is prime in this sieve precisely when its count is still zero when visited.
  • Starting the multiple loop at p * p without also accounting for p itself. This implementation starts at p, which keeps the logic straightforward.

Likely interview follow-ups

Q1. Why does primeFactors[p] == 0 identify a prime?

Every composite number has a prime divisor smaller than itself, so that smaller prime would already have incremented its count.

Q2. Why do repeated powers not increase the count multiple times?

Each prime is processed once, and its multiples are visited once during that prime's iteration.

Q3. Can we reduce memory usage?

The array uses \(O(A)\) space. Since we need factor counts for every number up to A, this is a practical choice.

9. Final Recommendation

Use the modified sieve in an interview. It processes all numbers together instead of repeatedly factoring each number.

  • Time: \(O(A\log\log A)\)
  • Auxiliary space: \(O(A)\)
  • Core intuition: Find each prime once and increment the count of all its multiples. Numbers with a final count of exactly 2 are lucky numbers.
