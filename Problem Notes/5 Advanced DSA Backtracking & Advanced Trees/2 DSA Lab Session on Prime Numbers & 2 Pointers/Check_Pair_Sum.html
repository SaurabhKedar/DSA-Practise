Check Pair Sum — Java Solution

We can solve this problem using three approaches:

  • 1 Brute Force — check every possible pair.
  • 2 HashSet — store previously seen elements and check for complement. Recommended
  • 3 Two Pointers — sort the array and move pointers based on current sum.

1. Problem Understanding

You are given:

  • A: the target sum.
  • B: an integer array.

Return 1 if two elements at different indices add up to A. Otherwise, return 0.

Example 1:

A = 8
B = [3, 5, 1, 2, 1, 2]

The pair 3 + 5 = 8, so the answer is 1.

Example 2:

A = 21
B = [9, 10, 7, 10, 9, 1, 5, 1, 5]

No pair adds up to 21, so the answer is 0.

Important condition: You cannot use the same array element twice. For example, if A = 10 and B = [5], the answer is 0, because there is only one occurrence of 5.

2. Approach 1: Brute Force

Intuition

Check every possible pair of elements in the array. For each element at index i, check every element after it at index j. If their sum equals A, return 1 immediately. If no pair works, return 0.

Java Code

public class Solution {
    public int solve(int A, int[] B) {
        int n = B.length;

        // Select the first element of the pair.
        for (int i = 0; i < n; i++) {

            // Select a different element after index i.
            for (int j = i + 1; j < n; j++) {

                // Check whether the pair gives the target sum.
                if (B[i] + B[j] == A) {
                    return 1;
                }
            }
        }

        // No valid pair was found.
        return 0;
    }
}

Dry Run

For A = 8 and B = [3, 5, 1, 2, 1, 2]:

i j Pair Sum Result
0 1 (3, 5) 8 Return 1

We find the answer in the first comparison, so the remaining pairs do not need to be checked.

Complexity Analysis

  • Time: \(O(N^2)\) in the worst case because we check all possible pairs.
  • Auxiliary space: \(O(1)\) because we use only a few variables.

Limitation: For an array of \(10^5\) elements, checking every pair can require billions of comparisons in the worst case.

3. Approach 2: HashSet — Recommended

Intuition

Instead of repeatedly searching the array for a matching element, remember the elements we have already visited in a HashSet. For every element \(x\), calculate the complement:

\[\text{complement} = A - x\]

If the complement is already in the set, we have found a valid pair. Otherwise, add \(x\) to the set and continue. The key is to check before inserting the current element. This ensures that an element cannot pair with itself unless another occurrence exists at a different index.

Algorithm

  1. Create an empty HashSet<Integer>.
  2. Iterate through every element \(x\) in \(B\).
    • Calculate \(A - x\).
    • If the set contains \(A - x\), return 1.
    • Otherwise, insert \(x\) into the set.
  3. If the loop finishes without finding a pair, return 0.

Java Code

import java.util.HashSet;

public class Solution {
    public int solve(int A, int[] B) {

        // Store elements that have already been visited.
        HashSet<Integer> seen = new HashSet<>();

        for (int x : B) {

            // Find the element needed to reach the target sum.
            int complement = A - x;

            // If it was seen earlier, a valid pair exists.
            if (seen.contains(complement)) {
                return 1;
            }

            // Store the current element for future comparisons.
            seen.add(x);
        }

        // No valid pair was found.
        return 0;
    }
}

Dry Run of the HashSet Approach

Input: A = 8, B = [3, 5, 1, 2, 1, 2]. Initially, seen = {}.

Current \(x\) Complement (\(A - x\)) Is complement in set? Set after processing
3 5 No {3}
5 3 Yes {3}

When \(x = 5\), the set already contains 3. Since \(3 + 5 = 8\), return 1. Notice that we do not need to store 5 before returning.

Why Does This Approach Work?

For every element \(x\), there is exactly one value needed to complete the sum: \(A - x\). If that value has already appeared, we have a valid pair at two different indices. If it has not appeared, storing \(x\) allows a future element to match it.

Complexity Analysis

  • Time: \(O(N)\) average, because HashSet insertion and lookup take \(O(1)\) average time per element.
  • Auxiliary space: \(O(N)\) worst case, because the set may store all elements.

Note: HashSet operations have \(O(N)\) worst-case time under pathological collision scenarios, but \(O(N)\) average total time is the standard expected complexity.

4. Approach 3: Two Pointers

Intuition

The two-pointer technique works most naturally on a sorted array. Use two pointers:

  • left starts at the beginning.
  • right starts at the end.

Calculate the sum of the elements at those positions:

  • If the sum equals A, return 1.
  • If the sum is smaller than A, move left forward to get a larger value.
  • If the sum is greater than A, move right backward to get a smaller value.

Why sort the array? Sorting makes these pointer movements predictable. Without sorting, moving a pointer would not guarantee that the sum increases or decreases.

Java Code

import java.util.Arrays;

public class Solution {
    public int solve(int A, int[] B) {

        // Copy the array so the original input remains unchanged.
        int[] sorted = B.clone();

        // Two pointers require a sorted array.
        Arrays.sort(sorted);

        int left = 0;
        int right = sorted.length - 1;

        while (left < right) {

            int sum = sorted[left] + sorted[right];

            // The target sum has been found.
            if (sum == A) {
                return 1;
            }

            // The sum is too small; increase the left value.
            else if (sum < A) {
                left++;
            }

            // The sum is too large; decrease the right value.
            else {
                right--;
            }
        }

        // The pointers met without finding a valid pair.
        return 0;
    }
}

Dry Run of the Two Pointers Approach

Input: A = 8, B = [3, 5, 1, 2, 1, 2]. After sorting: sorted = [1, 1, 2, 2, 3, 5]

Step left right Values Sum Action
1 0 5 1 + 5 6 Sum too small; left++
2 1 5 1 + 5 6 Sum too small; left++
3 2 5 2 + 5 7 Sum too small; left++
4 3 5 2 + 5 7 Sum too small; left++
5 4 5 3 + 5 8 Return 1

The pair is found when left = 4 and right = 5.

Why Must We Use left < right?

The condition ensures that both pointers refer to different positions. If we used left <= right, the algorithm could incorrectly use the same element twice.

Complexity Analysis

  • Sorting time: \(O(N \log N)\).
  • Two-pointer traversal: \(O(N)\), because each pointer moves in only one direction.
  • Total time: \(O(N \log N)\).
  • Auxiliary space: \(O(N)\) for the copied array, plus the sorting implementation's internal space.

If you sort the original array instead of cloning it, you avoid the \(O(N)\) copy space, but you modify the input array.

All three approaches handle these valid inputs correctly.

8. Interview Preparation Notes

Key Patterns to Remember

  • Brute force: nested loops to explore every pair.
  • HashSet: complement lookup, often the best approach for unsorted pair-sum problems.
  • Two pointers: sort first, then move pointers based on the sum.

Common Interviewer Follow-ups

Q1. Why do we check the HashSet before inserting the current element?

To guarantee that the matching element comes from a different index.

Q2. Why is HashSet generally faster than two pointers here?

HashSet takes \(O(N)\) average time without sorting, while two pointers need \(O(N \log N)\) time for sorting an unsorted array.

Q3. Can we use a HashMap instead?

Yes. A HashMap can store each number and its index. For this problem, a HashSet is simpler because we only need to know whether the complement exists.

Q4. Can two pointers work without sorting?

Not reliably. The array must be sorted for pointer movements to eliminate possibilities safely.

9. Final Recommendation

Implement the HashSet Approach in an Interview

  • Time: \(O(N)\) average.
  • Auxiliary space: \(O(N)\).

Remember the core idea:

For every number \(x\), look for \(A - x\) among the numbers already seen. If it exists, return 1; otherwise, store \(x\) and continue.

This complement-search pattern is one of the most important techniques for solving pair-sum problems efficiently.
