Closest Pair from Sorted Arrays — Java Solution

Since both arrays are sorted, the Two Pointers technique can find a close pair in \(O(N+M)\) time instead of checking every possible pair. The binary-search solution below directly and transparently enforces the required tie-breaking rules.

Core pattern: For each value in one sorted array, binary-search the other array for the target complement and inspect the nearest candidates.

1. Problem Understanding

You are given:

  • A: a sorted array of distinct integers.
  • B: another sorted array of distinct integers.
  • C: the target sum.

Choose one element from each array so their sum is as close as possible to C. The difference for a pair of indices i and j is:

\[\text{difference}=\left|A[i]+B[j]-C\right|\]

If multiple pairs have the same minimum difference:

  1. Choose the pair with the smallest index i in A.
  2. If i is the same, choose the smallest index j in B.

Return the values of the selected pair, not their indices.

Example

Input

A = [1, 2, 3, 4, 5]
B = [2, 4, 6, 8]
C = 9
Pair Sum Difference from 9
[1, 8]90
[3, 6]90
[5, 4]90

All three pairs have the same minimum difference. The pair [1, 8] wins because A[0] has the smallest index.

Output: [1, 8]

2. Brute Force Approach

Intuition

Try every possible pair by selecting each element from A and pairing it with every element from B.

For each pair:

  1. Calculate its sum.
  2. Calculate the absolute difference from C.
  3. If the difference is smaller than the best difference so far, update the answer.
  4. Iterating through A and then B in increasing index order means keeping the first pair on equal differences preserves the tie-breaking rules.

Java code — brute force

public class Solution {
    public int[] solve(int[] A, int[] B, int C) {
        int n = A.length;
        int m = B.length;

        int minDiff = Integer.MAX_VALUE;
        int[] answer = new int[2];

        // Try every possible pair, preserving index order.
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                int sum = A[i] + B[j];
                int diff = Math.abs(sum - C);

                // Strictly smaller: preserve the first pair on ties.
                if (diff < minDiff) {
                    minDiff = diff;
                    answer[0] = A[i];
                    answer[1] = B[j];
                }
            }
        }

        return answer;
    }
}

Complexity analysis

  • Time: \(O(N \times M)\), because every element of A is paired with every element of B.
  • Auxiliary space: \(O(1)\), using a fixed number of variables and a two-element answer array.
Limitation: If both arrays contain \(10^5\) elements, this approach can require \(10^{10}\) pair checks, which is too slow.

3. Optimized Approach — Two Pointers

Intuition

Because both arrays are sorted, start one pointer at each end:

  • i = 0: start at the smallest element of A.
  • j = B.length - 1: start at the largest element of B.

Use the current sum to decide which pointer to move:

  • If sum == C: the difference is zero, so save the pair and stop; no pair can improve upon zero.
  • If sum > C: the sum is too large, so decrease j to select a smaller element from B.
  • If sum < C: the sum is too small, so increase i to select a larger element from A.

When updating the answer, equal differences must prefer the smaller i, then the smaller j. However, stopping at the first exact sum can miss an exact-sum pair with a smaller i. The implementation below is useful for illustrating the scan, but the recommended solution afterward avoids that issue.

Java solution — two-pointer scan

public class Solution {
    public int[] solve(int[] A, int[] B, int C) {
        int n = A.length;
        int m = B.length;

        int i = 0;       // Start of A
        int j = m - 1;   // End of B

        int minDiff = Integer.MAX_VALUE;
        int bestI = 0;
        int bestJ = 0;

        while (i < n && j >= 0) {
            int sum = A[i] + B[j];
            int diff = Math.abs(sum - C);

            // Prefer a smaller difference, then smaller indices.
            if (diff < minDiff ||
                (diff == minDiff &&
                 (i < bestI || (i == bestI && j < bestJ)))) {

                minDiff = diff;
                bestI = i;
                bestJ = j;
            }

            // An exact sum cannot be improved.
            if (sum == C) {
                break;
            } else if (sum > C) {
                j--;
            } else {
                i++;
            }
        }

        return new int[] { A[bestI], B[bestJ] };
    }
}

4. Recommended Implementation — Binary Search

For each A[i], find the position in B where C - A[i] would fit. Only the value at that insertion point and its predecessor can be the closest candidates for that A[i].

Process A from left to right. Retain the first i when minimum differences tie. For a given i, check the predecessor before the insertion-point value so an equal difference keeps the smaller j. 

public class Solution {
    public int[] solve(int[] A, int[] B, int C) {
        int minDiff = Integer.MAX_VALUE;
        int[] answer = new int[2];

        for (int i = 0; i < A.length; i++) {
            // Find the first index in B whose value is
            // greater than or equal to C - A[i].
            long target = (long) C - A[i];
            int left = 0;
            int right = B.length;

            while (left < right) {
                int mid = left + (right - left) / 2;

                if (B[mid] < target) {
                    left = mid + 1;
                } else {
                    right = mid;
                }
            }

            // Check the predecessor first so smaller j wins equal differences.
            if (left > 0) {
                int sum = A[i] + B[left - 1];
                int diff = Math.abs(sum - C);

                if (diff < minDiff) {
                    minDiff = diff;
                    answer[0] = A[i];
                    answer[1] = B[left - 1];
                }
            }

            // Check the first value greater than or equal to target.
            if (left < B.length) {
                int sum = A[i] + B[left];
                int diff = Math.abs(sum - C);

                if (diff < minDiff) {
                    minDiff = diff;
                    answer[0] = A[i];
                    answer[1] = B[left];
                }
            }

            // A is processed in increasing index order.
            if (minDiff == 0) {
                return answer;
            }
        }

        return answer;
    }
}

Why the tie-breaking works

  • A is processed in increasing index order, and equal differences do not overwrite the current answer, so the smallest i is kept.
  • For one A[i], the closest candidates in B are at the insertion point or immediately before it.
  • The predecessor has the smaller index and is checked first, so it remains selected if both candidates have equal differences.
  • An exact sum allows an immediate return: the first exact sum has the smallest possible i, and the insertion point is the smallest j with that exact value.

6. Complexity Analysis

Let \(N\) be the length of A and \(M\) be the length of B.

Approach Time complexity Auxiliary space
Brute force\(O(NM)\)\(O(1)\)
Two pointers\(O(N+M)\)\(O(1)\)
Recommended binary search\(O(N\log M)\)\(O(1)\)

The binary-search solution uses constant extra working memory. The returned two-element array is output space.

7. Edge Cases

  • Single element in each array: the only possible pair is returned.
  • Target smaller than every possible sum: the smallest available sum is selected.
  • Target larger than every possible sum: the largest available sum is selected.
  • Multiple pairs with equal differences: the smallest i wins, followed by the smallest j.
  • Exact target sum: return the earliest valid pair according to the tie-breaking rules.
  • Large values: the given constraints keep pair sums within Java's int range. The binary-search target uses long for safer arithmetic.

9. Interview Preparation Notes

Pattern to remember: Sorted input often allows two pointers or binary search to avoid checking every pair.

Common mistakes

  • Returning indices instead of values.
  • Overwriting an answer when the difference ties.
  • Breaking on the first exact sum without checking whether an earlier i could produce an exact sum.
  • Checking only one side of a binary-search insertion point.

Likely interviewer follow-ups

  • Why does binary search work here? Because B is sorted, and the closest value to a target must be at the insertion point or immediately before it.
  • Can we achieve \(O(N+M)\)? Yes, a carefully implemented two-pointer scan can do so while explicitly enforcing the tie-breaking rules.
  • Why not use brute force? It takes \(O(NM)\) time, which is too expensive for arrays of size \(10^5\).

10. Final Recommendation

For a beginner, first understand the two-pointer intuition. For a solution that directly and transparently preserves the tie-breaking rules, the binary-search implementation is a reliable choice.

  • Recommended time: \(O(N\log M)\).
  • Auxiliary space: \(O(1)\).
  • Core intuition: for each element in A, binary-search B for the target complement and inspect the two nearest candidates.
