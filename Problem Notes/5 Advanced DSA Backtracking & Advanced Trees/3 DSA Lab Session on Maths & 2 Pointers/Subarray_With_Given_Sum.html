Java Algorithm Guide

Subarray with Given Sum

This is a classic sliding-window and two-pointers problem because all array elements are positive integers. Maintain a contiguous window and adjust its sum until it equals the target, achieving \(O(N)\) time.

Recommended pattern: Expand the window when its sum is too small, shrink it when its sum is too large, and return the first match.

1. Problem Understanding

You are given:

  • A: an array of positive integers.
  • B: the target sum.

Return the first continuous subarray whose sum is B. Elements must be contiguous; if multiple subarrays match, return the one with the smallest starting index. Return the actual elements, not their indices. If no subarray matches, return [-1].

Example

A = [1, 2, 3, 4, 5]
B = 5

The subarray [2, 3] sums to \(2+3=5\), so the answer is [2, 3]. Although [5] also sums to 5, [2, 3] starts earlier and is the correct answer.

2. Brute Force Approach

Intuition

Try every possible starting index. From each start, add following elements until the sum equals B, exceeds B, or the array ends. Since every element is positive, stop exploring a start as soon as its sum exceeds the target.

Java code

public class Solution {
    public int[] solve(int[] A, int B) {
        int n = A.length;

        // Try every possible starting index.
        for (int start = 0; start < n; start++) {
            long sum = 0;

            // Extend the subarray from this starting index.
            for (int end = start; end < n; end++) {
                sum += A[end];

                if (sum == B) {
                    // Copy the matching elements into the returned array.
                    int[] result = new int[end - start + 1];
                    for (int k = start; k <= end; k++) {
                        result[k - start] = A[k];
                    }
                    return result;
                }

                // Positive elements make the sum increase, so this start cannot match.
                if (sum > B) {
                    break;
                }
            }
        }

        // No matching subarray exists.
        return new int[]{-1};
    }
}

Time complexity

\(O(N^2)\) in the worst case, because many possible subarrays may be explored.

Auxiliary space

\(O(1)\), excluding the returned array, which can require \(O(N)\) space.

Limitation: For \(N=100000\), checking every possible subarray can be too slow.

3. Optimized Approach — Sliding Window

Intuition

Maintain one window with two pointers and the sum of its elements:

  • left: starting index of the current window.
  • right: ending index of the current window.
  • sum: sum of the elements inside the window.

Example window

For A = [1, 2, 3, 4, 5] and B = 5:

Window: [2, 3] → Sum = 5

  • If sum < B, expand the window by moving right.
  • If sum > B, shrink the window by moving left.
  • If sum == B, return the elements in the window.

This works because every element is positive: adding one increases the sum, and removing one decreases it. Therefore, the window can be adjusted without checking every possible subarray.

Step-by-step algorithm

  1. Initialize left = 0 and sum = 0.
  2. Move right from the beginning to the end of the array.
  3. Add A[right] to sum.
  4. While sum > B, subtract A[left] and increment left.
  5. If sum == B, copy the window into a result array and return it.
  6. If no matching window exists, return [-1].

Complete Java solution

public class Solution {
    public int[] solve(int[] A, int B) {
        int n = A.length;
        int left = 0;
        long sum = 0;

        // Expand the window by moving right through the array.
        for (int right = 0; right < n; right++) {
            sum += A[right];

            // Remove elements from the left while the window is too large.
            while (sum > B && left <= right) {
                sum -= A[left];
                left++;
            }

            // Return the first matching contiguous subarray.
            if (sum == B) {
                int length = right - left + 1;
                int[] result = new int[length];

                // Copy the matching window's values, not its indices.
                for (int i = 0; i < length; i++) {
                    result[i] = A[left + i];
                }

                return result;
            }
        }

        // No matching subarray exists.
        return new int[]{-1};
    }
}

Important: The running sum uses long because the sum of many array elements can exceed the range of an int.

5. Complexity Analysis

Approach Time complexity Auxiliary space
Brute force\(O(N^2)\)\(O(1)\)
Sliding window\(O(N)\)\(O(1)\)

The returned array requires up to \(O(N)\) space in either approach. Although the sliding-window algorithm has a nested while loop, each pointer moves only forward: right advances at most \(N\) times, and left also advances at most \(N\) times. The total work is linear.

8. Interview Preparation Notes

Pattern to remember: variable-size sliding window with two pointers.

Common mistakes

  • Using sliding window when negative numbers are allowed. Negative values can make the sum increase or decrease unpredictably, so this technique is not generally valid for arbitrary signed arrays.
  • Returning the indices instead of the actual elements.
  • Forgetting to shrink the window when its sum exceeds the target.
  • Using int for a running sum when it can overflow.

Likely interviewer follow-up questions

Q1. Why does sliding window work here?

Because every element is positive, expanding increases the sum and shrinking decreases it.

Q2. Can we use prefix sums?

Yes. Prefix sums combined with a suitable search strategy can solve related problems, but sliding window is simpler and runs in \(O(N)\) here.

Q3. What if negative numbers are allowed?

A standard sliding window is no longer reliable. A prefix-sum plus hash map approach is often appropriate for finding a subarray with a target sum.

Q4. Why return immediately after finding a match?

The window advances from left to right. If a valid subarray with an earlier starting index existed, it would have been detected before the current window. Returning immediately therefore respects the minimum-start-index requirement.

9. Final Recommendation

Use the sliding-window approach in an interview. It is straightforward, efficient, and takes advantage of the positive-integer constraint.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(1)\), excluding the returned array
  • Core intuition: expand when the sum is too small; shrink when it is too large; return when it matches.

Remember: positive numbers + continuous subarray + target sum = consider sliding window first.
