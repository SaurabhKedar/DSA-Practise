Excel Column Title — Java Solution

The key concept is base-26 conversion with a small adjustment. Excel columns start from 1 instead of 0, so subtracting one before each remainder calculation maps the letters correctly.

Core idea: Repeatedly decrement the number, use its remainder modulo 26 to select a letter, divide by 26, and reverse the letters at the end.

1. Problem understanding

  • Input: A positive integer A, where \(1 \le A \le 10^9\).
  • Output: A string representing the Excel column title.
  • Important condition: After Z, the sequence continues with AA, AB, and so on.

Examples:

  • Input: 3 → Output: "C"
  • Input: 27 → Output: "AA"

2. Brute-force approach

One possible approach is to build the column titles sequentially, starting from A, then B, and continuing until we reach the required number.

This is highly inefficient because A can be as large as \(10^9\). Generating every previous title would require an enormous number of operations.

Limitation: Time complexity is at least \(O(A)\), making this approach impractical for large inputs. We should instead calculate each character directly using division and remainder.

3. Optimized approach — Base-26 conversion

Intuition

Excel uses 26 letters, from A to Z, similar to a base-26 number system. The challenge is that normal base-26 digits range from 0 to 25, but Excel letters correspond to 1 to 26.

We solve this by subtracting 1 before calculating the remainder:

  • A-- adjusts the number to a zero-based range.
  • A % 26 identifies the current character, from A to Z.
  • A / 26 moves to the next position.
  • reverse() restores the correct character order because we build the title from right to left.

Java solution

public class Solution {
    public String convertToTitle(int A) {
        StringBuilder result = new StringBuilder();

        while (A > 0) {
            A--; // Convert to zero-based indexing

            int remainder = A % 26;

            // Map 0 to A, 1 to B, ..., 25 to Z
            char ch = (char) ('A' + remainder);
            result.append(ch);

            // Move to the next position
            A = A / 26;
        }

        // Characters were generated from right to left
        return result.reverse().toString();
    }
}

Algorithm step by step

  1. Create an empty StringBuilder to store the characters.
  2. While A > 0, subtract 1 from A.
  3. Calculate A % 26 to find the current letter.
  4. Convert the remainder into a character using 'A' + remainder.
  5. Append the character to the result.
  6. Divide A by 26 to process the next position.
  7. Reverse the result and return it.

4. Dry run of the optimized solution

Let's trace the example \(A = 27\). Initially, result = "".

Iteration A before decrement A after decrement Remainder Character A after division
127260A1
2100A0

After the loop:

  • result = "AA" because characters were appended in reverse order.
  • Reversing "AA" still gives "AA", so the final output is "AA".

Another example: \(A = 52\)

Iteration A after decrement Remainder Character
15125Z
210A

The generated string is "ZA". Reversing it gives "AZ", the correct Excel column title for 52.

Why is A-- necessary?

This is the most important trick in the problem. If we calculate 27 % 26, we get 1, corresponding to B. But 27 should begin with A, because the first 26 columns are A through Z.

\[(27-1)\bmod 26 = 0\]

Remainder 0 maps to A.

Without this adjustment, boundary cases such as 26, 27, and 52 would be handled incorrectly.

5. Complexity analysis

Let \(L\) be the number of characters in the resulting title.

Approach Time complexity Auxiliary space
Brute force: generate titles sequentially \(O(A \log A)\) or worse, depending on implementation Depends on implementation
Optimized: repeated division by 26 \(O(\log_{26} A)\) \(O(1)\), excluding output
  • Time: Each iteration divides A by 26, so the number of iterations is \(O(\log_{26} A)\).
  • Space: The StringBuilder stores \(L\) characters, requiring \(O(L)\) output space. The additional working variables use \(O(1)\) space.

Since \(L = O(\log_{26} A)\), the total space including the output is \(O(\log_{26} A)\).

8. Interview preparation notes

Pattern to remember: Number-system conversion using modulo and division.

Common mistakes

  • Forgetting A-- before calculating the remainder.
  • Forgetting to reverse the generated characters.
  • Using a data type too small for the maximum input. Java's int is sufficient here because \(10^9\) is within its range.

Likely interviewer follow-up questions

  • Why do we reverse the result? We calculate the least significant position first, so characters are generated right to left.
  • Why not use ordinary base-26 conversion? Excel columns are effectively one-indexed, unlike ordinary positional digits.
  • Can we solve it recursively? Yes. We can recursively process the quotient and append the current character, but iteration avoids recursive call-stack space.

9. Final recommendation

Use the optimized Java solution in an interview. It processes each character position directly rather than generating previous column titles.

  • Time complexity: \(O(\log_{26} A)\)
  • Auxiliary space: \(O(1)\), excluding the output string.
  • Core intuition: Subtract 1, take the remainder modulo 26 to get a letter, divide by 26, repeat, and reverse the result.
Remember: The one-line trick that makes this problem work is A--; before A % 26.
