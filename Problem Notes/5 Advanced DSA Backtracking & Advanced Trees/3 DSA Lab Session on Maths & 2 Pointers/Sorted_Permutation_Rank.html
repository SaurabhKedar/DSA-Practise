Sorted Permutation Rank

This problem uses permutations, factorials, and lexicographical ordering. The key idea is to count how many permutations would appear before the given string, one character at a time.

1. Problem Understanding

You are given a string A containing unique characters. Find its position (rank) when all its permutations are arranged in dictionary order.

  • The first permutation has rank 1, not 0.
  • Characters are sorted lexicographically, just like words in a dictionary.
  • Return the answer modulo 1000003.
  • The string can have up to 1000 characters.

Example: A = "acb"

Answer: A = "acb" has rank 2.

2. Brute Force Approach

The simplest approach is to generate every permutation, sort all permutations lexicographically, and find the position of the original string.

Steps

  1. Generate all permutations of the string.
  2. Sort them lexicographically.
  3. Find the index of A.
  4. Return the index plus 1.

Why is it inefficient?

For a string of length \(N\), there are \(N!\) permutations. Generating and sorting them becomes impossible for large strings, especially when \(N\) can be 1000.

  • Time complexity: at least \(O(N \cdot N!)\) to generate the permutations, excluding sorting overhead.
  • Space complexity: \(O(N \cdot N!)\) to store all permutations.

This approach is useful for understanding the problem, but not for implementation under the given constraints.

3. Optimized Approach — Counting Smaller Characters

Instead of generating every permutation, calculate how many permutations appear before A at each position.

Intuition

Consider A = "acb".

At the first position, the character is a. No character to its right is smaller than a, so no permutation starts with a smaller character.

At the second position, the character is c. The remaining character b is smaller than c.

If we place b at this position instead of c, the remaining characters can be arranged in \(1! = 1\) way.

So, one permutation comes before "acb": "abc".

The rank starts at 1, so the final answer is 1 + 1 = 2.

The key formula

For every position \(i\):

\[ \text{contribution} = \text{smaller characters to the right} \times (N-i-1)! \]

Add each contribution to the rank, starting from 1.

Algorithm

  1. Precompute factorials modulo 1000003.
  2. Initialize rank = 1.
  3. For each character, count the smaller characters appearing to its right.
  4. Multiply that count by the factorial of the number of remaining positions.
  5. Add the contribution to the rank modulo 1000003.
  6. Return the final rank.

4. Complete Java Solution

public class Solution {
    public int findRank(String A) {
        int n = A.length();
        int MOD = 1000003;

        // Precompute factorials modulo MOD.
        long[] fact = new long[n + 1];
        fact[0] = 1;

        for (int i = 1; i <= n; i++) {
            fact[i] = (fact[i - 1] * i) % MOD;
        }

        // Rank is 1-based.
        long rank = 1;

        // Examine each character from left to right.
        for (int i = 0; i < n; i++) {
            int smaller = 0;

            // Count characters smaller than A.charAt(i)
            // among the characters to its right.
            for (int j = i + 1; j < n; j++) {
                if (A.charAt(j) < A.charAt(i)) {
                    smaller++;
                }
            }

            // Each smaller character can begin a block
            // of (n - i - 1)! permutations.
            long contribution =
                (smaller * fact[n - i - 1]) % MOD;

            rank = (rank + contribution) % MOD;
        }

        return (int) rank;
    }
}

Why does this work?

Suppose we are at position i. If a smaller remaining character were placed there, it would make the resulting string lexicographically smaller than the given string.

For each such character, the remaining \(N-i-1\) characters can be arranged in \((N-i-1)!\) ways.

Because all characters are distinct, each possible smaller character produces a separate block of permutations. Adding the sizes of these blocks across every position counts exactly the permutations before A.

We start with rank 1 because the given string itself occupies its position after all preceding permutations.

6. Complexity Analysis

Time and auxiliary space complexity by approach
ApproachTime complexityAuxiliary space
Brute force\(O(N \cdot N!)\) or worse, excluding sorting overhead\(O(N \cdot N!)\)
Optimized\(O(N^2)\)\(O(N)\)

Optimized time complexity: \(O(N^2)\)

  • Computing factorials takes \(O(N)\).
  • The nested loops examine at most \(O(N^2)\) character pairs.
  • With \(N \leq 1000\), this is efficient enough.

Auxiliary space complexity: \(O(N)\)

The factorial array stores \(N+1\) values. No permutations are stored.

Using long for intermediate multiplication prevents integer overflow before applying the modulo.

9. Interview Preparation Notes

Key pattern: Lexicographical ranking using factorial counting.

Common mistakes

  • Starting from rank 0 instead of 1.
  • Using fact[n - i] instead of fact[n - i - 1].
  • Forgetting to apply modulo during calculations.
  • Using int for intermediate multiplication without considering overflow.
  • Generating every permutation instead of counting the preceding permutations directly.

Likely interviewer follow-ups

Q1. Why do we multiply by a factorial?
Because once a smaller character is fixed at the current position, all remaining characters can be rearranged in factorially many ways.
Q2. Why is the initial rank 1?
Ranks are 1-based. Even if no permutation comes before the string, its rank is still 1.
Q3. Can we optimize beyond \(O(N^2)\)?
Yes. A Fenwick tree (Binary Indexed Tree) or an order-statistics data structure can count remaining smaller characters efficiently, potentially reducing the counting phase to \(O(N \log N)\). However, the \(O(N^2)\) solution is simpler and sufficient for \(N \leq 1000\).

10. Final Recommendation

For this problem, implement the factorial-counting solution with nested loops. It is easy to explain in an interview, avoids generating permutations, and satisfies the constraints.

  • Time: \(O(N^2)\)
  • Auxiliary space: \(O(N)\)
  • Core intuition: Count how many permutations become smaller at each position, then add those counts to a 1-based rank.
