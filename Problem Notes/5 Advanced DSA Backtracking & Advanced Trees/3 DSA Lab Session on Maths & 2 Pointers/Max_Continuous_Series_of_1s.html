Max Continuous Series of 1s

This classic sliding-window and two-pointer problem asks for the longest subarray containing at most B zeros, since those zeros can be flipped into ones.

Important tie-breaker: If multiple subarrays have the same maximum length, return the one with the smallest starting index.

1. Problem Understanding

You are given:

  • A: a binary array containing only 0s and 1s.
  • B: the maximum number of zeros you can replace with ones.

Return the indices of the longest continuous sequence after flipping at most B zeros.

Example

A = [1, 1, 0, 1, 1, 0, 0, 1, 1, 1]
B = 1

We can flip the zero at index 2, producing a continuous sequence from index 0 to index 4.

Answer: [0, 1, 2, 3, 4], which has length 5.

2. Brute Force Approach

Intuition

Try every possible starting index and extend the subarray to the right, counting the zeros encountered.

  • If the number of zeros is at most B, the subarray is valid.
  • If its length is greater than the best length found so far, update the answer.
  • If the length is equal, keep the earlier starting index.

Java code

public class Solution {
    public int[] maxone(int[] A, int B) {
        int n = A.length;
        int bestStart = 0;
        int bestLength = 0;

        // Try every possible starting index.
        for (int start = 0; start < n; start++) {
            int zeros = 0;

            // Extend the subarray to the right.
            for (int end = start; end < n; end++) {
                if (A[end] == 0) {
                    zeros++;
                }

                // Stop when the allowed zero count is exceeded.
                if (zeros > B) {
                    break;
                }

                int length = end - start + 1;

                // Strictly greater preserves the earliest start.
                if (length > bestLength) {
                    bestLength = length;
                    bestStart = start;
                }
            }
        }

        // Return every index in the best continuous range.
        int[] result = new int[bestLength];

        for (int i = 0; i < bestLength; i++) {
            result[i] = bestStart + i;
        }

        return result;
    }
}

Time complexity

\(O(N^2)\), because we try all starting positions and extend each subarray.

Auxiliary space

\(O(1)\), excluding the returned array.

Limitation: With \(N = 10^5\), quadratic time is too slow in the worst case.

3. Optimized Approach — Sliding Window

The optimal approach uses two pointers, left and right, to maintain one window containing at most B zeros.

Intuition

  • Expand the window by moving right.
  • Whenever a zero enters the window, increment the zero count.
  • If the zero count exceeds B, move left forward until the window is valid again.
  • Whenever the current window is strictly longer than the best window, save its starting index and length.

Because we update only when currentLength > bestLength, the earliest starting index is preserved when lengths are tied.

Java solution

public class Solution {
    public int[] maxone(int[] A, int B) {
        int n = A.length;

        int left = 0;
        int zeros = 0;

        int bestStart = 0;
        int bestLength = 0;

        for (int right = 0; right < n; right++) {
            // Include the current element in the window.
            if (A[right] == 0) {
                zeros++;
            }

            // Shrink the window until at most B zeros remain.
            while (zeros > B) {
                if (A[left] == 0) {
                    zeros--;
                }
                left++;
            }

            // The current window is now valid.
            int currentLength = right - left + 1;

            // Update only for a strictly longer window to preserve the earliest start in a tie.
            if (currentLength > bestLength) {
                bestLength = currentLength;
                bestStart = left;
            }
        }

        // Return the indices of the best continuous sequence.
        int[] result = new int[bestLength];

        for (int i = 0; i < bestLength; i++) {
            result[i] = bestStart + i;
        }

        return result;
    }
}

Algorithm step by step

  1. Initialize left = 0, zeros = 0, and bestLength = 0.
  2. Move right from index 0 to n - 1.
  3. If A[right] == 0, increase zeros.
  4. If zeros > B, move left forward, decreasing zeros whenever a zero leaves the window.
  5. Calculate the valid window length: right - left + 1.
  6. If this length is greater than bestLength, update bestLength and bestStart.
  7. Finally, return all indices from bestStart to bestStart + bestLength - 1.

5. Complexity Analysis

Approach Time complexity Auxiliary space
Brute force\(O(N^2)\)\(O(1)\)
Sliding window\(O(N)\)\(O(1)\)

The optimized approach is linear because each pointer moves only forward. Although the while loop is nested inside the for loop, left never moves backward, so it advances at most N times.

The returned array requires \(O(L)\) output space, where \(L\) is the length of the answer. Including the output, total space is \(O(L)\), and therefore at most \(O(N)\).

8. Interview Preparation Notes

Pattern to remember: Variable-size sliding window with two pointers.

Common interview follow-ups

  • Why is the solution \(O(N)\) despite the nested while loop? Each pointer advances at most \(N\) times.
  • Why do we shrink the window only when zeros exceed B? Any window containing at most B zeros is a valid candidate.
  • Why update only when the length is strictly greater? To preserve the earliest starting index in case of a tie.
  • Can we solve this with binary search? Binary search on the answer length is possible with a window-validity check, but sliding window is simpler and runs in \(O(N)\).

9. Final Recommendation

Use the sliding-window solution in interviews. It is optimal, easy to explain, and handles the maximum constraint of \(10^5\) elements efficiently.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(1)\), excluding the result array.
  • Core intuition: Expand the right pointer, shrink the left pointer whenever too many zeros are present, and save only strictly longer valid windows.
