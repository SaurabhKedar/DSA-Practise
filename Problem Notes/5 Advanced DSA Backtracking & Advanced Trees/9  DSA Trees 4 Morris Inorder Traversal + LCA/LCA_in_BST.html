Lowest Common Ancestor in a BST

Find the deepest node that is an ancestor of two given nodes in a Binary Search Tree.

Recommended approach: Compare both target values with the current node and move into the only subtree that can contain both.

1. Problem Understanding

We are given a Binary Search Tree (BST) and two node values, B and C. Find their Lowest Common Ancestor (LCA): the deepest node that is an ancestor of both nodes. A node is considered an ancestor of itself.

The BST property is:

  • Values in the left subtree are smaller than the current node's value.
  • Values in the right subtree are greater than the current node's value.

This ordering lets us find the LCA without traversing the entire tree.

Example 1

For B = 8 and C = 20:

  • Path to 8: 15 → 12 → 10 → 8
  • Path to 20: 15 → 20

The paths first separate after node 15, so the LCA is 15.

Example 2

       8
      / \
     6   21
    / \
   1   7

For B = 7 and C = 1, both nodes are below 6, on opposite sides of it. The LCA is 6.

2. Brute-Force Approach

Find the path from the root to each target, then compare the paths from their beginnings.

Algorithm

  1. Start at the root and record the path to B.
  2. Start again at the root and record the path to C.
  3. Compare the paths from the beginning.
  4. The last node they share is the LCA.

For B = 8 and C = 20:

Path to 8:  [15, 12, 10, 8]
Path to 20: [15, 20]
              ↑
       Last common node = 15

Java code — brute force

import java.util.*;

public class Solution {

    private boolean findPath(TreeNode root, int target,
                             List<Integer> path) {
        if (root == null) {
            return false;
        }

        // Include the current node in the path.
        path.add(root.val);

        if (root.val == target) {
            return true;
        }

        // Search both subtrees.
        if (findPath(root.left, target, path) ||
            findPath(root.right, target, path)) {
            return true;
        }

        // This node is not on the target's path.
        path.remove(path.size() - 1);
        return false;
    }

    public int solve(TreeNode A, int B, int C) {
        List<Integer> pathB = new ArrayList<>();
        List<Integer> pathC = new ArrayList<>();

        findPath(A, B, pathB);
        findPath(A, C, pathC);

        int lca = -1;

        // Find the last common node in both paths.
        for (int i = 0;
             i < Math.min(pathB.size(), pathC.size()); i++) {

            if (pathB.get(i).equals(pathC.get(i))) {
                lca = pathB.get(i);
            } else {
                break;
            }
        }

        return lca;
    }
}

Complexity

  • Time: \(O(N)\) worst case; finding each path can visit all \(N\) nodes.
  • Auxiliary space: \(O(H)\) for the paths and recursion stack, where \(H\) is the tree height. In the worst case, this is \(O(N)\).

Limitation: This approach does not fully use the BST property.

3. Optimized Approach — Use the BST Property

At each node, compare its value with both targets and move in at most one direction.

Condition at current nodeAction
Both B and C are smallerMove to the left child.
Both B and C are greaterMove to the right child.
The values split across the node, or one equals itThe current node is the LCA.

The third case includes when the current node is one of the targets, because a node can be an ancestor of itself.

Interview-ready Java solution

Use the provided TreeNode class and method signature without changing them.

public class Solution {
    public int solve(TreeNode A, int B, int C) {

        // Start searching from the root.
        TreeNode current = A;

        while (current != null) {

            // Both target values are smaller:
            // their LCA must be in the left subtree.
            if (B < current.val && C < current.val) {
                current = current.left;
            }

            // Both target values are greater:
            // their LCA must be in the right subtree.
            else if (B > current.val && C > current.val) {
                current = current.right;
            }

            // The values split across the two sides,
            // or the current node is one of the targets.
            else {
                return current.val;
            }
        }

        // The problem guarantees both nodes exist.
        return -1;
    }
}

5. Complexity Analysis

Let \(N\) be the number of nodes and \(H\) be the height of the BST.

Approach Time complexity Auxiliary space
Brute force: store paths\(O(N)\)\(O(H)\)
Optimized: iterative BST traversal\(O(H)\)\(O(1)\)
  • The optimized traversal moves down one level per iteration, so it takes \(O(H)\) time.
  • For a balanced BST, \(H = O(\log N)\), so the time is \(O(\log N)\).
  • For a skewed BST, \(H = O(N)\), so the time is \(O(N)\).
  • The optimized solution uses \(O(1)\) auxiliary space because it maintains only one current-node reference.

A BST does not automatically guarantee logarithmic height.

6. Edge Cases

CaseExampleExpected behavior
Targets in opposite subtreesB = 8, C = 20Return root 15.
Targets in the left subtreeB = 1, C = 7Move left until the split at 6.
Targets in the right subtreeBoth values greater than the rootKeep moving right.
One target is the rootB = 15, C = 8Return 15.
One target is an ancestor of the otherB = 12, C = 8Return 12.
Both targets are equalB = C = 8Return 8.
Highly skewed BSTA chain of nodesCorrect result, but \(O(N)\) time.

The problem guarantees that both nodes exist, so the -1 return is only a defensive fallback.

8. Interview Preparation Notes

Pattern to remember: BST property plus ancestor/split-point search.

Common mistakes

  • Traversing both subtrees unnecessarily instead of using BST ordering.
  • Returning the root immediately without checking whether both targets lie on the same side.
  • Forgetting that the LCA can be one of the target nodes.
  • Claiming \(O(\log N)\) time for every BST, including skewed trees.

Likely interviewer follow-ups

Why is this faster than searching the entire tree?
BST ordering tells us which subtree can contain both targets, letting us discard the other subtree at every step.
What if the input is an ordinary binary tree instead of a BST?
We cannot make decisions using value comparisons. Use a general binary-tree LCA algorithm, such as recursive DFS.
Can you solve it recursively?
Yes. Apply the same three conditions recursively. It takes \(O(H)\) time and \(O(H)\) auxiliary space for the call stack.
What if one target is the ancestor of the other?
The ancestor itself is the LCA. When one value equals current.val, neither the “both smaller” nor “both greater” condition applies.

9. Final Recommendation

Use the iterative optimized solution in an interview. It is simple, uses the BST property, and requires constant auxiliary space.

  • Time: \(O(H)\), worst case \(O(N)\).
  • Auxiliary space: \(O(1)\).
If both targets are smaller, go left. If both are greater, go right. Otherwise, the current node is the LCA.
