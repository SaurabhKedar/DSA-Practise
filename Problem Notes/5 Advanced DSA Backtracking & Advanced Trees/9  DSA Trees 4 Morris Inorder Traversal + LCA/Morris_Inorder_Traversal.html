Binary Trees · Inorder Traversal

Morris Inorder Traversal

Traverse a binary tree without recursion or an explicit stack by temporarily threading existing tree pointers. The traversal runs in \(O(N)\) time and uses \(O(1)\) auxiliary space.

Pattern to remember: Left → Root → Right, using temporary threads to return from a left subtree.

1. Problem Understanding

Given the root A of a binary tree, return an ArrayList<Integer> containing its inorder traversal. Inorder traversal always follows:

Left → Root → Right

Example

1
 \
  2
 /
3

Node 2 is the right child of 1, and node 3 is the left child of 2. The inorder output is [1, 3, 2].

  • Recursion is not allowed.
  • An explicit stack is not allowed.
  • The output array is allowed; auxiliary space should be constant.
  • The tree can contain up to \(10^5\) nodes.

2. Brute-Force Approach

A normal iterative inorder traversal uses a stack: move left while pushing nodes, pop and visit a node, then continue from its right child. This takes \(O(N)\) time, but the stack can use \(O(N)\) space. Recursion also uses the call stack.

Why not use it? The problem prohibits both recursion and an explicit stack, so we need Morris Traversal.

3. Optimized Approach — Morris Traversal

Core intuition

Ordinarily, a stack or recursion remembers where to return after exploring a left subtree. Morris Traversal temporarily creates a link back to the current node instead.

When the current node has a left child:

  • Find the rightmost node in the left subtree, called the inorder predecessor.
  • If its right pointer is null, point it temporarily to the current node and move left.
  • When traversal returns through that thread, remove it, visit the current node, and move right.

These temporary links are called threads.

Step-by-step algorithm

  1. Initialize current = A and create an empty result array.
  2. If current.left == null, add its value and move to current.right.
  3. Otherwise, find the rightmost node in current.left, the inorder predecessor.
  4. If the predecessor's right pointer is null, create a temporary thread to current and move left.
  5. If the predecessor's right pointer already points to current, remove the thread, add current.val, and move right.
  6. Continue until current == null.

Complete Java solution

import java.util.ArrayList;

public class Solution {
    public ArrayList<Integer> solve(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();

        TreeNode current = A;

        // Continue until all nodes are processed.
        while (current != null) {

            // Case 1: No left subtree.
            // Visit this node and move to the right.
            if (current.left == null) {
                result.add(current.val);
                current = current.right;
            } else {

                // Find the rightmost node in the left subtree.
                // This node is the inorder predecessor.
                TreeNode predecessor = current.left;

                while (predecessor.right != null
                        && predecessor.right != current) {
                    predecessor = predecessor.right;
                }

                // Case 2: First visit to this node.
                // Create a temporary thread back to current.
                if (predecessor.right == null) {
                    predecessor.right = current;
                    current = current.left;
                } else {

                    // Case 3: We returned through the thread.
                    // Remove the thread to restore the tree.
                    predecessor.right = null;

                    // Left subtree is complete; visit current.
                    result.add(current.val);

                    // Process the right subtree next.
                    current = current.right;
                }
            }
        }

        return result;
    }
}

Platform note: Keep the given TreeNode definition. Only implement the solve() method inside Solution.

In this example, node 1 has left child 6 and right child 2; node 2 has left child 3.

Step Current Action Result
11Create thread 6.right → 1; move left.[]
26No left child; visit 6.[6]
31Thread found; remove it and visit 1.[6, 1]
42Create thread 3.right → 2; move left.[6, 1]
53No left child; visit 3.[6, 1, 3]
62Thread found; remove it and visit 2.[6, 1, 3, 2]
7nullTraversal ends.[6, 1, 3, 2]

Final output: [6, 1, 3, 2]

Why do we need the second condition?

predecessor.right != current

This condition prevents the predecessor search from following a temporary thread back to the current node. Without it, the traversal could get stuck in a loop.

Removing the thread with predecessor.right = null is essential to restore the original tree structure.

5. Complexity Analysis

Let \(N\) be the number of nodes.

Approach Time Auxiliary space Allowed here?
Recursive inorder\(O(N)\)\(O(H)\)No
Stack-based inorder\(O(N)\)\(O(H)\)No
Morris traversal\(O(N)\)\(O(1)\)Yes
  • Time — \(O(N)\): Every node is visited, and predecessor links are traversed only a constant number of times across the traversal.
  • Auxiliary space — \(O(1)\): Only a few node references, such as current and predecessor, are maintained. There is no recursion or explicit stack.
  • Output space — \(O(N)\): The returned ArrayList stores all node values. Output memory is separate from auxiliary space.

6. Edge Cases

  • Single node: The root has no left child, so its value is added immediately.
  • Left-skewed tree: Temporary threads let traversal return to ancestors without a stack.
  • Right-skewed tree: Each node has no left child, so traversal simply moves right.
  • Balanced tree: Threads handle each left subtree and are removed after use.
  • Up to \(10^5\) nodes: The algorithm remains \(O(N)\) in time and uses constant auxiliary space.

8. Interview Preparation Notes

Pattern to remember: Morris Traversal = inorder traversal + temporary threaded links.

Common mistakes

  • Forgetting to remove the temporary thread.
  • Not checking whether predecessor.right == current.
  • Adding a node to the result before its left subtree has been processed.
  • Claiming total space is \(O(1)\) without distinguishing the output array from auxiliary space.

Likely interviewer follow-ups

Q1. Why is Morris Traversal \(O(1)\) auxiliary space?
It uses existing tree pointers and a constant number of references instead of a stack.
Q2. Does Morris Traversal modify the tree?
Temporarily, yes. It restores the modified pointers during normal completion.
Q3. Can Morris Traversal be used for preorder?
Yes. The visit position changes: visit the current node when first creating the thread instead of when removing it.
Q4. Is it always preferable to recursion?
No. Recursion is often simpler when permitted. Morris Traversal is especially useful when auxiliary space must remain constant.

9. Final Recommendation

For this problem, implement Morris Inorder Traversal because it satisfies both restrictions: no recursion and no stack.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(1)\)
  • Output space: \(O(N)\)

Simple rule: No left child → visit and move right. Left child exists → find the predecessor, create a thread to go left, then remove the thread and visit the node when you return.
