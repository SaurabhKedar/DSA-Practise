Distance Between Nodes in a BST

Find the minimum number of edges between two values in a Binary Search Tree. The key idea is to find their Lowest Common Ancestor (LCA), then add the distance from the LCA to each target.

Pattern to remember: \(\operatorname{Distance}(B,C)=\operatorname{Distance}(\operatorname{LCA},B)+\operatorname{Distance}(\operatorname{LCA},C)\). Count edges, not nodes.

1. Problem Understanding

You are given:

  • A: the root of a Binary Search Tree.
  • B: the first node value.
  • C: the second node value.

Return the minimum number of edges required to travel from node B to node C. Both values are guaranteed to exist.

Remember the BST property:

  • The left subtree contains smaller values.
  • The right subtree contains greater values.

Example 1

        5
       / \
      2   8
     / \ / \
    1  4 6  11

B = 2
C = 11

Path from 2 to 11:

2 -> 5 -> 8 -> 11

The path has 3 edges, so the output is 3.

Example 2

        6
       / \
      2   9
     / \ / \
    1  4 7  10

B = 2
C = 6

The path is 2 -> 6, which has 1 edge, so the output is 1.

Why the LCA matters

The path between two nodes in a tree always passes through their Lowest Common Ancestor.

        5  <- LCA
       / \
      2   8
           \
            11

For B = 2 and C = 11, the LCA is 5. The distance from the LCA to B is 1 edge, and the distance from the LCA to C is 2 edges. The total is 1 + 2 = 3.

2. Brute-Force Approach — Find Both Paths

Intuition

We can solve this without using the BST property. Find the complete path from the root to each target, then compare the paths to find their last common node.

For the first example:

Path to B = 2:  [5, 2]
Path to C = 11: [5, 8, 11]
Common path:    [5]

A parent map and BFS can find paths and distances without relying on BST ordering.

Java code — brute force

import java.util.HashMap;
import java.util.LinkedList;
import java.util.Map;
import java.util.Queue;

public class Solution {

    public int solve(TreeNode A, int B, int C) {
        // Store the parent of every visited node so we can walk upward later.
        Map<TreeNode, TreeNode> parent = new HashMap<>();

        // BFS visits the tree and populates the parent relationships.
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(A);
        parent.put(A, null);

        TreeNode nodeB = null;
        TreeNode nodeC = null;

        while (!queue.isEmpty()) {
            TreeNode curr = queue.poll();

            if (curr.val == B) {
                nodeB = curr;
            }

            if (curr.val == C) {
                nodeC = curr;
            }

            if (curr.left != null) {
                parent.put(curr.left, curr);
                queue.offer(curr.left);
            }

            if (curr.right != null) {
                parent.put(curr.right, curr);
                queue.offer(curr.right);
            }
        }

        // Record each ancestor of B and its distance from B.
        Map<TreeNode, Integer> ancestors = new HashMap<>();
        int distance = 0;
        TreeNode curr = nodeB;

        while (curr != null) {
            ancestors.put(curr, distance);
            distance++;
            curr = parent.get(curr);
        }

        // Walk upward from C until reaching an ancestor of B.
        distance = 0;
        curr = nodeC;

        while (!ancestors.containsKey(curr)) {
            distance++;
            curr = parent.get(curr);
        }

        // Add the distance from B to the common ancestor to the distance from C.
        return ancestors.get(curr) + distance;
    }
}

Complexity and limitation

  • Time: O(N), because BFS may visit every node and ancestor traversal takes at most O(N).
  • Space: O(N) for the parent map, ancestor map, and BFS queue.

This visits the entire tree even though the BST property lets us avoid unnecessary traversal.

3. Optimized Approach — BST + LCA

Step 1: Find the LCA

Starting at the root, compare both target values with the current node:

  • If both values are smaller, move left.
  • If both values are greater, move right.
  • Otherwise, the values are on different sides or one equals the current value; the current node is the LCA.

Step 2: Find each distance

From the LCA, search for B using BST rules and count each edge traversed. Repeat for C, then add the two distances. 

Answer = distance(LCA, B) + distance(LCA, C)

Optimized Java solution

This implementation is iterative. That matters for a highly skewed tree, where recursive traversal could cause a stack overflow. 

public class Solution {

    public int solve(TreeNode A, int B, int C) {
        // Step 1: Find the Lowest Common Ancestor using the BST property.
        TreeNode lca = A;

        while (lca != null) {
            // Both targets are smaller, so their paths are in the left subtree.
            if (B < lca.val && C < lca.val) {
                lca = lca.left;
            }
            // Both targets are greater, so their paths are in the right subtree.
            else if (B > lca.val && C > lca.val) {
                lca = lca.right;
            }
            // They split across the current node, or one target is the current node.
            else {
                break;
            }
        }

        // Step 2: Find the distance from the LCA to each target.
        int distanceB = findDistance(lca, B);
        int distanceC = findDistance(lca, C);

        // Step 3: The path between the targets passes through the LCA.
        return distanceB + distanceC;
    }

    // Counts the edges on the BST search path from root to target.
    private int findDistance(TreeNode root, int target) {
        int distance = 0;

        while (root.val != target) {
            // Follow the only subtree that can contain the target.
            if (target < root.val) {
                root = root.left;
            } else {
                root = root.right;
            }

            // Every move to a child traverses one edge.
            distance++;
        }

        return distance;
    }
}

The solution assumes the root is non-null and both target values exist, as guaranteed by the problem statement.

5. Complexity Analysis

Let N be the number of nodes and H be the height of the BST.

ApproachTime ComplexityAuxiliary Space
Brute force (BFS + HashMaps)O(N)O(N)
Optimized (BST + LCA)O(H)O(1)

The optimized method performs three traversals: find the LCA, find the distance to B, and find the distance to C. Each takes at most O(H), so the total is \(O(H)+O(H)+O(H)=O(3H)=O(H)\).

BST structureHeightTime
Balanced BSTO(log N)O(log N)
Skewed BSTO(N)O(N)

The optimized solution uses O(1) auxiliary space: it uses only pointers and integer variables, with no recursion, stack, or additional data structure.

8. Interview Preparation Notes

Key concepts to remember

  • Binary Search Tree property.
  • Lowest Common Ancestor (LCA).
  • Finding distance between two nodes.
  • Iterative tree traversal.

Common interview mistakes

  1. Counting nodes instead of edges.

    For 2 -> 5 -> 8 -> 11, there are 4 nodes but only 3 edges. Count movements, not nodes.

  2. Finding the LCA without using BST properties.

    A normal binary tree needs a different LCA approach. Here, BST ordering makes the search more efficient.

  3. Forgetting when one target is the LCA.

    For a tree with root 5 and left child 2, the LCA of B = 5 and C = 2 is 5.

  4. Using recursion unnecessarily.

    With up to 1,000,000 nodes, a skewed tree can cause StackOverflowError. The iterative implementation avoids this.

Likely interviewer follow-up questions

What is the Lowest Common Ancestor?
The lowest node in a tree that is an ancestor of both given nodes. A node can be its own ancestor.
What if the tree is not a BST?
Value comparisons cannot determine which subtree contains a target. Use a general binary-tree LCA algorithm, typically with DFS.
Can this be solved in O(log N)?
Yes, if the BST is balanced, its height is O(log N). The solution takes O(H), which becomes O(log N) for a balanced BST.
Why is the auxiliary space O(1)?
The iterative traversal uses a constant number of pointers and variables, with no additional data structure or recursion stack.

9. Final Recommendation

For interviews, implement the optimized BST + LCA approach because:

  1. It uses the BST property to find the LCA without traversing unnecessary subtrees.
  2. It calculates both distances using simple BST searches.
  3. It requires O(1) auxiliary space.
  4. Its iterative implementation avoids recursion stack overflow for highly skewed trees.
ComplexityResult
TimeO(H)
Auxiliary spaceO(1)

For a balanced BST, the time is O(log N). For a skewed BST, it is O(N).

Remember this intuition

The entire problem reduces to one formula:

\[\boxed{\operatorname{Distance}(B,C)=\operatorname{Distance}(\operatorname{LCA},B)+\operatorname{Distance}(\operatorname{LCA},C)}\]

Interview pattern: BST traversal + Lowest Common Ancestor + distance calculation.

This technique is reusable for many BST and binary-tree interview questions involving the LCA and path distance.
