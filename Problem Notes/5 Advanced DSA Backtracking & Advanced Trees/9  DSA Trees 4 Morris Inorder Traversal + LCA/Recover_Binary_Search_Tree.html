Recover Binary Search Tree

Identify the two values swapped by mistake in a Binary Search Tree.

Recommended approach: Morris inorder traversal detects the misplaced nodes in \(O(N)\) time and \(O(1)\) auxiliary space.

1. Problem Understanding

We are given a Binary Search Tree in which exactly two nodes have been swapped by mistake. Identify the two incorrect values and return the values that should be swapped to restore the BST.

A BST has this ordering property:

  • All values in a node's left subtree are smaller than the node's value.
  • All values in a node's right subtree are greater than the node's value.

Therefore, inorder traversal (Left → Root → Right) of a valid BST visits values in ascending order.

Example 1: adjacent values

Incorrect inorder: 2 → 1 → 3

After swapping 2 and 1: 1 → 2 → 3

Example 2: non-adjacent values

Tree:

       3
      / \
     1   4
        /
       2

Inorder: 1 → 3 → 2 → 4. The misplaced values are 3 and 2.

Output-order note

The supplied note says the pair should be returned in ascending order, but its InterviewBit examples and optimized code return values in inversion-detection order, such as [3, 1]. The implementations below follow those examples and code: return [first, second]. If a judge explicitly requires ascending order, return [Math.min(first, second), Math.max(first, second)] instead.

Key observation: inorder inversions

Whenever two consecutive inorder values satisfy previous.val > current.val, they form an inversion and violate the sorted order.

  • Adjacent swapped values create one inversion.
  • Non-adjacent swapped values create two inversions.

2. Brute Force: Inorder Traversal + ArrayList

Store the inorder values in an ArrayList. Because a valid BST's inorder sequence is sorted, scan the stored sequence for adjacent inversions to identify the two misplaced values.

Algorithm

  1. Perform inorder traversal and store every node value in an ArrayList.
  2. Scan neighboring values for positions where arr[i] > arr[i + 1].
  3. On the first inversion, record the value at i as first.
  4. For each inversion, update second to the value at i + 1.
  5. Return first and second in inversion-detection order.

Java Code — Brute Force

import java.util.ArrayList;

public class Solution {

    private final ArrayList<Integer> inorder = new ArrayList<>();

    // Visit nodes in Left, Root, Right order and save their values.
    private void inorderTraversal(TreeNode root) {
        if (root == null) {
            return;
        }

        inorderTraversal(root.left);
        inorder.add(root.val);
        inorderTraversal(root.right);
    }

    public ArrayList<Integer> recoverTree(TreeNode root) {
        inorder.clear();
        inorderTraversal(root);

        int first = -1;
        int second = -1;

        // The swapped values create one or two descending adjacent pairs.
        for (int i = 0; i < inorder.size() - 1; i++) {
            if (inorder.get(i) > inorder.get(i + 1)) {
                if (first == -1) {
                    first = inorder.get(i);
                }
                second = inorder.get(i + 1);
            }
        }

        ArrayList<Integer> answer = new ArrayList<>();
        // Match the supplied InterviewBit examples: preserve detection order.
        answer.add(first);
        answer.add(second);
        return answer;
    }
}

Complexity

  • Space: \(O(N)\) for the stored values, plus up to \(O(H)\) recursive call-stack space for tree height \(H\).

This works, but it uses linear extra space. The optimized approach avoids both recursion and a traversal collection.

3. Optimized Approach: Morris Inorder Traversal

Morris traversal performs inorder traversal without recursion, a stack, or an ArrayList. It temporarily threads the rightmost node in the current node's left subtree back to the current node, then removes that thread when it returns.

A visual explanation is available in the supplied Morris traversal article by Papon Ahasan.

  1. If the current node has no left child, process it and move right.
  2. Otherwise, find the rightmost node in its left subtree (the inorder predecessor).
  3. If that predecessor's right pointer is null, create a temporary link to the current node and move left.
  4. If the predecessor's right pointer already points to the current node, remove the link, process the current node, and move right.

Detecting the swapped nodes

VariablePurpose
prevPrevious node in the inorder traversal.
firstPrevious node at the first detected inversion.
secondCurrent node at the latest detected inversion.

Whenever prev.val > curr.val, an inversion has been found:

if (first == null) {
    first = prev;
}
second = curr;

The first inversion gives the first misplaced node. Updating second on every inversion handles both cases: adjacent swaps have one inversion, while non-adjacent swaps have two and the current node in the second inversion is the other misplaced node.

4. Optimized Java Code — Morris Traversal

This implementation uses \(O(N)\) time and \(O(1)\) auxiliary traversal space. It returns the pair in the inversion-detection order used in the supplied InterviewBit examples.

import java.util.ArrayList;

public class Solution {

    private TreeNode first;
    private TreeNode second;
    private TreeNode prev;

    public ArrayList<Integer> recoverTree(TreeNode root) {
        // Reset state so this Solution instance can be reused safely.
        first = null;
        second = null;
        prev = null;

        TreeNode curr = root;

        // Morris inorder traversal visits nodes without recursion or a stack.
        while (curr != null) {
            if (curr.left == null) {
                // No left subtree: process this node, then move right.
                detectInversion(curr);
                curr = curr.right;
            } else {
                // Find the inorder predecessor in the left subtree.
                TreeNode pred = curr.left;
                while (pred.right != null && pred.right != curr) {
                    pred = pred.right;
                }

                if (pred.right == null) {
                    // First visit: thread the predecessor back to curr.
                    pred.right = curr;
                    curr = curr.left;
                } else {
                    // Second visit: remove the thread and process curr.
                    pred.right = null;
                    detectInversion(curr);
                    curr = curr.right;
                }
            }
        }

        ArrayList<Integer> answer = new ArrayList<>();
        // The problem guarantees exactly two swapped nodes.
        answer.add(first.val);
        answer.add(second.val);
        return answer;
    }

    // Compare each visited node with its inorder predecessor.
    private void detectInversion(TreeNode curr) {
        if (prev != null && prev.val > curr.val) {
            if (first == null) {
                first = prev;
            }
            second = curr;
        }

        prev = curr;
    }
}

Temporary threads are removed as the traversal returns from each left subtree, restoring the original tree structure.

5. Dry Run of the Optimized Solution

Consider the supplied example:

        2
       / \
      3   1

Its inorder sequence is 3 → 2 → 1, so both adjacent pairs are inversions.

PreviousCurrentConditionAction
323 > 2first = 3, second = 2
212 > 1Update second = 1

At the end, first = 3 and second = 1, so the result is [3, 1].

Non-adjacent swapped values

For inorder sequence 1 → 3 → 2 → 4, the only inversion is 3 > 2. It identifies first = 3 and second = 2, even though those nodes are not adjacent in the tree.

Why remove each temporary thread?

A link such as pred.right = curr gives traversal a way back after visiting the left subtree. On the return visit, pred.right = null removes the temporary link. Leaving it in place would change the tree's structure.

6. Complexity Analysis

ApproachTimeAuxiliary space
Inorder + ArrayList\(O(N)\)\(O(N)\) for values, plus recursive stack space
Morris traversal\(O(N)\)\(O(1)\)

Why is Morris traversal linear?

Each node is processed during inorder traversal. Predecessor searches follow right pointers, and each temporary thread is created and removed only a constant number of times per node over the full traversal, so the total work is \(O(N)\).

Why is auxiliary space constant?

The traversal uses only a fixed set of node references, such as curr, pred, prev, first, and second. It does not use recursion, a stack, or a collection for traversal; temporary threads reuse existing tree pointers.

9. Interview Preparation Notes

Key concepts to remember

  1. Inorder traversal of a BST produces values in sorted order.
  2. Two swapped nodes create one or two inversions.
  3. prev.val > curr.val detects an inversion.
  4. Morris traversal achieves \(O(1)\) auxiliary space.
  5. Remove temporary threads to restore the original tree.

Common mistakes

  • Using >= instead of > in the inversion check.
  • Updating first on every inversion instead of only the first one.
  • Failing to update second on later inversions.
  • Forgetting to remove a temporary Morris thread.
  • Using recursion or a stack when constant auxiliary space is required.
  • Ignoring the stated-versus-example output-order inconsistency.

Likely interviewer follow-up questions

Why does inorder traversal help identify swapped nodes?
A valid BST produces an ascending inorder sequence. Swapping two nodes breaks that sorted order.

How many inversions can occur?
Adjacent swapped elements create one inversion; non-adjacent swapped elements create two.

Why not use iterative inorder traversal with a stack?
A stack requires \(O(H)\) auxiliary space, where \(H\) is the tree height. Morris traversal avoids it with temporary threads.

Does Morris traversal permanently modify the tree?
No. The traversal removes each temporary thread before finishing, restoring the original structure.

Use Morris inorder traversal when the problem requires constant extra space.

Remember the intuition

Think of the BST as a sorted array with exactly two elements swapped:

  • Find the first inversion and remember its previous node.
  • Update the second node whenever another inversion appears.
  • Finish traversal and return the two identified nodes in the required output order.

The key check is prev != null && prev.val > curr.val. Understanding why this detects misplaced nodes is the core of the problem. Practise Morris traversal on a normal inorder traversal problem as well; it is a useful tree-interview technique.
