Common Nodes in Two BSTs

Find the values shared by two Binary Search Trees and return their sum modulo \(10^9+7\). Compare a HashSet solution, a two-stack inorder solution, and a constant-auxiliary-space Morris traversal.

Pattern to remember: Two BSTs → two sorted inorder traversals → compare values like two pointers.

1. Problem Understanding

You are given two Binary Search Trees, A and B. Your task is to:

  1. Find all values that exist in both BSTs.
  2. Calculate their sum.
  3. Return the sum modulo \(10^9+7\).
  4. If there are no common values, return 0.

Example 1 — BST A

       5
      / \
     2   8
      \    \
       3    15
           /
          9

BST B

       7
      / \
     1   10
      \    \
       2    15
           /
          11

Inorder values and result

A = [2, 3, 5, 8, 9, 15]

B = [1, 2, 7, 10, 11, 15]

Common values: 2, 15

Answer: \((2+15)\bmod(10^9+7)=17\)

Important observation: Inorder traversal of a BST produces values in sorted ascending order. We can therefore treat the two trees as sorted sequences and find their common values.

2. Approach 1 — Brute Force Using a HashSet

Intuition

Store all values from the first BST in a HashSet. Then traverse the second BST, checking whether each value is present. Add matching values to the sum.

Algorithm

  1. Traverse BST A and insert every node value into a HashSet.
  2. Traverse BST B.
  3. For every node, check whether its value is in the HashSet.
  4. If it exists, add the value to the sum.
  5. Return the sum modulo \(10^9+7\).

Java code

import java.util.HashSet;
import java.util.Set;

public class Solution {
    private static final long MOD = 1000000007L;

    // Store all values from BST A so BST B can be checked efficiently.
    private void store(TreeNode root, Set<Integer> values) {
        if (root == null) {
            return;
        }

        values.add(root.val);
        store(root.left, values);
        store(root.right, values);
    }

    // Sum values in BST B that also appear in BST A.
    private long findCommon(TreeNode root, Set<Integer> values) {
        if (root == null) {
            return 0;
        }

        long sum = values.contains(root.val) ? root.val : 0;
        sum += findCommon(root.left, values);
        sum += findCommon(root.right, values);

        return sum % MOD;
    }

    public int solve(TreeNode A, TreeNode B) {
        Set<Integer> values = new HashSet<>();
        store(A, values);

        return (int) findCommon(B, values);
    }
}

Complexity analysis

  • Time: Expected \(O(N+M)\). Inserting N values and checking M values each take expected constant time per operation.
  • Auxiliary space: \(O(N+H_2)\). The HashSet stores N values, and recursion uses \(O(H_2)\) stack space while traversing BST B.

Limitation: This approach stores all values of BST A. We can reduce memory usage by using the sorted property of BST inorder traversals.

3. Approach 2 — Two-Stack Inorder Traversal

Recommended practical approach: It uses the sorted order of inorder traversal and is usually easier to explain and maintain than Morris traversal.

Intuition

Inorder traversal gives sorted values. For example, BST A produces [2, 3, 5, 8, 9, 15] and BST B produces [1, 2, 7, 10, 11, 15]. This is like finding common elements in two sorted arrays. Two stacks generate the values one at a time without building arrays.

Comparison conditions

ComparisonAction
A value equals B valueCommon value; add it and advance both traversals.
A value is smallerAdvance A.
B value is smallerAdvance B.

Why advance only the smaller value? Suppose the current values are A = 3 and B = 7. Since both sequences are sorted, future values in B cannot be smaller than 7. Therefore, A's current value 3 cannot match B's current or future values, so we can safely move forward in A.

Algorithm

  1. Create two stacks.
  2. Push the leftmost path of both BSTs.
  3. Compare the top elements.
  4. If equal, add the value and advance both traversals.
  5. If A's value is smaller, advance A; otherwise, advance B.
  6. Stop when either stack becomes empty.

Java code

import java.util.Stack;

public class Solution {
    public int solve(TreeNode A, TreeNode B) {
        final long MOD = 1000000007L;
        Stack<TreeNode> stackA = new Stack<>();
        Stack<TreeNode> stackB = new Stack<>();
        TreeNode currA = A;
        TreeNode currB = B;
        long sum = 0;

        while (true) {
            // Push the next leftmost path from BST A.
            while (currA != null) {
                stackA.push(currA);
                currA = currA.left;
            }

            // Push the next leftmost path from BST B.
            while (currB != null) {
                stackB.push(currB);
                currB = currB.left;
            }

            // An empty stack means that tree's inorder traversal is complete.
            if (stackA.isEmpty() || stackB.isEmpty()) {
                break;
            }

            TreeNode nodeA = stackA.peek();
            TreeNode nodeB = stackB.peek();

            if (nodeA.val == nodeB.val) {
                // Add the common value and advance both inorder traversals.
                sum = (sum + nodeA.val) % MOD;
                stackA.pop();
                stackB.pop();
                currA = nodeA.right;
                currB = nodeB.right;
            } else if (nodeA.val < nodeB.val) {
                // A's smaller value cannot match B's current or later values.
                stackA.pop();
                currA = nodeA.right;
            } else {
                // B's smaller value cannot match A's current or later values.
                stackB.pop();
                currB = nodeB.right;
            }
        }

        return (int) sum;
    }
}

Complexity analysis

  • Time: \(O(N+M)\). Each node is pushed and popped once.
  • Auxiliary space: \(O(H_1+H_2)\) for the two traversal stacks.
  • For balanced BSTs this is approximately \(O(\log N+\log M)\); for skewed BSTs it can become \(O(N+M)\).

4. Approach 3 — Morris Inorder Traversal

Advanced optimization: This approach compares inorder values without recursion or explicit stacks, using \(O(1)\) auxiliary space.

How Morris traversal works

Normally, inorder traversal uses recursion or a stack to remember where to return after exploring a left subtree. Morris traversal temporarily uses an existing right pointer to create a link, called a thread, back to the current node. The thread is removed when traversal returns through it.

For this BST:

       5
      / \
     3   8
    / \
   2   4

The inorder sequence is 2 → 3 → 4 → 5 → 8.

Two cases

  1. The current node has no left child: visit it and move to its right child. 
    if (curr.left == null) {
    // Visit this node, then continue to its right child.
    curr = curr.right;
}
  2. The current node has a left child: find the rightmost node in the left subtree, called the inorder predecessor. If its right pointer is null, point it temporarily to the current node and move left. When traversal returns to the predecessor, remove the thread, visit the current node, and move right.

For example, before the left subtree of 5 has been processed:

       5
      /
     3
      \
       4
        \
         5  <-- temporary thread

After processing the left subtree, the thread is removed and 5 is visited.

Approach 1: Morris inorder using an iterator

To traverse two BSTs simultaneously, create one Morris iterator per tree. Each call to next() returns exactly one node in inorder sequence. The two returned values can then be compared like in the two-stack approach. 

class MorrisIterator {
    TreeNode curr;

    MorrisIterator(TreeNode root) {
        curr = root;
    }

    // Return the next node in inorder, creating and removing threads as needed.
    TreeNode next() {
        while (curr != null) {
            if (curr.left == null) {
                // No left subtree remains; return this node and move right.
                TreeNode node = curr;
                curr = curr.right;
                return node;
            }

            // Find the inorder predecessor in the left subtree.
            TreeNode pred = curr.left;
            while (pred.right != null && pred.right != curr) {
                pred = pred.right;
            }

            if (pred.right == null) {
                // First visit: thread the predecessor back to the current node.
                pred.right = curr;
                curr = curr.left;
            } else {
                // Second visit: remove the thread, then return the current node.
                pred.right = null;
                TreeNode node = curr;
                curr = curr.right;
                return node;
            }
        }

        return null;
    }
}

Complete Java code — iterator approach

public class Solution {
    private static final long MOD = 1000000007L;

    // Generate inorder nodes without recursion or an explicit stack.
    private class MorrisIterator {
        private TreeNode curr;

        MorrisIterator(TreeNode root) {
            curr = root;
        }

        // Return the next inorder node and remove threads as they are revisited.
        TreeNode next() {
            while (curr != null) {
                if (curr.left == null) {
                    // Visit a node with no left subtree.
                    TreeNode node = curr;
                    curr = curr.right;
                    return node;
                }

                // Locate the rightmost node in the current left subtree.
                TreeNode pred = curr.left;
                while (pred.right != null && pred.right != curr) {
                    pred = pred.right;
                }

                if (pred.right == null) {
                    // Create a temporary return path and process the left subtree.
                    pred.right = curr;
                    curr = curr.left;
                } else {
                    // Restore the original tree link before visiting this node.
                    pred.right = null;
                    TreeNode node = curr;
                    curr = curr.right;
                    return node;
                }
            }

            return null;
        }
    }

    public int solve(TreeNode A, TreeNode B) {
        MorrisIterator itA = new MorrisIterator(A);
        MorrisIterator itB = new MorrisIterator(B);
        long sum = 0;

        // Fetch the first inorder node from each tree.
        TreeNode nodeA = itA.next();
        TreeNode nodeB = itB.next();

        while (nodeA != null && nodeB != null) {
            if (nodeA.val == nodeB.val) {
                // The values match, so add once and advance both iterators.
                sum = (sum + nodeA.val) % MOD;
                nodeA = itA.next();
                nodeB = itB.next();
            } else if (nodeA.val < nodeB.val) {
                // Advance the iterator with the smaller value.
                nodeA = itA.next();
            } else {
                // Advance the iterator with the smaller value.
                nodeB = itB.next();
            }
        }

        // Drain both iterators so all temporary threads are removed.
        while (itA.next() != null) {
            // Continue until BST A is fully restored.
        }
        while (itB.next() != null) {
            // Continue until BST B is fully restored.
        }

        return (int) sum;
    }
}

Approach 2: Morris inorder without an iterator class

This version has no separate iterator class or next() method. It keeps currA and currB as fields on Solution and uses getNextA() and getNextB() to return the next inorder node from each tree. The fields are needed because a Java helper method cannot update a local pointer in its caller. 

public class Solution {
    private static final long MOD = 1000000007L;

    // Keep traversal state between calls to the helper methods.
    private TreeNode currA;
    private TreeNode currB;

    // Return the next inorder node from BST A.
    private TreeNode getNextA() {
        while (currA != null) {
            if (currA.left == null) {
                // Visit a node with no left subtree.
                TreeNode node = currA;
                currA = currA.right;
                return node;
            }

            // Find the inorder predecessor in A's left subtree.
            TreeNode pred = currA.left;
            while (pred.right != null && pred.right != currA) {
                pred = pred.right;
            }

            if (pred.right == null) {
                // First visit: create a temporary return path.
                pred.right = currA;
                currA = currA.left;
            } else {
                // Second visit: remove the thread and return the current node.
                pred.right = null;
                TreeNode node = currA;
                currA = currA.right;
                return node;
            }
        }

        return null;
    }

    // Return the next inorder node from BST B.
    private TreeNode getNextB() {
        while (currB != null) {
            if (currB.left == null) {
                // Visit a node with no left subtree.
                TreeNode node = currB;
                currB = currB.right;
                return node;
            }

            // Find the inorder predecessor in B's left subtree.
            TreeNode pred = currB.left;
            while (pred.right != null && pred.right != currB) {
                pred = pred.right;
            }

            if (pred.right == null) {
                // First visit: create a temporary return path.
                pred.right = currB;
                currB = currB.left;
            } else {
                // Second visit: remove the thread and return the current node.
                pred.right = null;
                TreeNode node = currB;
                currB = currB.right;
                return node;
            }
        }

        return null;
    }

    public int solve(TreeNode A, TreeNode B) {
        currA = A;
        currB = B;
        long sum = 0;

        // Get the first inorder node from each tree.
        TreeNode nodeA = getNextA();
        TreeNode nodeB = getNextB();

        while (nodeA != null && nodeB != null) {
            if (nodeA.val == nodeB.val) {
                // The values match, so add once and advance both traversals.
                sum = (sum + nodeA.val) % MOD;
                nodeA = getNextA();
                nodeB = getNextB();
            } else if (nodeA.val < nodeB.val) {
                // Advance A, whose smaller value cannot match B's current value.
                nodeA = getNextA();
            } else {
                // Advance B, whose smaller value cannot match A's current value.
                nodeB = getNextB();
            }
        }

        // Finish both traversals so no temporary threads remain.
        while (getNextA() != null) {
            // Continue until BST A is restored.
        }
        while (getNextB() != null) {
            // Continue until BST B is restored.
        }

        return (int) sum;
    }
}

Why drain both iterators?

If one traversal finishes before the other, the comparison loop stops early. The other traversal may still have temporary threads in its tree. Finish both traversals before returning so both original tree structures are restored. This cleanup is essential because the comparison can stop before either traversal is complete.

6. Complexity Analysis — All Approaches

Let N and M be the numbers of nodes in BST A and BST B. Let \(H_1\) and \(H_2\) be their respective heights.

ApproachTimeAuxiliary space
HashSetExpected \(O(N+M)\)\(O(N+H_2)\)
Two stacks\(O(N+M)\)\(O(H_1+H_2)\)
Morris with iterator\(O(N+M)\)\(O(1)\)
Morris without iterator\(O(N+M)\)\(O(1)\)

Why is Morris traversal \(O(1)\) space?

Both Morris versions use existing left and right pointers to create temporary connections. They do not use recursion, explicit stacks, arrays, or HashSets. Each version maintains two current pointers, a few temporary node references, and a running sum, so its auxiliary space is constant.

Comparison

  • HashSet stores values.
  • Two stacks store traversal paths.
  • Both Morris approaches use temporary tree connections.
  • All approaches have linear time complexity. Morris is most space-efficient, but more complicated.

9. Interview Preparation Notes

Important concepts to remember

  1. BST inorder traversal produces sorted values.
  2. Two sorted sequences can be compared using two pointers.
  3. Iterative inorder traversal uses a stack.
  4. Morris traversal uses temporary threads instead of a stack.
  5. Morris traversal achieves \(O(1)\) auxiliary space.

Common interview questions

Q1. What is the biggest advantage of Morris traversal?
It achieves \(O(1)\) auxiliary space without recursion or an explicit stack.
Q2. Does Morris traversal modify the original tree?
Temporarily, yes. It creates threads by modifying right pointers and restores those pointers before completing traversal.
Q3. Is Morris traversal always better than stack-based traversal?
No. It saves memory but is more complicated and temporarily modifies the tree. Stack-based traversal is generally easier to maintain and debug.
Q4. Can Morris traversal cause problems if the tree is accessed concurrently?
Yes. Another operation accessing the same tree during traversal could observe its temporarily modified pointers.

The iterator version is easier to understand conceptually because next() clearly represents getting the next smallest node, and the iterator can be reused in other BST problems.
