3 Sum Closest — Java Solution

The recommended approach is Sorting + Two Pointers. It reduces the time complexity from \(O(N^3)\) to \(O(N^2)\), making it much more efficient for large arrays.

Recommended pattern: Sort the array, fix one element, and use two pointers to find the closest three-element sum.

1. Problem Understanding

You are given:

  • An integer array A.
  • An integer target B.

Select three elements at different indices whose sum is as close as possible to B. Return the sum, not the three elements themselves. The sum does not have to equal the target exactly.

Example 1

Input

A = [-1, 2, 1, -4]
B = 1

Possible combinations

  • -1 + 2 + 1 = 2; difference = 1
  • -1 + 2 + (-4) = -3; difference = 4
  • -1 + 1 + (-4) = -4; difference = 5
  • 2 + 1 + (-4) = -1; difference = 2

Output: 2. The sum 2 is closest to target 1.

Example 2

A = [1, 2, 3]
B = 6

There is only one possible combination: \(1+2+3=6\).

Output: 6

Important conditions

  • Choose exactly three elements at distinct indices.
  • Negative numbers and duplicate values are allowed.
  • Return the sum with the smallest absolute difference from B.
  • The problem guarantees a unique closest sum.
  • Although the stated constraints allow \(N=1\), a valid three-element selection requires \(N\geq3\); we assume the test cases satisfy this requirement.

2. Brute Force Approach

Intuition

Generate every possible combination of three elements, calculate its sum, and remember the sum closest to the target.

Algorithm

  1. Use three nested loops to select indices i, j, and k.
  2. Ensure i < j < k, so each combination is considered once.
  3. Calculate sum = A[i] + A[j] + A[k].
  4. If this sum is closer to B than the best sum found so far, update the answer.
  5. Return the closest sum after checking all combinations.

Java code — Brute force

public class Solution {
    public int threeSumClosest(int[] A, int B) {
        int n = A.length;

        // Initialize with the first valid combination.
        int closestSum = A[0] + A[1] + A[2];

        // Choose the first element.
        for (int i = 0; i < n - 2; i++) {

            // Choose the second element.
            for (int j = i + 1; j < n - 1; j++) {

                // Choose the third element.
                for (int k = j + 1; k < n; k++) {

                    int sum = A[i] + A[j] + A[k];

                    // Compare absolute distances from target B.
                    if (Math.abs(sum - B)
                            < Math.abs(closestSum - B)) {
                        closestSum = sum;
                    }
                }
            }
        }

        return closestSum;
    }
}

Complexity analysis

  • Time: \(O(N^3)\). Three nested loops examine every combination of three elements.
  • Auxiliary space: \(O(1)\). Only a few variables are used.

For \(N=10^4\), the number of combinations can reach approximately 166.6 billion. This approach is too slow for the maximum input size.

3. Optimized Approach — Sorting + Two Pointers

Why do we need optimization?

Brute force checks all possible triples. Sorting the array and using the two-pointer technique avoids checking every possible combination.

Intuition

First, sort the array in ascending order. For each element, fix it as the first element and use two pointers to find the other two elements:

  • i: index of the fixed first element.
  • left: index immediately after i.
  • right: index at the end of the array.

Calculate the sum of the three selected elements:

  • If sum == B, we have found the exact target. Return it immediately.
  • If sum < B, we need a larger sum, so move left to the right.
  • If sum > B, we need a smaller sum, so move right to the left.
  • After calculating each sum, update closestSum whenever the new sum is closer to B.

Because the array is sorted, moving left forward increases or preserves the sum, while moving right backward decreases or preserves it.

Algorithm step by step

  1. Sort array A.
  2. Initialize closestSum using the first three elements.
  3. Iterate i from 0 to N - 3.
  4. Initialize left = i + 1 and right = N - 1.
  5. While left < right, calculate the sum of the three values.
  6. Update closestSum if the new sum is closer to B.
  7. Return immediately if sum == B.
  8. Move left forward if sum < B; otherwise, move right backward.
  9. Return closestSum.

Complete Java solution

This is the recommended interview-ready solution for the given method signature.

import java.util.Arrays;

public class Solution {
    public int threeSumClosest(int[] A, int B) {
        int n = A.length;

        // Step 1: Sort the array.
        Arrays.sort(A);

        // Step 2: Start with any valid triple.
        int closestSum = A[0] + A[1] + A[2];

        // Step 3: Fix the first element.
        for (int i = 0; i < n - 2; i++) {

            // Step 4: Initialize the two pointers.
            int left = i + 1;
            int right = n - 1;

            // Step 5: Search for the best pair.
            while (left < right) {
                int sum = A[i] + A[left] + A[right];

                // Update the answer if this sum is closer.
                if (Math.abs(sum - B)
                        < Math.abs(closestSum - B)) {
                    closestSum = sum;
                }

                // An exact match is the best possible answer.
                if (sum == B) {
                    return sum;
                }

                // Move pointers to improve the sum.
                if (sum < B) {
                    left++;    // Need a larger sum.
                } else {
                    right--;   // Need a smaller sum.
                }
            }
        }

        return closestSum;
    }
}
Note: The code sorts A in place, so the original array order changes. This is acceptable for the usual coding-platform version of this problem.

The initial distance from the target is \(|-4-1|=5\).

Step 2: Fix the first element

Initially, i = 0:

A[i] = -4
left = 1

Now calculate the sum and adjust the pointers.

IterationileftrightSumDistance from 1Action
1013-34Move left

312321Update answer

Understand each iteration

Iteration 1

\(-4+(-1)+2=-3\). The distance is \(|-3-1|=4\), better than the previous distance of 5.

Update closestSum = -3. Since -3 < 1, move left forward.

Iteration 2

\(-4+1+2=-1\). The distance is \(|-1-1|=2\).

Update closestSum = -1. Since -1 < 1, move left forward again. Now left == right, so this search ends.

Next fixed element: i = 1

Now A[i] = -1, left = 2, and right = 3.

Iteration 3

\(-1+1+2=2\). The distance is \(|2-1|=1\).

Update closestSum = 2. Because 2 > 1, move right backward. The pointers meet, so the search ends.

The remaining fixed elements cannot produce a closer sum than 2 for this input.

Final output: 2
The sum \(-1 + 1 + 2 = 2\) has an absolute difference of 1 from the target.

Why are the pointer movements necessary?

  • sum < B: the sum is too small. Since the array is sorted, increasing left is the natural way to try for a larger sum.
  • sum > B: the sum is too large. Decreasing right tries for a smaller sum.
  • sum == B: no sum can be closer than an exact match, so returning immediately is safe.

5. Complexity Analysis

ApproachTime complexityAuxiliary spaceExplanation
Brute force\(O(N^3)\)\(O(1)\)Three nested loops
Sorting + two pointers\(O(N^2)\)\(O(\log N)\) typicallySorting plus a quadratic search

For the optimized solution:

  • Sorting takes \(O(N\log N)\).
  • The outer loop runs \(O(N)\) times.
  • For each fixed element, the two pointers together move at most \(O(N)\) times.
  • Therefore, the search takes \(O(N^2)\), which dominates sorting.

The auxiliary space of \(O(\log N)\) is typical for Java's primitive-array sorting implementation due to sorting-related stack usage; it is separate from the constant number of variables used by the search itself.

Potential pitfall

Do not compare sums directly with closestSum to decide which is better. Compare their absolute distances from B.

Math.abs(sum - B) < Math.abs(closestSum - B)

Also, initialize closestSum using a valid triple instead of 0, because 0 might not be a valid or close sum.

8. Interview Preparation Notes

Key concept to remember

Sorting + Two Pointers + Minimum Absolute Difference

This pattern is useful when you need to find a pair or triplet with a sum equal or close to a target.

Common mistakes

  • Forgetting to sort the array before using the two-pointer technique.
  • Moving the wrong pointer.
  • Comparing the sums instead of their distances from the target.
  • Initializing the answer to 0.
  • Using three nested loops in the final solution despite the large input constraint.

Likely interviewer follow-up questions

Q1. Why do we sort the array?

Sorting gives us an ordered structure, so we can decide which pointer to move based on whether the current sum is too small or too large.

Q2. Why is the optimized solution \(O(N^2)\)?

We fix one element in an outer loop, then scan the remaining elements using two pointers. The pointer scan is linear for each fixed element.

Q3. Can we use a HashSet instead?

A HashSet-based search can also solve related sum problems, but sorting plus two pointers is a straightforward and efficient approach for this problem.

Q4. What happens if two sums are equally close to the target?

The statement guarantees only one solution, so the closest sum is assumed to be unique. Without that guarantee, a tie-breaking rule would be needed if a specific answer were required.

9. Final Recommendation

Implement Sorting + Two Pointers in your interview.

  • Time complexity: \(O(N^2)\)
  • Auxiliary space: Typically \(O(\log N)\) for Java array sorting.
  • Pattern: Sorting + Two Pointers.

Remember this simple intuition: fix one element, use two pointers for the other two, and keep the sum with the smallest distance from the target.
