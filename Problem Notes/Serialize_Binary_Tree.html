Java Algorithm Guide

Serialize Binary Tree

The key concept is Level Order Traversal (BFS) using a queue, while recording every null child as -1.

Pattern to remember: Process real nodes in level order, enqueue both child positions, and write -1 for each missing child.

1. Problem Understanding

We are given the root of a binary tree. Convert the tree into an ArrayList<Integer> following these rules:

  • Visit nodes level by level, from left to right.
  • Add each node's value to the result.
  • If a node's left or right child is null, add -1 for that child.
  • Do not skip null children, because they are necessary to preserve the tree's structure.

Example tree

        1
       / \
      2   3
     / \
    4   5

Its serialized representation is [1, 2, 3, 4, 5, -1, -1, -1, -1, -1, -1].

There are six -1 values because nodes 3, 4, and 5 each have two missing children: \(3 \times 2 = 6\) null children.

2. Brute Force Approach

A separate brute-force approach is unnecessary here because the problem itself requires visiting the tree level by level. We can use the simplest correct BFS approach directly.

The important distinction is that we must add -1 for null children, rather than ignoring them as we might in an ordinary level-order traversal.

3. Optimized Approach — BFS Using a Queue

Intuition

Imagine processing the tree one node at a time in level order. For every actual node, record its value and put both children into the queue—even if a child is null.

When a null entry comes out of the queue, add -1 to the result. Do not add children for a null entry.

Java solution

import java.util.*;

public class Solution {
    public ArrayList<Integer> solve(TreeNode A) {
        ArrayList<Integer> result = new ArrayList<>();

        // Handle an empty tree (if permitted).
        if (A == null) {
            return result;
        }

        // LinkedList allows null entries, unlike ArrayDeque.
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(A);

        while (!queue.isEmpty()) {
            TreeNode node = queue.poll();

            if (node == null) {
                // Represent a missing child with -1.
                result.add(-1);
            } else {
                // Record the current node's value.
                result.add(node.val);

                // Add both children, including null children.
                queue.offer(node.left);
                queue.offer(node.right);
            }
        }

        return result;
    }
}

Algorithm step by step

  1. Create an empty result list and a queue.
  2. Insert the root into the queue.
  3. Remove the front entry from the queue.
  4. If it is null, append -1 to the result.
  5. Otherwise, append its value and enqueue its left and right children.
  6. Repeat until the queue becomes empty.
  7. Return the result.
Important: We use LinkedList instead of ArrayDeque because Java's ArrayDeque does not permit null elements.

4. Dry Run of the Optimized Solution

Consider the example tree:

        1
       / \
      2   3
     / \
    4   5

Initially, queue = [1] and result = [].

2 2 [1, 2] [3, 4, 5]

4 4 [1, 2, 3, 4] [5, null, null, null, null]

Final output:

The queue becomes empty because each real node contributes two child entries. Null entries are recorded, but they never produce further children.

5. Complexity Analysis

Let \(N\) be the number of actual nodes in the tree.

Time and space complexity of the serialization algorithm
Complexity Analysis
Time \(O(N)\) — each real node is processed once, and each of its two child positions is recorded once.
Auxiliary space \(O(N)\) — the queue can hold \(O(N)\) entries in the worst case.
Output space \(O(N)\) — the result contains \(N\) node values and \(N+1\) null markers, for \(2N+1\) entries.

The overall time and space complexities are both \(O(N)\). There is no need for a more complicated optimization: every node and null-child position must be represented in the output.

6. Edge Cases

  • Single node: A tree containing only 7 produces [7, -1, -1].
  • Left-skewed tree: Missing right children are recorded as -1 at every level.
  • Right-skewed tree: Missing left children are recorded as -1 at every level.
  • Complete binary tree: All actual nodes are visited in level order, and the leaf nodes' missing children are recorded.
  • Empty tree: The implementation returns an empty list. The stated constraints require at least one node, so this case is outside the required input.

8. Interview Preparation Notes

Pattern to remember: Binary Tree + BFS (Level Order Traversal) + Null Markers.

Common mistakes

  • Skipping null children instead of recording -1.
  • Using ArrayDeque while trying to enqueue null.
  • Accidentally adding children for a null entry, which would create an infinite expansion.
  • Stopping at the last non-null node and forgetting its missing children.

Likely interview follow-ups

Q1. Why is BFS appropriate?

Because the required output is level order, which a queue naturally produces.

Q2. Why must null children be recorded?

Without null markers, different tree structures can produce the same sequence of actual node values.

Q3. Can DFS solve this problem?

Yes, a preorder traversal with explicit null markers can serialize a tree, but it would not produce the required level-order representation.

Q4. Why does the output contain \(2N+1\) elements?

A binary tree with \(N\) nodes has \(2N\) child positions. Exactly \(N-1\) positions contain actual children, leaving \(N+1\) null positions.

9. Final Recommendation

Use the BFS queue solution in your interview. It directly follows the problem's required traversal order, handles missing children correctly, and runs in linear time.

  • Time: \(O(N)\)
  • Auxiliary space: \(O(N)\)
  • Output space: \(O(N)\)
Remember: Remove one queue entry, record its value or -1, and enqueue two children only when the entry is a real node.
