Delete a Node in a BST

Find the node with value B, delete it if it exists, and return the updated root of the Binary Search Tree (BST).

Key condition: When a node has two children, replace it with its in-order predecessor—the largest value in its left subtree—not its in-order successor.

1. Problem Understanding

A Binary Search Tree follows these rules:

  • Every value in the left subtree is smaller than the current node.
  • Every value in the right subtree is greater than the current node.
  • All node values are unique.

Delete the node whose value equals B while preserving these BST properties. Deletion has three cases:

Case 1 — Leaf

A node with no children is deleted by returning null for its subtree.

Case 2 — One child

Replace the node with its only child, whether that child is on the left or right.

Case 3 — Two children

Copy the in-order predecessor's value into the node, then delete the predecessor from the left subtree.

2. Brute-Force Approach

A straightforward alternative is to traverse the entire tree, find the target node and its parent, and handle its children according to the three deletion cases. This can take \(O(N)\) time and requires additional parent-tracking logic. A better approach uses the BST property to search only the relevant subtree.

3. Optimized Approach — Use BST Properties

Intuition

Compare B with the current node's value to decide which direction to search:

  • If B < A.val, search the left subtree.
  • If B > A.val, search the right subtree.
  • If B == A.val, the node is found; handle its deletion.

For a node with two children, the predecessor is the rightmost node in the left subtree.

Java Solution

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */
public class Solution {
    public TreeNode solve(TreeNode A, int B) {

        // An empty subtree means the target was not found on this path.
        if (A == null) {
            return null;
        }

        // Search the left subtree when the target is smaller.
        if (B < A.val) {
            A.left = solve(A.left, B);
        }

        // Search the right subtree when the target is greater.
        else if (B > A.val) {
            A.right = solve(A.right, B);
        }

        // The target node has been found.
        else {
            // With no left child, the right child replaces this node.
            if (A.left == null) {
                return A.right;
            }

            // With no right child, the left child replaces this node.
            if (A.right == null) {
                return A.left;
            }

            // Find the in-order predecessor: the largest value in the left subtree.
            TreeNode predecessor = A.left;
            while (predecessor.right != null) {
                predecessor = predecessor.right;
            }

            // Copy the predecessor value, then remove its original node.
            A.val = predecessor.val;
            A.left = solve(A.left, predecessor.val);
        }

        // Return this subtree's root so the parent can reconnect it.
        return A;
    }
}

Why assign the recursive result?

The recursive call may delete the root of a subtree or replace it with one of its children. Assigning the result, as in A.left = solve(A.left, B), ensures the parent points to the updated subtree. The same applies to the right subtree.

Why use the in-order predecessor?

Suppose the target node is 6, with left child 1 and right child 7:

    6
   / \
  1   7

The predecessor is the largest value in the left subtree, which is 1. Replace 6 with 1, then delete the original 1 node:

    1
     \
      7

This preserves the BST property and uses the required predecessor.

4. Dry Run of the Optimized Solution

Consider Example 2 and delete B = 6:

        8
       / \
      6   21
     / \
    1   7
  1. Search for 6. At node 8, 6 < 8, so move to the left child.
  2. Find the target. Node 6 is found. It has two children, so find its in-order predecessor.
  3. Find the predecessor. The left subtree contains only node 1, so the predecessor is 1.
  4. Replace and delete. Copy 1 into the target node, then delete the original node 1.

Final tree

        8
       / \
      1   21
       \
        7

The root remains 8; only the affected subtree changes.

5. Complexity Analysis

Let \(N\) be the number of nodes and \(H\) be the height of the tree.

Approach Time complexity Auxiliary space
Brute-force search without BST ordering \(O(N)\) \(O(H)\)
Optimized BST search and deletion \(O(H)\) \(O(H)\)
  • Searching takes \(O(H)\). Finding the predecessor and deleting it also takes at most \(O(H)\), so total time is \(O(H)\).
  • Recursion uses \(O(H)\) stack space.
  • For a balanced BST, \(H = O(\log N)\), so time and auxiliary space are \(O(\log N)\).
  • For a skewed BST, \(H = O(N)\), so both can reach \(O(N)\).

Brute-force alternative

A brute-force search ignores BST ordering and explores both subtrees until it finds the target. It can visit every node, requiring \(O(N)\) time and \(O(H)\) recursive stack space. The optimized approach is preferable because it avoids searching irrelevant subtrees.

6. Important Edge Cases

Case Expected behavior
Target is a leafReturn null for that subtree.
Target has only a left childReturn its left child.
Target has only a right childReturn its right child.
Target has two childrenReplace it with the in-order predecessor.
Target is the rootReturn the updated root after deletion.
Target does not existThe original tree remains unchanged.
Target is the minimum or maximum valueDelete it using its applicable child case.
Tree is skewedThe algorithm remains correct, but recursion can reach \(O(N)\) depth.

8. Interview Preparation Notes

Pattern to remember: BST search + recursive subtree updates + in-order predecessor.

Common mistakes

  • Using the in-order successor when the problem explicitly requires the predecessor.
  • Finding the predecessor but forgetting to delete its original node.
  • Forgetting to assign A.left = solve(...) or A.right = solve(...).
  • Forgetting that deleting the root may change the root returned to the caller.
  • Returning null when the target is absent instead of preserving the unchanged subtree.

Likely interviewer follow-ups

Q1. What is the in-order predecessor?
The largest value in a node's left subtree, found by moving as far right as possible from its left child.
Q2. Why not simply remove a node with two children?
Removing it directly would leave two subtrees to reconnect. Replacing it with the predecessor preserves BST ordering while allowing the predecessor to be removed using a simpler case.
Q3. What happens if B is not present?
The search eventually reaches null, and the tree remains unchanged.
Q4. Can this algorithm be iterative?
Yes. An iterative implementation can search for the target and predecessor while tracking parent pointers. This avoids recursive call-stack usage, though it requires more bookkeeping.

9. Final Recommendation

Use the recursive BST deletion approach with the in-order predecessor. It is concise, interview-friendly, and follows the problem's explicit requirement.

  • Time complexity: \(O(H)\), worst case \(O(N)\).
  • Auxiliary space: \(O(H)\), worst case \(O(N)\).
Memory trick: Search using BST ordering → handle zero or one child directly → for two children, copy the largest value from the left subtree → delete its original node.
