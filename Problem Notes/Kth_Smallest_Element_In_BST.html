Kth Smallest Element in BST

Find the element at position B when the values of a binary search tree are arranged in ascending order.

Recommended approach: Use inorder traversal to visit BST values in sorted order, count each visited node, and stop at the Bth node.

1. Problem Understanding

You are given:

  • A: The root of a Binary Search Tree.
  • B: The 1-based position of the smallest element to find.

Return the element at position B in ascending order.

A BST has the following property:

  • All values in the left subtree are smaller than the node's value.
  • All values in the right subtree are greater than the node's value.

Therefore, inorder traversal (Left → Root → Right) visits BST elements in sorted ascending order. This lets us find the Bth smallest value without sorting the entire tree.

Example 1

Inorder traversal: 1 → 2 → 3

  • 1st smallest = 1
  • 2nd smallest = 2
  • 3rd smallest = 3

Output: 2

Example 2

Inorder traversal: 1 → 2 → 3

Output: 1

2. Brute Force Approach

Intuition

Visit every node, store its value in a list, sort the list in ascending order, and return the element at index B - 1. We subtract one because Java lists use zero-based indexing.

Java code

import java.util.*;

public class Solution {
    public int kthsmallest(TreeNode A, int B) {
        List<Integer> values = new ArrayList<>();

        // Collect every node value.
        collectValues(A, values);

        // Sort values in ascending order.
        Collections.sort(values);

        // B is 1-based, but list indices are 0-based.
        return values.get(B - 1);
    }

    private void collectValues(TreeNode node, List<Integer> values) {
        if (node == null) {
            return;
        }

        // Add this node before collecting values from its children.
        values.add(node.val);
        collectValues(node.left, values);
        collectValues(node.right, values);
    }
}

Complexity

  • Time: \(O(N\log N)\), because sorting \(N\) node values takes \(O(N\log N)\).
  • Auxiliary space: \(O(N)\) to store values, plus \(O(H)\) recursion stack space, where \(H\) is the tree height.

Limitation: This sorts all elements even though only one is needed. The BST already provides a more efficient way to find the answer.

3. Optimized Approach — Inorder Traversal

Intuition

Because the tree is a BST, inorder traversal automatically visits values from smallest to largest.

  1. Traverse the left subtree.
  2. Visit the current node and increase a counter.
  3. If the counter equals B, save the current value.
  4. Otherwise, traverse the right subtree.
  5. Stop as soon as the Bth element is found.

This avoids visiting unnecessary nodes when the answer appears early.

Java solution (recommended)

/**
 * Definition for binary tree
 * class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) {
 *         val = x;
 *         left = null;
 *         right = null;
 *     }
 * }
 */
public class Solution {

    private int count;
    private int answer;

    public int kthsmallest(TreeNode A, int B) {
        // Reset state so repeated calls on this Solution instance are independent.
        count = 0;
        inorder(A, B);
        return answer;
    }

    private boolean inorder(TreeNode node, int B) {
        // No node to visit.
        if (node == null) {
            return false;
        }

        // Visit smaller elements first.
        if (inorder(node.left, B)) {
            return true;
        }

        // Process the current node.
        count++;

        // The Bth visited node is the answer.
        if (count == B) {
            answer = node.val;
            return true;
        }

        // Search larger elements only if needed.
        return inorder(node.right, B);
    }
}

Understanding the important variables

VariablePurpose
countCounts the nodes visited in sorted order.
answerStores the Bth smallest value.
BThe required position in ascending order.
nodeThe current node being processed.
Why does inorder() return a boolean? Recursive calls use the return value to signal that the answer has already been found. Each parent then stops exploring its remaining subtree.

4. Dry Run of the Optimized Solution

Consider this BST with B = 2. The inorder traversal visits 1, then 2, then 3.

  1. Start at node 2.
  2. Move to its left child, node 1.
  3. Node 1 has no left child, so visit it. Now count = 1.
  4. Since count is not B, continue.
  5. Return to node 2 and visit it. Now count = 2.
  6. Since count == B, save answer = 2 and stop.
Step Node visited Count Answer
111Not found
2222 — found

Node 3 is never visited because the answer has already been found. Final output: 2.

5. Complexity Analysis

Let \(N\) be the number of nodes, \(H\) the tree height, and \(K=B\).

Approach Time complexity Auxiliary space
Collect and sort\(O(N\log N)\)\(O(N+H)\)
Inorder traversal with early stopping\(O(N)\) worst case\(O(H)\)
  • Worst-case time: \(O(N)\), when the required element is the largest or near the end of the traversal.
  • Best-case bound: \(O(H+K)\) for the nodes and recursive traversal needed to reach the \(K\)th node; more precisely, work is proportional to the portion of the tree visited.
  • Auxiliary space: \(O(H)\) for recursion. A balanced BST has \(H=O(\log N)\), while a skewed BST can have \(H=O(N)\).

The optimized approach is preferable because it does not store or sort all node values.

8. Interview Preparation Notes

Key concept to remember: BST + Inorder Traversal = Sorted Order. When asked for the Kth smallest element in a BST, consider inorder traversal with a counter.

Common mistakes

  • Using preorder or postorder traversal and assuming the elements will be sorted.
  • Returning values.get(B) instead of values.get(B - 1) in the brute-force approach.
  • Forgetting to stop recursion once the answer has been found.
  • Forgetting to reset count before each call to kthsmallest().
  • Assuming recursion uses constant space; its stack depends on tree height.

Likely follow-up questions

Q1. How would you find the Kth largest element?

Use reverse inorder traversal: Right → Root → Left. Count visited nodes until the counter reaches B.

Q2. Can you solve it iteratively?

Yes. Use a stack to perform iterative inorder traversal and stop at the Bth popped node.

Q3. What if we need to find many Kth-smallest queries on the same BST?

Store the subtree size at each node during preprocessing. These sizes can help answer each query in \(O(H)\) time, assuming the tree remains unchanged and subtree sizes are maintained correctly.

Q4. What if the BST is skewed?

Its height can become \(O(N)\), so recursion can use \(O(N)\) stack space and may risk stack overflow for 100,000 nodes. An iterative stack-based traversal avoids recursive call-stack overflow.

9. Final Recommendation

Use inorder traversal with early stopping for this problem. It is straightforward, efficient, and interview-friendly.

  • Time: \(O(N)\) worst case.
  • Auxiliary space: \(O(H)\) for the recursive implementation.
  • Core intuition: Visit nodes in sorted order, count them, and stop at the Bth node.

Remember this pattern: whenever a problem asks for the smallest or largest element in a BST by rank, think about inorder or reverse inorder traversal first.
