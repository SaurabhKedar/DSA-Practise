Java Algorithm Guide

Sum Binary Tree

The best approach is postorder depth-first search with recursion. Every non-leaf node must equal the sum of all values in its left and right subtrees.

Recommended pattern: Return each subtree's sum to its parent and propagate an invalid-state marker as soon as a subtree fails.

1. Problem Understanding

A binary tree is a Sum Binary Tree if:

  • Every leaf node is considered valid automatically.
  • Every non-leaf node's value equals the sum of all nodes in its left subtree and right subtree.
  • An empty subtree has a sum of 0.
  • Return 1 if the entire tree satisfies the condition; otherwise, return 0.

For example, consider this tree:

        26
       /  \
     10    3
    / \     \
   4   6     3

Check each non-leaf node:

  • Node 10: \(4+6=10\) — valid.
  • Node 3: \(0+3=3\) — valid because its right child is 3 and its left subtree is empty.
  • Root 26: the left subtree sum is \(10+4+6=20\), and the right subtree sum is \(3+3=6\). Therefore, \(20+6=26\) — valid.

The answer is 1.

Important: Use the sum of the entire subtrees, not just the immediate children.

2. Brute-Force Approach

Intuition

For every non-leaf node:

  1. Calculate the sum of its entire left subtree.
  2. Calculate the sum of its entire right subtree.
  3. Check whether their sum equals the current node's value.
  4. Recursively check the left and right subtrees.

If any node fails, the tree is not a Sum Binary Tree.

Java code — brute force

public class Solution {

    // Calculates the sum of all nodes in a subtree.
    private long getSum(TreeNode node) {
        if (node == null) {
            return 0L;
        }

        return node.val
                + getSum(node.left)
                + getSum(node.right);
    }

    // Checks whether the subtree rooted at node is a Sum Tree.
    private boolean isSumTree(TreeNode node) {
        // An empty tree or leaf node is valid.
        if (node == null || (node.left == null && node.right == null)) {
            return true;
        }

        // Calculate the sums of both subtrees.
        long leftSum = getSum(node.left);
        long rightSum = getSum(node.right);

        // Current node must equal the sum of both subtrees.
        if (node.val != leftSum + rightSum) {
            return false;
        }

        // Both subtrees must also satisfy the Sum Tree property.
        return isSumTree(node.left) && isSumTree(node.right);
    }

    public int solve(TreeNode A) {
        return isSumTree(A) ? 1 : 0;
    }
}

Brute-force dry run

For the first example:

Node Left subtree sum Right subtree sum Check
1046\(4+6=10\) ✓
303\(0+3=3\) ✓
26206\(20+6=26\) ✓

Every node passes, so solve(A) returns 1.

Complexity

  • Time: \(O(n^2)\) in the worst case. We repeatedly calculate subtree sums, and a skewed tree can require scanning most of the tree for many nodes.
  • Auxiliary space: \(O(h)\), where \(h\) is the tree height, due to recursion. In the worst case, this is \(O(n)\).

Limitation: Many nodes are visited repeatedly. We can avoid this by calculating each subtree's sum only once.

3. Optimized Approach — Postorder DFS

Intuition

Instead of calculating subtree sums separately, calculate them while checking whether each subtree is valid. For every node, return its total subtree sum to its parent, but immediately report failure if the subtree is not a Sum Tree.

Postorder traversal visits the left subtree, then the right subtree, and finally processes the current node. This ensures that both subtree sums are available when we check the current node.

Algorithm

  1. If the node is null, return 0.
  2. If the node is a leaf, return its value because a leaf is always valid.
  3. Recursively process the left and right subtrees.
  4. If either subtree returns -1, propagate -1 because that subtree is invalid.
  5. Check whether node.val == leftSum + rightSum.
  6. If the check fails, return -1.
  7. Otherwise, return the total sum of the current subtree: node.val + leftSum + rightSum.
  8. In solve(), return 1 if the helper returns a nonnegative value; otherwise, return 0.

We use -1 as an invalid-tree marker because all node values are nonnegative, so a valid subtree sum cannot be negative.

Optimized Java solution

This is the recommended solution for the platform's required Solution class and solve(TreeNode A) signature.

public class Solution {

    // Returns the subtree sum if valid, otherwise -1.
    private long checkSumTree(TreeNode node) {

        // An empty subtree has sum 0.
        if (node == null) {
            return 0L;
        }

        // Every leaf node is automatically a Sum Tree.
        if (node.left == null && node.right == null) {
            return node.val;
        }

        // Get the sums of the left and right subtrees.
        long leftSum = checkSumTree(node.left);
        long rightSum = checkSumTree(node.right);

        // If either subtree is invalid, the current tree is invalid.
        if (leftSum == -1L || rightSum == -1L) {
            return -1L;
        }

        // Current node must equal the sum of both subtrees.
        if (node.val != leftSum + rightSum) {
            return -1L;
        }

        // Return the sum of the entire subtree for the parent.
        return node.val + leftSum + rightSum;
    }

    public int solve(TreeNode A) {
        return checkSumTree(A) == -1L ? 0 : 1;
    }
}

Why this approach works

Each node is processed only after its children have been processed. Therefore, the helper already knows whether each child subtree is valid and what its total sum is.

If a child subtree is invalid, the failure propagates upward. If both children are valid and their sums equal the current node's value, the current subtree is valid, and its total sum is returned. This checks every node exactly once.

5. Complexity Analysis

Let \(n\) be the number of nodes and \(h\) be the height of the tree.

Approach Time complexity Auxiliary space
Brute force\(O(n^2)\) worst case\(O(h)\)
Optimized postorder DFS\(O(n)\)\(O(h)\)

Why is the optimized time \(O(n)\)?

Each node is visited once, and each visit performs constant-time checks and arithmetic. Therefore, the total work is proportional to the number of nodes.

Why is the space \(O(h)\)?

The recursive call stack can hold up to \(h\) calls at once. A balanced tree has height approximately \(O(\log n)\), while a highly skewed tree can have height \(O(n)\).

Practical note: The constraints permit up to 100,000 nodes. A deeply skewed tree may cause a Java StackOverflowError with a recursive implementation. If the platform's hidden tests include extremely deep trees, an iterative postorder traversal can avoid that risk.

8. Interview Preparation Notes

Key concept to remember

Postorder DFS + subtree sum + invalid-state propagation. The same pattern is useful whenever a parent needs information computed from its children.

Common mistakes

  1. Checking only the immediate children instead of the entire subtrees.
  2. Forgetting that a leaf node is automatically valid.
  3. Returning only node.val instead of the entire subtree sum.
  4. Checking the current node without verifying that both child subtrees are valid.
  5. Using -1 as an error marker without ensuring valid results cannot equal -1.

Likely interviewer follow-up questions

Q1. Why do we use postorder traversal?
Because we need both subtree sums before validating the parent node.
Q2. Why can't we simply compare the root with its two children?
Because the required sum includes every node in each subtree, not just the direct children.
Q3. Why does the helper return the subtree sum instead of a boolean?
The parent needs the child's total subtree sum to validate its own value. Returning the sum lets us validate and calculate in one traversal.
Q4. Can this be solved in \(O(n)\) time?
Yes. Postorder DFS visits every node once and computes each subtree sum as it returns.

9. Final Recommendation

Use the optimized postorder DFS solution in an interview.

  • Time: \(O(n)\)
  • Auxiliary space: \(O(h)\)
  • Pattern: Postorder DFS with subtree information returned to the parent.

Remember this simple rule: validate both children, compare the current node with their subtree sums, and return the total subtree sum upward.
