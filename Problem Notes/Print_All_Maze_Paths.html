Recursion & Backtracking

Print All Maze Paths

Java — brute force and the provided recursive approach

This problem is a classic recursion and backtracking problem. We will use the provided code as the optimized approach and explain how it works, why it produces lexicographically sorted paths, and how it compares with the brute-force solution.

1. Problem Understanding

We are given two integers, A and B, representing the number of rows and columns in a rectangular grid.

Return all possible paths from the top-left cell \((0, 0)\) to the bottom-right cell \((A - 1, B - 1)\).

Allowed movements:

  • D — move one cell down.
  • R — move one cell right.

The returned paths must be in lexicographical order.

Constraints

  • \(1 \le A, B \le 8\)
  • The output is an ArrayList<String>.
  • Every valid path must reach the destination without leaving the grid.

Example: \(A = 3, B = 2\)

The grid has three rows and two columns. We need two downward moves and one rightward move to reach the destination.

  • DDR — down, down, right.
  • DRD — down, right, down.
  • RDD — right, down, down.

Output:

[DDR, DRD, RDD]

Since D comes before R alphabetically, the paths are returned in lexicographical order.

Another example: for \(A = 1, B = 2\), the output is [R]. There is only one possible move: right.

2. Brute Force Approach

Intuition

The simplest approach is to explore every possible sequence of moves. At each cell:

  1. Try moving down by increasing the row.
  2. Try moving right by increasing the column.
  3. If the current position goes beyond the destination row or column, stop that recursive call.
  4. When we reach the destination, save the current path.

Because we explore D before R, the paths are generated in lexicographical order.

Java code — brute force

import java.util.*;

public class Solution {

    public ArrayList<String> PrintAllPaths(int A, int B) {
        ArrayList<String> result = new ArrayList<>();

        // Start at the top-left cell with an empty path.
        findPaths("", result, 0, 0, A - 1, B - 1);

        return result;
    }

    private void findPaths(
            String current,
            ArrayList<String> result,
            int currRow,
            int currCol,
            int destRow,
            int destCol) {

        // Stop if we move beyond the destination boundaries.
        if (currRow > destRow || currCol > destCol) {
            return;
        }

        // Save the path when we reach the destination.
        if (currRow == destRow && currCol == destCol) {
            result.add(current);
            return;
        }

        // Try moving Down.
        findPaths(current + "D", result,
                  currRow + 1, currCol, destRow, destCol);

        // Try moving Right.
        findPaths(current + "R", result,
                  currRow, currCol + 1, destRow, destCol);
    }
}

Brute-force dry run

For \(A = 3, B = 2\), the destination is \((2, 1)\).

  1. Start at \((0, 0)\) with "".
  2. Choose D, reaching \((1, 0)\) with "D".
  3. Choose D, reaching \((2, 0)\) with "DD".
  4. Choose R, reaching \((2, 1)\) with "DDR". Save it.
  5. Backtrack to "D" and choose R, reaching \((1, 1)\) with "DR".
  6. Choose D, reaching \((2, 1)\) with "DRD". Save it.
  7. Return to the start and choose R. Continue down twice to obtain "RDD". Save it.

Final result:

[DDR, DRD, RDD]

Complexity analysis

Let \(P\) be the number of valid paths and \(L = A + B - 2\) be the number of moves per path.

  • Time: \(O(P \cdot L)\) for generating and storing all paths, plus a constant-factor overhead from invalid boundary calls.
  • Auxiliary space: Up to \(O(L^2)\) for the active recursion and intermediate immutable strings in this implementation.
  • Output space: \(O(P \cdot L)\) for storing all paths.

The limitation is that string concatenation creates new strings repeatedly. The provided approach uses the same general recursion strategy but makes the code more direct by passing the destination coordinates and checking the boundaries.

3. Optimized Approach — Your Code

This approach uses recursion and explores both possible moves, D and R, while checking whether the current position has gone beyond the destination.

Complexity note: This is a clean backtracking solution, but it does not improve the asymptotic time complexity over brute force. It still uses immutable strings and concatenation. Its advantages are straightforward boundary handling and automatic lexicographical ordering without a separate sorting step.

Your optimized code — adapted to the platform template

import java.util.*;

public class Solution {

    public ArrayList<String> PrintAllPaths(int A, int B) {
        ArrayList<String> result = new ArrayList<>();

        // Start with an empty path at cell (0, 0).
        backtrack("", result, 0, 0, A - 1, B - 1);

        return result;
    }

    private void backtrack(
            String current,
            ArrayList<String> result,
            int currRow,
            int currCol,
            int destRow,
            int destCol) {

        // Stop if we move outside the grid boundaries.
        if (currRow > destRow || currCol > destCol) {
            return;
        }

        // If we reach the destination, save the complete path.
        if (currRow == destRow && currCol == destCol) {
            result.add(current);
            return;
        }

        // Option 1: Move Down.
        String newStr = current + "D";
        backtrack(newStr, result,
                  currRow + 1, currCol, destRow, destCol);

        // Option 2: Move Right.
        newStr = current + "R";
        backtrack(newStr, result,
                  currRow, currCol + 1, destRow, destCol);
    }
}

Understanding the important parts

  1. 1. Initialize the result and start recursion

    ArrayList<String> result = new ArrayList<>();

backtrack("", result, 0, 0, A - 1, B - 1);
    • result stores all completed paths.
    • "" means no moves have been made yet.
    • \((0, 0)\) is the starting cell.
    • \((A - 1, B - 1)\) is the destination.

  2. 2. Stop invalid paths

    if (currRow > destRow || currCol > destCol) {
    return;
}

    If the row exceeds the destination row or the column exceeds the destination column, the path is invalid. For example, in a \(3 \times 2\) grid, the valid row indices are \(0, 1, 2\). Reaching row \(3\) means we have gone outside the grid.

  3. 3. Save a complete path

    if (currRow == destRow && currCol == destCol) {
    result.add(current);
    return;
}

    When both coordinates match the destination, save the complete path and return without exploring further.

  4. 4. Explore downward

    String newStr = current + "D";

backtrack(newStr, result,
          currRow + 1, currCol, destRow, destCol);

    Append D, increase the row by one, and recursively explore that path.

  5. 5. Explore rightward

    newStr = current + "R";

backtrack(newStr, result,
          currRow, currCol + 1, destRow, destCol);

    Append R, increase the column by one, and explore the next path.

    Notice that newStr is reassigned to current + "R", not appended to the previous newStr. This ensures that the rightward branch starts from the original path.

Why is the output sorted?

The recursive calls always explore D before R. Since D comes before R alphabetically, all paths beginning with D are generated before paths beginning with R. The same rule applies recursively at every position. Therefore, we do not need Collections.sort(result).

5. Complexity Analysis

Let \(L = A + B - 2\) be the length of every complete path, and let \(P\) be the number of valid paths:

\[P = \binom{A + B - 2}{A - 1}\]
ComplexityYour code
Time\(O(P \cdot L)\)
Auxiliary space\(O(L^2)\)
Output space\(O(P \cdot L)\)
  • Time: We must generate and store every valid path. Since each path has \(L\) moves, generating the output takes \(O(P \cdot L)\) time. String concatenation also copies characters, contributing to this bound.
  • Auxiliary space: The recursion depth is \(O(L)\), but each recursive frame can retain a string of length up to \(O(L)\). Therefore, the worst-case auxiliary space for this implementation is \(O(L^2)\).
  • Output space: Storing all \(P\) paths, each of length \(L\), requires \(O(P \cdot L)\) space.

8. Interview Preparation Notes

Key concept

Remember recursion, backtracking, and boundary checks. The method explores two choices at every step:

  • Move down and continue.
  • Move right and continue.

If a path reaches the destination, save it. If it goes beyond the destination boundaries, stop that branch.

Common mistakes

  1. Using currRow >= destRow as the invalid condition instead of currRow > destRow. Reaching the destination row is valid.
  2. Forgetting to check both row and column in the destination condition.
  3. Exploring R before D and assuming the output will still be lexicographically sorted.
  4. Assuming this implementation is asymptotically faster than all other recursive solutions. It still uses string concatenation, which has a cost.

Possible follow-up questions

Q1. Why don't we need to sort the result?

Because D is explored before R at every recursive step.

Q2. Why does the number of paths grow quickly?

Each path consists of \(A - 1\) downward moves and \(B - 1\) rightward moves. The number of ways to arrange these moves is a binomial coefficient.

Q3. Can we reduce auxiliary space?

Yes. Using a shared StringBuilder and undoing each move after recursion reduces auxiliary space to \(O(L)\), while preserving the same \(O(P \cdot L)\) time complexity.

Q4. Is this dynamic programming?

No. This solution enumerates every path using recursion and backtracking. Dynamic programming is more useful when we need to count paths or compute an optimal path without listing every possible path.
