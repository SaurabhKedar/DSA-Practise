Java Algorithm Guide

Letter Phone

Generate all letter combinations for a digit string using the telephone keypad mapping and backtracking.

Recommended pattern: Choose a letter for the current digit, recursively explore the next digit, and collect a result when every digit has been processed.

This note uses immutable Java String values for the current combination. Each recursive call receives current + ch, so no manual character removal is needed.

1. Problem Understanding

Given a digit string A, return all possible letter combinations based on the telephone keypad mapping.

The special rules are:

  • Digit 0 maps to "0".
  • Digit 1 maps to "1".
  • Digits 2 through 9 map to their corresponding letters.
  • The output must be in lexicographical order.

For example, with A = "23":

  • 2 maps to a, b, c.
  • 3 maps to d, e, f.

The output is:

["ad", "ae", "af", "bd", "be", "bf", "cd", "ce", "cf"]

For input "012", the output is:

["01a", "01b", "01c"]

The input length satisfies \(1 \le |A| \le 10\).

2. Brute Force Approach

A simple approach is to generate every possible string of length N using digits 0 through 9, check each candidate against the telephone mapping, and keep only valid strings.

Steps

  1. Generate all strings of length N.
  2. Check each position against the corresponding digit's mapping.
  3. Store valid strings.
  4. Sort the results lexicographically.

Java code

import java.util.*;

public class Solution {

    public String[] letterCombinations(String A) {
        List<String> result = new ArrayList<>();

        generateAll(A, 0, "", result);
        Collections.sort(result);

        return result.toArray(new String[0]);
    }

    private void generateAll(
            String A, int index, String current,
            List<String> result) {

        // A complete candidate string has been generated.
        if (index == A.length()) {
            if (isValid(A, current)) {
                result.add(current);
            }
            return;
        }

        // Try all ten digits at the current position.
        for (char ch = '0'; ch <= '9'; ch++) {
            generateAll(A, index + 1, current + ch, result);
        }
    }

    private boolean isValid(String A, String candidate) {
        String[] mapping = {
            "0", "1", "abc", "def", "ghi",
            "jkl", "mno", "pqrs", "tuv", "wxyz"
        };

        for (int i = 0; i < A.length(); i++) {
            int digit = A.charAt(i) - '0';

            if (!mapping[digit].contains(
                    String.valueOf(candidate.charAt(i)))) {
                return false;
            }
        }

        return true;
    }
}

Complexity

  • Time: \(O(N \cdot 10^N)\) for generating and validating candidates, excluding the additional sorting cost.
  • Auxiliary space: \(O(N^2)\) for the active recursion path and its intermediate immutable strings, excluding stored results.

This approach is inefficient because it generates many strings that cannot possibly be valid.

3. Optimized Approach — Backtracking Using String

Intuition

Instead of generating every possible string and checking it afterward, generate only valid combinations. For input "23", choose a from digit 2, then choose d, e, or f from digit 3 to form ad, ae, and af. Then return to digit 2 and repeat with b and c.

The recursive call receives current + ch. Since String is immutable, the original current remains unchanged.

Optimized Java code

import java.util.*;

public class Solution {

    public ArrayList<String> letterCombinations(String A) {
        ArrayList<String> result = new ArrayList<>();

        // Map each digit to its corresponding letters.
        String[] mapping = {
            "0", "1", "abc", "def", "ghi",
            "jkl", "mno", "pqrs", "tuv", "wxyz"
        };

        // Start generating combinations from index 0.
        backtrack(A, 0, "", result, mapping);

        // This mapping and traversal order already produce lexicographical order.
        return result;
    }

    private void backtrack(
            String A,
            int index,
            String current,
            ArrayList<String> result,
            String[] mapping) {

        // If all digits have been processed, save one complete combination.
        if (index == A.length()) {
            result.add(current);
            return;
        }

        // Find the letters corresponding to the current digit.
        int digit = A.charAt(index) - '0';
        String letters = mapping[digit];

        // Try every possible letter for this digit.
        for (int i = 0; i < letters.length(); i++) {
            char ch = letters.charAt(i);

            // Each recursive call receives a new String value.
            backtrack(
                A,
                index + 1,
                current + ch,
                result,
                mapping
            );
        }
    }
}

Why don't we need deleteCharAt()?

With a mutable StringBuilder, the same object is changed and shared between recursive calls, so the change must be undone before exploring the next choice: 

current.append(ch);
backtrack(A, index + 1, current, result, mapping);
current.deleteCharAt(current.length() - 1);

With an immutable String, pass a new value into the next call:

backtrack(A, index + 1, current + ch, result, mapping);

Here, current + ch creates a new string. The parent call's current is unaffected when the recursive call returns.

Example strings created from the unchanged prefix a
Current prefix Recursive call New string
"a"current + 'd'"ad"
"a"current + 'e'"ae"
"a"current + 'f'"af"

Interview takeaway: You still perform backtracking in the logical sense by exploring alternative choices. You do not need to manually undo a string modification when using immutable String objects.

5. Complexity Analysis

Let N be the input length and K the total number of generated combinations.

Brute force

  • Time: \(O(N \cdot 10^N)\) to generate and validate candidates, plus sorting the valid results.
  • Auxiliary space: \(O(N^2)\) for the active recursion path and intermediate immutable strings, excluding the output list.

Optimized backtracking using String

  • Time: \(O(NK)\) for inputs with branching choices across the generated combinations. In the general case, repeated string concatenation is bounded by \(O(N^2K)\), including inputs with long runs of digits 0 and 1.
  • Auxiliary space: \(O(N^2)\) in the worst case for the active recursive path and its intermediate immutable strings, excluding the output list.
  • Output space: \(O(NK)\) to store all combinations.

String concatenation copies the prefix used for each recursive call. When every digit has multiple choices, the recursion tree has exponentially many combinations and the total work is commonly expressed as \(O(NK)\). With digits that each have only one choice, such as all 0s and 1s, the single path still copies prefixes of increasing length, which takes \(O(N^2)\).

With StringBuilder, the active combination can be maintained in \(O(N)\) auxiliary space, and append/delete operations avoid repeatedly constructing intermediate strings. The String version is simpler to reason about, while StringBuilder is more memory-efficient during recursion.

8. Interview Preparation Notes

Key pattern

Backtracking = Choose → Explore → Undo. With a mutable structure such as StringBuilder, explicitly undo changes. With immutable strings, each recursive call gets a newly constructed value, so the undo step is unnecessary.

Common mistakes

  • Forgetting that 0 and 1 map to themselves.
  • Using the wrong digit index when looking up the mapping.
  • Adding the result before all digits have been processed.
  • Sorting unnecessarily when traversal already guarantees lexicographical order.
  • Underestimating the memory cost of repeated string concatenation.

Likely follow-up questions

Q1. Is String better than StringBuilder here?

String is simpler and eliminates explicit character removal. StringBuilder generally uses less auxiliary memory and avoids repeated string construction.

Q2. Does using String mean we are no longer using backtracking?

No. We are still exploring different recursive choices. We simply do not need to undo mutations because strings are immutable.

Q3. Why does the result come out sorted?

Each digit's mapping is traversed in alphabetical order, and the recursive traversal processes earlier positions before later ones. This produces lexicographical ordering.

Q4. What determines the number of combinations?

Multiply the number of available choices for every digit. For "23", there are \(3 \times 3 = 9\) combinations.

9. Final Recommendation

For your current learning stage, the String-based backtracking solution is a good choice because the code is easy to understand and does not require explicit cleanup.

  • Time complexity: \(O(NK)\) for inputs with branching choices; \(O(N^2K)\) is a general upper bound when accounting for repeated immutable string concatenation.
  • Auxiliary space: \(O(N^2)\) worst case for the active recursive path and intermediate strings.
  • Output space: \(O(NK)\).
Remember: Pass current + ch into the recursive call. Since strings are immutable, each path gets its own value, and deleteCharAt() is not needed.
