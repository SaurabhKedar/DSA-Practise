Java Algorithm Guide

Array 3 Pointers

This classic three-pointer and greedy problem uses the sorted order of three arrays to find the smallest possible maximum pairwise difference in \(O(N+M+P)\) time.

Recommended pattern: Calculate the current range, save the best difference, and move the pointer at the smallest value.

1. Problem Understanding

You are given three sorted arrays A, B, and C. Choose one element from each array so that this expression is as small as possible:

\[\max(|A[i]-B[j]|,\ |B[j]-C[k]|,\ |C[k]-A[i]|)\]

In simple words, choose three numbers—one from each array—whose maximum pairwise difference is minimized. For any three numbers, the expression simplifies to:

\[\boxed{\max(A[i],B[j],C[k])-\min(A[i],B[j],C[k])}\]

The largest difference between any two numbers is always the maximum number minus the minimum number.

Example

A = [1, 4, 10]
B = [2, 15, 20]
C = [10, 12]

Choose 10 from A, 15 from B, and 10 from C:

  • \(|10-15|=5\)
  • \(|15-10|=5\)
  • \(|10-10|=0\)

Maximum difference: max(5, 5, 0) = 5. Therefore, the answer is 5.

2. Brute Force Approach

Intuition

Try every possible combination of one element from each array, calculate the maximum pairwise difference, and keep track of the minimum value found.

Java code

public class Solution {
    public int minimize(final int[] A, final int[] B, final int[] C) {
        int ans = Integer.MAX_VALUE;

        // Try every possible triplet.
        for (int i = 0; i < A.length; i++) {
            for (int j = 0; j < B.length; j++) {
                for (int k = 0; k < C.length; k++) {
                    int max = Math.max(A[i], Math.max(B[j], C[k]));
                    int min = Math.min(A[i], Math.min(B[j], C[k]));
                    ans = Math.min(ans, max - min);
                }
            }
        }

        return ans;
    }
}

Time complexity

\(O(NMP)\), because all three loops examine every possible triplet.

Auxiliary space

\(O(1)\), because only a few variables are used.

Limitation: Each array can contain up to \(10^6\) elements. Three nested loops are far too slow for these constraints.

3. Optimized Approach — Three Pointers

Intuition

Because the arrays are sorted, we do not need to check every combination. Suppose the current elements are:

  • A[i] = 4
  • B[j] = 15
  • C[k] = 10

The maximum is 15 and the minimum is 4, so the current difference is \(15-4=11\). Move the pointer at the smallest element. Advancing a pointer at a non-minimum element leaves the current minimum unchanged and cannot improve this range; advancing the minimum pointer is the way to potentially reduce the gap.

Algorithm

  1. Initialize three pointers: i = 0, j = 0, and k = 0.
  2. Calculate the maximum and minimum among A[i], B[j], and C[k].
  3. Update the answer with max - min.
  4. Move the pointer that points to the minimum element one position forward.
  5. Repeat until any one of the arrays is exhausted.
  6. Return the minimum difference found.

Java solution

public class Solution {
    // DO NOT MODIFY THE ARGUMENTS WITH "final" PREFIX.
    // IT IS READ ONLY.
    public int minimize(final int[] A, final int[] B, final int[] C) {
        int i = 0;
        int j = 0;
        int k = 0;
        int ans = Integer.MAX_VALUE;

        // Continue while all three arrays have elements.
        while (i < A.length && j < B.length && k < C.length) {
            int a = A[i];
            int b = B[j];
            int c = C[k];

            // Find the largest and smallest current values.
            int max = Math.max(a, Math.max(b, c));
            int min = Math.min(a, Math.min(b, c));

            // Save the best difference found so far.
            ans = Math.min(ans, max - min);

            // Advance one pointer at a minimum value.
            if (min == a) {
                i++;
            } else if (min == b) {
                j++;
            } else {
                k++;
            }
        }

        return ans;
    }
}

Why does moving the minimum pointer work?

With current values 4, 15, and 10, the range is \([4,15]\), with a difference of \(11\).

  • Moving 15 forward cannot make the current maximum smaller.
  • Moving 10 forward does not address the smallest value, 4.
  • Moving 4 forward gives a chance to find a smaller range.

Since the arrays are sorted, moving the minimum pointer forward never decreases that array's value. We preserve the best answer seen so far and explore the pointer movement that can improve the current range.

Important: Do not stop when you find a small difference. Continue until one array is exhausted because a better triplet may exist later.

5. Complexity Analysis

Let the lengths of the arrays be \(N\), \(M\), and \(P\).

Approach Time complexity Auxiliary space
Brute force\(O(NMP)\)\(O(1)\)
Three pointers\(O(N+M+P)\)\(O(1)\)

Every iteration advances exactly one pointer. Each pointer can advance at most the length of its corresponding array, so the total number of iterations is at most \(N+M+P\).

No extra array, sorting, or data structure is needed.

6. Edge Cases

  • All values equal: The answer is 0.
  • Duplicate values: The algorithm works correctly, even when multiple values share the minimum.
  • One array has a single element: The algorithm still works and stops when that array is exhausted.
  • Very different ranges: The algorithm gradually advances the smallest value to search for a closer triplet.
  • Minimum values are zero: The calculation remains valid because all values are non-negative.
  • Maximum values are \(10^7\): The difference fits safely within Java's int range.

8. Interview Preparation Notes

Key pattern to remember

Three sorted arrays + minimize the maximum difference = three pointers.

The most important observation is:

\[\max(|a-b|,|b-c|,|c-a|)=\max(a,b,c)-\min(a,b,c)\]

Common mistakes

  • Moving the pointer at the maximum instead of the minimum.
  • Forgetting to update ans before moving a pointer.
  • Using three nested loops despite sorted input.
  • Continuing after one array is exhausted and accidentally accessing an invalid index.

Likely interviewer follow-up questions

Q1. Why must the arrays be sorted?

Sorting allows us to advance the minimum element toward larger values without revisiting earlier elements. This is what makes the linear-time approach possible.

Q2. What happens if two or three elements share the minimum?

Moving any pointer whose value equals the minimum is safe. The code moves one such pointer per iteration.

Q3. Can we solve this in \(O(NMP)\) without sorting?

Yes. The brute-force solution works even for unsorted arrays, but it is much slower. Sorting first is another possibility, although it is unnecessary here because the input is already sorted.

Q4. Can the answer be negative?

No. The answer is a maximum absolute difference, so it is always non-negative.

9. Final Recommendation

Implement the three-pointer greedy approach in an interview. It uses the sorted property of the arrays to eliminate unnecessary combinations and meets the maximum constraints efficiently.

  • Time: \(O(N+M+P)\)
  • Auxiliary space: \(O(1)\)

Remember: Calculate the current range, save the best difference, and move the pointer at the smallest value.
